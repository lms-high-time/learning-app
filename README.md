# lms_frappe_app

Frappe-приложение платформы **MCP-LMS**: хранит директивы уроков, учебные
сессии и результаты серверного квиза, отдаёт их наружу документированным
REST-контрактом — [CONTRACT.md](CONTRACT.md).

Дополняет [Frappe Learning](https://github.com/frappe/lms), не заменяя его:
итоги занятий пишутся в стандартные `LMS Course Progress` и
`LMS Quiz Submission`, поэтому прогресс, набранный через агента, виден в
браузерном интерфейсе.

## Лицензия и граница

Приложение распространяется под **AGPL-3.0** — оно загружается в один процесс
с Frappe Learning и работает с его DocType, а значит считается совместным
произведением.

Закрытая часть платформы — MCP-сервис — живёт отдельным процессом и общается с
этим приложением **только по HTTP**, через документированный контракт общего
назначения ([CONTRACT.md](CONTRACT.md)). Что именно можно писать здесь, а что
нельзя, — в [CONTRIBUTING.md](CONTRIBUTING.md); это не стилистика, а условие,
на котором держится граница.

## Состав

| Что | Состояние |
|---|---|
| `Agent Lesson Directive` — директива урока | готово |
| `Agent Learning Session`, `Agent Session Event` — занятия и журнал | готово |
| Нормализатор контента уроков | готово |
| Организации, членство, назначение курсов | готово |
| Изоляция организаций | готово |
| Пространства: личное и организаций, документ и занятие по пространству | готово |
| «Команда»: участники, документы по блокам, отчёт, приглашения, назначения | готово |
| Письма о назначении и сроке (`Allocation Notice`) | готово |
| Организация, созданная пользователем: `verified`, лимиты | готово |
| Пошаговый серверный квиз | готово |
| Whitelisted-методы контракта | готово |
| Страница `/agent` «Подключить агента» и пункт сайдбара | готово |
| Артефакты курса: схема от автора, документ ученика, страница `/artifacts` | готово |
| Навигация в desk: плитка приложения, workspace и сайдбар модуля | готово |
| `Agent Course Report` — репорты агента о том, что мешает курсу работать | готово |

Страница `/agent` показывает залогиненному пользователю адреса подключения
агента под его роль, шаги для Claude Desktop и ссылку на исходники; пункт
«Подключить агента» в сайдбаре Frappe Learning ставится при установке и каждой
миграции. Адреса строятся от базы, заданной в `Agent Learning Settings`
(`agent_service_url`); пусто — сервиса агента у установки нет, и страница
адресов не показывает.

Артефакты курса — документы, которые ученик собирает по ходу обучения:
автор задаёт схему (`Agent Course Artifact`: блоки с подсказками агенту и
привязкой к урокам, раскладка столбцом или сеткой), ученик заполняет блоки
через агента или на странице `/artifacts` «Мои документы» и скачивает
документ одним markdown-файлом. Содержимое хранится по ключам блоков, поэтому
правка схемы его не рушит; на зачёт артефакт не влияет, и видит его только
сам ученик. Пункт «Мои документы» ставится в сайдбар так же, как «Подключить
агента».

В desk приложение видно плиткой на стартовом экране (сотрудникам платформы,
не ученикам) и workspace «Agent Learning» с курируемым сайдбаром модуля:
курс, ученики, организации, настройки. Оба приезжают миграцией из JSON
приложения; новый доктайп модуля добавляется в сайдбар руками — тест на
состав это проверяет.

Занятия закрываются по бездействию фоновой задачей раз в час; порог задаётся в
`Agent Learning Settings`, по умолчанию 6 часов. Там же живут параметры
методики: глубина переноса незакрытых целей, предел заметок об ученике, размер
сегмента урока и число пробных уроков в веб-чате. Незаполненное поле уступает
запасному значению из кода, а значения по умолчанию ставит миграция.
На стенде для этого нужен включённый планировщик: у нового сайта он выключен,
`bench --site $SITE_NAME enable-scheduler`.

## Разработка

Приложение работает внутри Frappe bench вместе с
[Frappe Learning](https://github.com/frappe/lms). Стенд платформы собирается из
закрытой части проекта; для разработки достаточно любого bench, куда установлены
Learning и это приложение.

**Тесты гоняются против форка [`lms-high-time/learning-fork`](https://github.com/lms-high-time/learning-fork),
ветка `high-time`** — его ставит CI, на нём же работает стенд. Сейчас правки
форка только во фронтенде, и с upstream `frappe/lms` разницы для приложения нет;
первая серверная правка форка её создаст, и тогда прогон на upstream станет
зелёным там, где стенд сломан.

Правки видны без пересборки образа, если каталог примонтирован в контейнеры
с хоста:

```bash
docker compose up -d                      # compose.yaml + compose.override.yaml
docker compose exec backend bench --site lms.localhost install-app lms_frappe_app
docker compose exec backend bench --site lms.localhost migrate     # после правок DocType
docker compose exec backend bench --site lms.localhost run-tests --app lms_frappe_app
```

## Почему репозиторий открыт

AGPL-3.0 требует предлагать исходники тем, кто пользуется программой **по сети**
(ст. 13). Обязательство возникло с развёртыванием платформы наружу — репозиторий
открыт к этому моменту, и ссылка на него отдаётся в описании MCP-сервера.

Ограничить это NDA или пользовательским соглашением нельзя: AGPL запрещает
дополнительные ограничения.
