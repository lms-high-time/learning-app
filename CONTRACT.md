# REST-контракт приложения

Единственный канал наружу: всё, что приложение отдаёт и принимает, перечислено
здесь. Потребитель на платформе Cenda — MCP-сервис, живущий отдельным
процессом; любой другой клиент разговаривает с приложением теми же методами.

Описание живёт рядом с реализацией — в одном репозитории с `api/`. `Why:`
описание в соседнем репозитории отстаёт молча: дрейф возникает в PR этого
приложения, и ловиться должен здесь же.

Держат его ворота `lms_frappe_app/api/test_contract.py`: раздел на каждый
whitelisted-метод и ни одного лишнего, а ключи примера ответа сверяются с
настоящим ответом метода на фикстуре. Параметры и списки отказов ворота не
проверяют — они остаются на ревью.

**Статус:** описывает текущее состояние `lms_frappe_app/api/`, покрыто тестами.

## Зачем контракт именно такой

Граница между AGPL-частью и закрытой проходит по этому интерфейсу. Чтобы она
держалась, контракт обязан оставаться **интерфейсом общего назначения, который
в принципе мог бы реализовать другой backend**. Отсюда три правила, которые
здесь не обсуждаются:

1. **Никаких структур Frappe наружу.** Ни `doctype`, ни `owner`, ни
   `modified_by`, ни `docstatus`. Идентификатор записи называется `id`, а не
   `name`.
2. **Контракт — только перечисленные методы.** Универсальный `query_doctype` не
   появится: агент начнёт изобретать сценарии в обход педагогики и прав.
   `/api/resource` Frappe открыт тем же токеном, но контрактом не является:
   его держат права DocType, а что он отдаёт — раздел «Сырой REST».
3. **Никаких эталонов ответов.** См. раздел «Запрещённые поля».

## Транспорт

```
POST {frappe_url}/api/method/{method}
Authorization: Bearer {access_token ученика}
Content-Type: application/json
```

MCP-клиент зовёт методы только `POST`, поэтому метод принимает `POST`.
Исключение — метод, которого зовёт страница, а не агент: он бывает только
`GET`, и тогда это сказано в его разделе. Метод без `POST` и без такой
пометки валит ворота в `test_contract.py`. `Why:` на неподходящий глагол
Frappe отвечает `403`, и агент передаёт его как «нет доступа к этим данным» —
так `course_reports` не работал через MCP (learning-services#281).

Токен — личный токен пользователя, полученный по OAuth. Именно поэтому
проверки прав не дублируются в MCP-сервисе: Frappe применяет роли и
`permission_query_conditions` сам, и ученик не увидит курс, на который не
зачислен, даже если его агент попросит напрямую.

Сервисная роль `Agent Service` используется только там, где действие исходит
не от ученика.

## Формат ответа

Frappe заворачивает результат whitelisted-метода в поле `message`. Успех:

```json
{ "message": { "ok": true, "data": { } } }
```

**Ожидаемый доменный отказ** — тоже HTTP 200, с машинным кодом:

```json
{ "message": { "ok": false, "error": { "code": "quiz_attempts_exhausted",
                                        "message": "Попытки исчерпаны до 14:30",
                                        "retry_after": "2026-09-01T14:30:00+03:00" } } }
```

`Why:` доменные отказы не могут ехать HTTP-ошибкой. Тело ошибки Frappe
формирует фреймворк: в API v1 туда попадают `exc_type` и `exception`, причём
`exception` кладётся **только когда разрешён traceback** — в проде его нет, и
машинного кода отказа в ответе не остаётся. Агенту нужен предсказуемый код, а
не текст исключения.

**Ошибка уровня фреймворка** приходит HTTP-статусом; тело разбирать не следует:

| Статус | Когда | Что делает MCP-сервис |
|---|---|---|
| 401 | токен истёк или отозван между интроспекцией и вызовом | «требуется повторная авторизация» |
| 403 | нет прав на уровне Frappe | «нет доступа к этим данным» |
| 404 | объекта нет | «запрошенного объекта не существует» |
| 417 | `ValidationError` — нарушение инварианта | «сервис отклонил запрос как некорректный» |
| 429 | rate limit | «слишком много запросов, попробуйте позже» |
| 5xx, обрыв связи | сбой или недоступность | «учебный сервис недоступен, попробуйте позже» |

Тело ответа Frappe агенту не пересказывается: там имя питоновского класса
исключения, а при `developer_mode` и трассировка. Автоматических повторов
нет — решение о повторе принимает агент, у него есть контекст занятия.

**Чужая сессия и чужая попытка отклоняются доменным кодом** `not_your_session`,
а чужой ученик в отчёте — `not_your_student`. Проверка идёт по принадлежности
записи, и это не дублирование прав Frappe, а необходимость:

- `frappe.get_all` — это `get_list(ignore_permissions=True)`, и
  `permission_query_conditions` к нему не применяются **никогда**. Изоляция,
  построенная только на хуках, в методах отчётности не работала вовсе;
- читать занятие вправе ещё и руководитель — если оно в пространстве его
  организации, — но **действовать** в нём он не должен: иначе сожжёт ученику
  попытку квиза или ответит за него.

Права Frappe при этом остаются: они закрывают прямое обращение к
`/api/resource/...` — что там видит и пишет ученик, сказано в разделе
«Сырой REST».

## Пределы записи ученика

Каждый POST-метод ученика, который пишет, ограничен по частоте — на
пользователя и метод, а не на адрес: вызовы агентов всех учеников приходят с
одного адреса MCP-сервиса. Сверх предела — HTTP 429 с заголовком
`Retry-After` (секунды до конца окна), вызов не выполняется. Читающие
POST-методы (`homework`, `my_homework`) предела не имеют; ворота в
`test_write_limits.py` требуют предел или запись в исключениях у каждого
метода записи (без GET) `api/student.py` и `api/consent.py`. Пределы — в
`Agent Learning Settings`, раздел «Пределы записи ученика»:

- `student_writes_per_minute` (по умолчанию 60) — вызовов в минуту на каждый
  метод записи: заметки, отметки пунктов, документ курса, репорты, занятие
  и квиз, пространство, ходы сценария, запись на курс, согласие, вступление
  в организацию по приглашению и её создание (`team.accept_invite`,
  `team.create_organization`);
- `state_saves_per_minute` (по умолчанию 600) — `save_chat_state` и
  `save_scenario_state`: веб-чат сохраняет состояние несколько раз за ход;
- `homework_saves_per_hour` (по умолчанию 30) — вызовов `submit_homework` в
  час, по всем урокам вместе;
- `student_files_quota_mb` (по умолчанию 200) — место под файлы ученика,
  загруженные за последние 30 дней: сдачи домашки и загрузки на сайте мимо
  методов, включая фото профиля. Убранные из ответа файлы домашки остаются и
  место занимают. Квота — у учеников, в том числе у руководителей команд;
  методистов, модераторов и администраторов она не касается. Сдача сверх
  квоты — отказ `storage_quota_exceeded`, загрузку мимо методов Frappe
  отклоняет HTTP 417. Ученику, упёршемуся в квоту, оператор поднимает
  `student_files_quota_mb` — для всех — или ждёт, пока старые файлы выйдут из
  окна.

Флаг System Settings `only_allow_system_managers_to_upload_public_files` не
включён: фото профиля и картинки курса Learning загружает публичными файлами,
и с флагом их загрузка у всех, кроме System Manager, ломается. Вместо флага
публичный файл ученика — только растровое изображение (PNG, JPEG, GIF, WebP,
AVIF), иначе HTTP 417; приватный — любой разрешённый сайтом тип. Публичные
загрузки ученика ограничивает и квота.

Пределы длины свободного текста — в разделах методов: отказы `*_too_long`
с `limit` и `length`.

## Запрещённые поля

Ни один ответ методов ученика и руководителя не содержит:

- верного варианта вопроса квиза и признака правильности вариантов
  (`lessons[].quiz.answers` релиза: `correct`); пояснения вопроса
  (`explanation`) — кроме вердикта на верный ответ и итога сданной попытки
  («Квиз урока из релиза»);
- пакета агента курса из релиза (директива и материал урока, рамка курса,
  подробности пунктов) в методах, кроме `start_lesson`, где он приходит
  отдельными полями, и `lesson_item` — текст одного пункта;
- пунктов целей агента (ключей, названий, статусов) — кроме агентских
  методов курса из релиза (`start_lesson`, `lesson_item`, `mark_goal`, отказ
  `goals_open`); методы уровня целей урока — `course_outline`, `course_map`,
  `lesson_session`, прогресс в `remember` и `update_artifact`,
  `student_detail` — отдают цели урока без пунктов;
- свидетельств к пунктам прохождения;
- полей других учеников в методах ученика.

Методы авторинга — единственное исключение, и оно обозначено ролью, а не
адресом: `course_release` отдаёт ответы квиза и пакет агента тому, кто
публикует курс, `goal_runs` — пункты прохождений со свидетельствами
инструктору курса. Ученик до них не доходит — вызов без роли куратора
отклоняется 403.

На это вешается регрессия `lms_frappe_app/api/test_no_leak.py`: прогон всех
методов ученика и руководителя с проверкой ответов на присутствие этих полей.
Утечка эталона обесценивает серверный квиз целиком — а он несущее решение
всей схемы зачёта.

## Кто что видит

Дом модели доступа: роли, что каждой открыто и где это проверяется.
Подробности метода — в его разделе, правила прав DocType — в
`agent_learning/permissions.py`, запись полей Learning — в хуках `validate`
(`hooks.py`, `doc_events`). Спека дизайна и прочие документы ссылаются сюда.

**Роли.**

- **Гость** — не вошедший.
- **Ученик** — любой вошедший: роль `LMS Student` Learning выдаёт каждому
  новому пользователю. Основание доступа к курсу — запись на курс
  (`LMS Enrollment`); назначение организации само доступа не даёт, курс от
  приостановленной организации закрыт (`agent_learning/access.py`). Тестер
  курса — тот же ученик с отметкой `agent_tester` на записи.
- **Участник организации** — действующее членство `Member`
  (`Organization Membership`). Отдельной роли Frappe нет.
- **Руководитель** — членство `Manager` или `Org Admin`; по нему Frappe-роль
  `Organization Manager` выдаётся и снимается сама. Роль без действующего
  членства не открывает ничего, членство — только свою организацию.
  `Org Admin` ещё меняет роли участников.
- **Методист** — `Course Creator`; **модератор** — `Moderator`. Выдаются
  вручную. Как ученики они видят то же, что ученик, сверх этого — авторинг,
  Desk и строки матрицы ниже. Инструктором курса (`instructors`) публикация
  релиза ставит только автора. `goal_runs` сначала требует авторскую роль,
  а `reset_student_progress` пускает любого инструктора курса, кто бы он ни
  был.
- **Куратор** — тот, кто проверяет домашки: руководитель, методист,
  модератор (раздел «Методы куратора»).
- **Администратор платформы** — `System Manager`, пользователь
  `Administrator`.
- **`Agent Service`** — служебная роль: изоляцию организаций не применяет
  вовсе, поэтому выдаётся только сервису (спека дизайна, §4).
- **`Batch Evaluator`** — роль Learning, платформа её не выдаёт. Learning и
  подмены его методов (`learning_reads`) считают её персоналом групп: она
  видит неопубликованные группы и статистику и записывает в группу других.
  По правам Learning она заводит группы с любыми курсами, и проверки «не
  опубликован» и «платный» её не держат: роль равна праву открыть любой курс
  любому человеку и выдаётся только доверенным (решение владельца,
  learning-services#674).

**Матрица.** «Свои» — записи, где пользователь — ученик; «пространство» —
записи в пространстве организации, где он руководитель (ушедший участник
из него выпадает).

куратор — `может_проверять`, автор — ролью (403). Те же правила держат права
DocType для `/api/resource` — следующий раздел.

## Сырой REST: что видит ученик

`/api/resource/<DocType>`, `frappe.client.*`, `frappe.desk.reportview`,
`frappe.desk.form.load` и `frappe.desk.search` отвечают тому же токену:
OAuth выдаёт область `all`. Контрактом этот путь не является, его держат
права DocType — схемы Learning и приложения плюс хуки `has_permission` и
`permission_query_conditions` в `hooks.py`. Методы Learning
(`/api/method/lms.*`) отвечают по правилам Learning; часть из них приложение
подменяет (`override_whitelisted_methods` в `hooks.py`). Подменённый метод
доступен только под своим HTTP-именем: оригинал снят из реестра whitelisted
Frappe, и под другим путём модуля он отвечает отказом
(`lms_frappe_app/whitelist_guard.py`).

**Чтение.**

- **Занятия, их журнал, попытки квиза, документы, сдачи домашки** — свои;
  руководителю — его пространство, как в матрице. Документы участнику — если
  организация открыла их всем. **Членства** — свои, руководителю — весь
  состав его организаций; **назначения** — организаций, где пользователь
  состоит.
- **Заметки агента** — только свои, руководителю тоже нет. **Ответы квиза**
  (`Agent Quiz Answer`) — ни ученику, ни руководителю: в них текст ответа
  рядом с признаком верности.
- **Поля уровня 1**: кто проверял сдачу (`history[].by_user` у
  `Agent Homework Submission`) читают `System Manager`, `Course Creator`,
  `Moderator`; адресатов назначения (`Course Allocation.members`) —
  `System Manager` и `Moderator`, руководителю их отдают методы команды.
  Списком дочерних строк этих полей не отдаёт никому.
- **DocType Learning по `/api/resource`:** главы (`Course Chapter`) — курсов
  на витрине, своих и тех, что пользователь ведёт инструктором; свои записи на курс, отметки уроков, попытки квиза
  Learning; по правам Learning — группы, программы, квизы, задания,
  упражнения, сертификаты, живые занятия и источники (`LMS Batch`,
  `LMS Program`, `LMS Quiz`, `LMS Assignment`, `LMS Programming Exercise`,
  `LMS Certificate`, `LMS Live Class`, `LMS Source`). Уроки (`Course Lesson`),
  `LMS Course` и `LMS Question` ученику не читаются вовсе.
- **Методы Learning:** урок — по правилу Learning (записанному, превью
  опубликованного курса, инструктору); оглавление, урок и отзывы курса вне
  витрины — только тому, кому курс открыт⁵, каталог курсов и групп —
  опубликованные, кроме вкладки своих записей, статистика платформы —
  персоналу (`agent_learning/learning_reads.py`).
- **Версии приложений** (`frappe.utils.change_log.get_versions`) — только
  пользователю Desk.
- Остальные DocType приложения — организации, приглашения, релизы курсов,
  журнал проверки квиза (`Agent Quiz Event`), прохождения уроков,
  уведомления о назначениях и домашках, настройки — ученику закрыты.

**Запись.** Данные приложения и запись на курс ученик меняет только методами
контракта; прочие DocType Learning — по правам Learning, например: свои
заметки к уроку, отзывы о курсе и группе, сдачи заданий и упражнений, время
просмотра видео, запрос сертификата, значки, запись в группу, свой профиль
`User`.

- DocType приложения с данными учеников и организаций принимают от
  `/api/resource` только чтение — запись и создание там по схеме есть лишь у
  `System Manager` и `Moderator`, у сдачи домашки — только у
  `System Manager`;
- запись на курс (`LMS Enrollment`): Learning даёт право на свои записи, но
  поля записи меняет только код платформы; вставка без методов — только
  когда Learning записывает ученика в группу (`LMS Batch Enrollment`) и
  заводит зачисления на её курсы, обычная запись — `enroll`
  (`agent_learning/enrollment_guard.py`);
- отметку урока курса из релиза ставит только занятие
  (`browser_progress.py`).

Что пишут через Desk авторы и модераторы и что держит сама запись — раздел
«Методы авторинга».

## Тексты и HTML

Текст, который пишут методы, — заметки и их ключи, ответы и слова ученика,
блоки документа, репорты, заметки автора и ответы в них, комментарии
проверки, название организации, — хранится без исполнимой разметки, если в
нём есть начало тега: `<` и сразу буква, `!`, `/` или `?`. Тогда методы
отдают его не таким, каким он был передан:

- `<`, с которого тег не сложился, приходит как `&lt;`, а текст за ним — как
  был, с переводами строк: `если x<y, то z` → `если x&lt;y, то z`,
  `List<String> items` → `List&lt;String> items`,
  `<img src=x onerror=…//` → `&lt;img src=x onerror=…//`; комментарий тоже
  не разметка: `<!--` приходит как `&lt;!--`;
- в тексте с закрытыми тегами опасные теги и атрибуты вырезаются, прочая
  разметка остаётся, а `&`, `<` и `>` вне тегов приходят сущностями:
  `"<img src=x onerror=…>"` → `"<img src="x">"` — и в тексте, который
  разбирается как JSON; `<b>x</b> & y` → `<b>x</b> &amp; y`.

Повторная запись того же текста его не меняет. Текст без начала тега —
`a < b`, `5<6`, `цена<сто` (имя тега бывает только латинским),
`{"rule": "score > 80 & x"}` — хранится и отдаётся как передан.

Ключ заметки `remember` и `forget` приводят так же, как он хранится: `x<y`
находится, а в `my_notes` приходит `x&lt;y`. Ключи, которые после приведения
совпали, — одна заметка: `x<y` и `x&lt;y`, ключ с разметкой и он же с
вырезанной.

Как есть хранятся поля, перечисленные в разделе «Релиз курса», значения JSON
— ячейки документа — и состояния разговора и сценария; кто выводит их в HTML,
тот и экранирует.

`Why:` Frappe пропускает без очистки текст с тегом, который разбирается как
JSON или где тег не закрыт, а Desk выводит часть полей без экранирования в
расчёте на очистку при записи — тег из такого текста исполнился бы в браузере
администратора (learning-services#527).

# Методы витрины

Методы, доступные **без входа**; из прочих методов контракта гостю открыт
только `team.invite_info`. Они ничего не знают о вызывающем, кроме того,
зачислен ли он: гостю отдаётся состав курса, зачисленному — он же
плюс его собственное покрытие целей.

## `lms_frappe_app.api.public.course_map`

Карта курса: главы, уроки с зачином, цели уроков и покрытие целей, а
зачисленному — ещё пройденность уроков и следующий урок. Зовёт страница курса
для программы курса, в MCP не выставляется.

**Параметры:** `course`, `space` (необязательный) — чей документ показывать зачисленному. Только `GET`.

```json
{ "ok": true, "data": {
  "course": "p3-express", "title": "P3.express", "next_lesson": "lesson-2",
  "documents": [ { "artifact": "project_summary", "title": "Резюме проекта",
                   "blocks_total": 6, "blocks_filled": 2 } ],
  "chapters": [
    { "title": "Запуск", "description": "Проект получает спонсора и цель.",
      "status": "in_progress", "lessons_total": 3, "lessons_passed": 1,
      "lessons": [
      { "id": "lesson-1", "number": 1, "title": "Запуск проекта",
        "hook": "Проект без спонсора глохнет на первом споре о деньгах.",
        "completed": true,
        "blocks": [ { "artifact": "project_summary", "key": "sponsor",
                      "title": "Спонсор и менеджер",
                      "description": "Кто платит за проект и кто им управляет",
                      "filled": true } ],
        "objectives": [ { "text": "Назвать спонсора проекта", "status": "covered" },
                        { "text": "Отличить проект от операций" } ] } ] } ] } }
```

`hook` — зачин урока, обращённый к ученику; виден всем, `null`, если автор
его не задал.

У главы `description` — описание главы из действующего релиза, видно всем;
у курса без релиза — `null` (learning-services#547). Зачисленному на курс из
релиза — ещё прогресс главы, тот же, что у `course_outline`: `status` —
`not_started`, `in_progress` или `passed`, `lessons_total` — уроков главы в
релизе, `lessons_passed` — пройденных из них. Прочим и у курса без релиза
этих ключей нет.

`documents` — документы, которые ученик собирает по ходу курса, у урока
`blocks` — какие их блоки собирают на этом уроке (learning-services#340). Видны
всем: что курс оставит после себя, — его обещание. Зачисленному — ещё
`blocks_total` и `blocks_filled` у документа и `filled` у блока, по тем же
правилам, что у `artifact`. У курса без документа — пустые списки.

Блок здесь — **краткий блок**: `{artifact, key, title, description, filled?}`,
`description` — что сюда записывают, для ученика (`null`, если раздел его не
задал), `filled` — только зачисленному. Та же форма — у `lesson_entry`
(`blocks`), `start_lesson` (`artifact_blocks`), `complete_lesson` и итога
квиза (`empty_blocks`) и сигнала `blocks_empty`.

`tester: true` приходит зачисленному тестеру курса — его записал автор, чтобы
проверить курс до публикации (learning-services#393). У остальных ключа нет.

`completed` у урока и `next_lesson` у курса приходят **только зачисленному**,
по тому же правилу, что `status` у цели: у прочих ключей нет. `completed` —
урок закрыт квизом или `complete_lesson`; `next_lesson` — первый незакрытый
урок, тот же, что у `lesson_entry(course=…)`, у пройденного курса — `null`.

Цели урока **курса из релиза** — тексты целей урока действующего релиза, без
пунктов. `status` у цели появляется **только у зачисленного** и только по его
собственному прохождению урока (см. «Состояние ученика по релизу»): `touched`
или `covered`. У гостя и у вошедшего, но не зачисленного, ключа нет вовсе —
`null` был бы неотличим от «цель не разобрана». Не начатая цель приходит без
`status` и у зачисленного: это и есть «не дошли». Статусы — сохранённые, без
сверки прохождения с релизом.

У **курса без релиза** цели уроков задавать нечему: `objectives` у урока —
пустой список.

**Анонс** (learning-services#389) — курс, который готовится: главы, уроки и
документы у него закрыты, наружу выходят только цели курса: у курса из релиза
— названия глав действующего релиза, у курса без релиза — цели, заданные
`announce_course`. Незачисленному карта анонса приходит в другом виде:

```json
{ "ok": true, "data": {
  "course": "ops-junctions", "title": "Где теряется работа между отделами",
  "upcoming": true, "notify": false,
  "objectives": [ "Описать процесс в пять колонок",
                  "Найти стыки между отделами" ],
  "documents": [], "chapters": [] } }
```

`upcoming` приходит только у анонса. `notify` — подписан ли вызывающий на
письмо о выходе (`notify_when_released`); у гостя ключа нет.

**Отказы:** `course_not_found` — курса нет или он не опубликован, а вызывающему
не открыт: не записан, не инструктор курса и не в роли персонала
(`Course Creator`, `Moderator`, `System Manager`, `Agent Service`;
`permissions.курс_открыт`). Непубликованный курс для постороннего не
существует.

## `lms_frappe_app.api.public.course_programs`

В какие программы Learning входит курс и заперт ли он программой
(learning-services#405). Зовёт страница курса: «курс 2 из 3 программы …», а у
запертого курса — «сначала пройдите …» вместо записи. В MCP не выставляется:
агенту те же сведения приходят полем `programs` у курса в `list_catalog`,
`list_my_courses` и `course_outline`. Доступен и гостю.

**Параметры:** `course`. Только `GET`.

```json
{ "ok": true, "data": {
  "course": "course-early-signals",
  "programs": [ {
    "program": "Работа между отделами", "title": "Работа между отделами",
    "number": 2, "total": 3, "enforce_order": true, "member": true,
    "previous": { "id": "course-handoffs", "title": "Где теряется работа между отделами" },
    "next": { "id": "course-risk-matrix", "title": "Матрица рисков и контролей" },
    "locked_by": { "id": "course-handoffs", "title": "Где теряется работа между отделами" } } ] } }
```

Видны опубликованные программы и те, где вызывающий участник. `previous` —
курс перед этим в программе, у первого — `null`; `next` — курс после, у
последнего — `null`. `locked_by` — курс, который
пройти раньше: только участнику программы с обязательным порядком
(`enforce_order`), пока предыдущий курс не пройден целиком; прочим — `null`.
Порядок действует только для участников: второй курс напрямую из каталога
берётся без условий (решение владельца).

**Отказы:** `course_not_found` — курса нет или он не опубликован, а вызывающий
на него не записан.

## `lms_frappe_app.api.public.lesson_entry`

Вход в урок: зачин, пройден ли урок и куда вести ученика на занятие. Зовёт
страница урока в браузере — она показывает не материал, а дорогу к агенту.
В MCP не выставляется. Требует входа.

**Параметры:** `lesson` или `course`; `space` (необязательный) — чей документ
показывать в `blocks`. Только `GET`.

Только `course` — вход в следующий незакрытый урок курса, у пройденного
курса — в первый урок: так кнопка «Продолжить» на странице курса ведёт прямо
на занятие. Какой урок выбран, видно по `lesson`.

```json
{ "ok": true, "data": {
  "lesson": "lesson-1", "course": "p3-express", "title": "Запуск проекта",
  "hook": "Проект без спонсора глохнет на первом споре о деньгах — разберём, кто он у вас.",
  "completed": false,
  "objectives": [ { "text": "Назвать спонсора проекта", "status": "touched" },
                  { "text": "Отличить проект от операций" } ],
  "study": { "channel": "web", "url": "https://lms.example.com/chat?lesson=lesson-1", "demo_left": 2 },
  "program_lock": null,
  "blocks": [ { "artifact": "project_summary", "key": "sponsor",
                "title": "Спонсор и менеджер",
                "description": "Кто платит за проект и кто им управляет",
                "filled": false } ] } }
```

`study.channel`:

- `web` — веб-чат платформы на этот урок. Так бывает, пока у ученика остались
  пробные уроки, и для урока, уже начатого в веб-чате: возврат в него пробного
  не тратит — то же правило, что у `start_lesson` с `channel: "web"`;
- `agent` — пробные кончились или сервиса агента у установки нет; `url` ведёт
  на `/lms/agent`, где шаги подключения своего ассистента.

`demo_left` — сколько пробных уроков веб-чата осталось, с учётом уже начатых.

`hook` — зачин урока, обращённый к ученику; `null`, если автор его не задал.
Материал и директива сюда не выходят: материал написан для агента.

`completed` — урок закрыт квизом или `complete_lesson`.

`objectives` — цели урока, как у урока в `course_map`: тексты целей
действующего релиза; зачисленному — `status` у цели, начатой в его
прохождении (`touched`, `covered`), не начатая — без ключа. У курса без
релиза — `[]` (learning-services#547).

`program_lock` — курс заперт программой (learning-services#405): ученик —
участник программы с обязательным порядком, а предыдущий курс не пройден
целиком. Тогда `{ "program": "…", "program_title": "…", "previous": { "id": "…",
"title": "…" } }`, и страница ведёт к предыдущему курсу, а не на занятие;
иначе `null`.

`blocks` — краткие блоки документа курса, которые собирают на этом занятии,
как у урока в `course_map`; у ученика курса — с `filled`.

**Отказы:** `lesson_not_found` — урока нет, в курсе нет уроков, не передано
ни `lesson`, ни `course` или курс не опубликован либо анонсирован, а
вызывающему он не открыт — как курс у `course_map`.

## `lms_frappe_app.api.analytics.analytics_id`

Идентификатор вошедшего для аналитики (learning-services#582): события того,
кто дал согласие на аналитику, привязываются к нему, а не к email и имени.

согласия сайта, агент — нет. Гостю — 403 Frappe (метод без `allow_guest`), без
обёртки контракта. Только `GET`.

**Параметры:** нет.

```json
{ "ok": true, "data": { "id": "3f9a0c4e1b7d52a86e0f4c9b2d1a7e53" } }
```

# Согласие с документами

## `lms_frappe_app.api.consent.accept`

Явное согласие с документами с экрана `/consent` (learning-services#624):
пользователю есть 18 лет, Условия использования и Политику
конфиденциальности он принимает — в действующей редакции (`legal_version` в
`Agent Learning Settings`). Когда экран показывается — в `agent_learning/consent.py`.
Зовёт экран, из сессии браузера; агент — нет. Гостю — 403 Frappe.

**Параметры:** `age_confirmed`, `documents_accepted` — оба `1` (или `true`).

```json
{ "ok": true, "data": { "version": "2026-10-20" } }
```

Повторный вызов с уже данным согласием ничего не пишет.

```json
{ "ok": false, "error": { "code": "consent_marks_required",
                          "message": "Чтобы продолжить, подтвердите возраст и примите условия" } }
```

**Отказы:** `consent_marks_required` — не отмечено одно из двух;
`consent_by_user_only` — вызов с заголовком `Authorization` (токен агента) или
из сессии «Войти как».

## `lms_frappe_app.api.consent.decline_underage`

Пользователь сообщает на экране согласия, что ему нет 18 лет
(learning-services#624). Если на аккаунт ничего не ссылается (проверка ссылок
самого Frappe), он удаляется сразу, вместе с контактом. Если ссылается —
закрывается, а данные удаляет администратор по письму на
`privacy@cenda.app`. В обоих случаях сессии пользователя завершаются, а в
«Согласие с документами» остаётся запись `Underage`. Тот же путь ежедневно
проходят аккаунты, созданные через Google, без согласия за 30 дней (запись
`Not Given`). Зовёт экран, из сессии браузера; агент — нет. Гостю — 403
Frappe.

**Параметры:** нет.

```json
{ "ok": true, "data": { "result": "deleted" } }
```

`result`: `deleted` — аккаунт удалён; `closed` — закрыт, данные будут удалены.

**Отказы:** `consent_by_user_only` — вызов с заголовком `Authorization` (токен
агента) или из сессии «Войти как»; `consent_staff_account` — учётная запись
сотрудника (`System User`): её закрывает администратор.

# Агенты и сессии

Страница `/connections` (learning-services#669): пользователь отключает
агентов, которым дал доступ, и завершает свои сессии браузера. Методы зовёт
страница, из сессии браузера и с заголовком `X-Frappe-CSRF-Token` — без него
отказ `CSRFTokenError` Frappe, даже если сессия токена ещё не получала.
Агент их не зовёт: вызов с заголовком `Authorization` (токен агента) или из
сессии «Войти как» — отказ `account_by_user_only`. Гостю — 403 Frappe.
Подключение и сессия названы отпечатком со страницы, а не токеном и не `sid`;
отпечаток ищется только среди своих записей, и чужой — тот же отказ, что
уже отключённый.

## `lms_frappe_app.api.account.disconnect_agent`

Отзывает подключение агента: токены одного его входа (семью токенов) и
неиспользованные коды авторизации этого агента у пользователя. Пароль не
нужен: доступ возвращается новым подключением.

**Параметры:** `connection` — отпечаток подключения со страницы.

```json
{ "ok": true, "data": { "connection": "3f9a0c4e1b7d52a8" } }
```

```json
{ "ok": false, "error": { "code": "connection_not_found",
                          "message": "Это подключение уже отключено" } }
```

**Отказы:** `connection_not_found` — у пользователя нет действующего
подключения с таким отпечатком; `account_by_user_only`.

## `lms_frappe_app.api.account.end_session`

Завершает другую сессию браузера пользователя после повторного ввода пароля
(ASVS 7.5.2). Неверный пароль идёт в счётчик неудачных входов Frappe; вызовов
с одного адреса — не больше 10 в час, сверх — 429 Frappe.

**Параметры:** `session` — отпечаток сессии со страницы; `password`.

```json
{ "ok": true, "data": { "ended": 1 } }
```

```json
{ "ok": false, "error": { "code": "password_incorrect", "message": "Неверный пароль" } }
```

**Отказы:** `password_not_set` — у аккаунта нет пароля (задаётся по ссылке из
письма), в счётчик неверных попыток не идёт; `password_required` — пароль не
передан; `password_incorrect`;
`password_attempts_exceeded` — неверных попыток больше, чем разрешает
System Settings (без настройки — 3 за 5 минут), пароль не проверяется;
`session_not_found` — такой сессии у пользователя нет; `session_is_current` —
текущую сессию завершает выход; `account_by_user_only`.

## `lms_frappe_app.api.account.end_other_sessions`

Завершает все сессии браузера пользователя, кроме текущей, после повторного
ввода пароля. Предел вызовов и счётчик неверных попыток — как у
`end_session`.

**Параметры:** `password`.

```json
{ "ok": true, "data": { "ended": 2 } }
```

`ended` — сколько завершено из сессий, которые видны на странице; `0` —
других не было. Вышедшие по сроку удаляются тоже, но в число не входят.

**Отказы:** `password_not_set`, `password_required`, `password_incorrect`,
`password_attempts_exceeded`, `account_by_user_only`.

# Методы ученика

**Пространства** (learning-services#346). Прогресс у ученика один, а курсы и
документы — у пространства: личного или организации, в которой он состоит.
Человеку организация показывается **командой**, роли `Org Admin` / `Manager` /
`Member` — администратором, ведущим и участником (learning-services#585); в
контракте имена прежние: `organization`, `Manager`.
Параметр `space` — имя организации или `personal`; чужое или приостановленное
пространство — отказ `space_not_available`. Без `space` методы списков
(`list_my_courses`, `list_catalog`, `enroll`, `get_my_progress`, `my_homework`
без курса и урока) работают в
**выбранном** пространстве (`my_spaces`, `set_space`), а методы курса
(`start_lesson`, `artifact`, `update_artifact`,
`homework`, `submit_homework`, `my_homework` с `course` или `lesson`,
`course_map`, `lesson_entry`) — в пространстве открытого занятия по курсу,
иначе в выбранном, если курс в нём есть, иначе в личном. Пространство открытого
занятия в организации, где ученика больше нет, не в счёт. `Why:` агент, начавший
урок в компании, пишет документ туда же, не повторяя `space`. Названное
пространство, в котором курса нет, — отказ `course_not_in_space`.

## `lms_frappe_app.api.student.whoami`

Под какой учётной записью вошёл ученик и в каких он организациях.

**Параметры:** нет.

```json
{ "ok": true, "data": {
  "login": "ivanov@example.com", "full_name": "Иван Иванов",
  "organizations": [ { "id": "org-1", "title": "Компания",
                       "role": "Member", "suspended": false } ],
  "space": "org-1" } }
```

`Why:` пустой список курсов сам по себе ничего не объясняет — «вошли не тем
аккаунтом» и «тем, но без зачислений» выглядят одинаково. Приостановленная
организация закрывает доступ к своим курсам, и без `suspended` пустой каталог
необъясним.

Наружу идут только собственные данные ученика. `role` — роль в организации (`Member`,
`Manager`, `Org Admin`), а не на платформе: ролей Frappe здесь нет. Организации,
из которых ученик вышел, в список не входят. `space` — выбранное пространство.

**Отказов нет.**

## `lms_frappe_app.api.student.my_spaces`

Пространства ученика и какое выбрано.

**Параметры:** нет.

```json
{ "ok": true, "data": { "current": "org-1", "spaces": [
  { "id": "personal", "title": null, "role": null, "suspended": false,
    "documents_visible_to": "only_me" },
  { "id": "org-1", "title": "Компания", "role": "Member", "suspended": false,
    "documents_visible_to": "managers" } ] } }
```

`documents_visible_to` — кто, кроме автора, читает документы пространства:
`only_me` (личное), `managers` — руководители организации, `members` — все её
участники. Интерфейс пишет это ученику на документе.

Личное — всегда первым. Не выбирал — выбрана первая действующая организация,
иначе личное: сотрудник приходит прежде всего за курсами компании. Выбор,
который перестал действовать (вышел, организацию приостановили), уступает тому
же правилу.

**Отказов нет.**

## `lms_frappe_app.api.student.set_space`

Выбирает пространство. Выбор хранится на сервере: по нему работают и
интерфейс, и агент, и веб-чат. Только `POST`.

**Параметры:** `space` — организация или `personal`.

```json
{ "ok": true, "data": { "current": "personal" } }
```

**Отказы:** `space_not_available`.

## `lms_frappe_app.api.student.list_my_courses`

Курсы пространства с прогрессом и дедлайнами.

**Параметры:** `space` (необязательный).

В личном пространстве — все курсы ученика, в том числе назначенные компанией:
прогресс у него один (решение владельца, learning-services#346). В
пространстве организации — курсы, которые она назначила ему или которые он
выбрал в её каталоге; `deadline` и `mandatory` — её.

Список строится **по зачислениям**, а не по назначениям: ученик, записавшийся
сам, назначений не имеет вовсе. Назначение организации добавляет поверх
`deadline`, `mandatory` и `organization`; у частного ученика эти поля пустые.

Курсы приостановленной организации в список не попадают, но зачисление на них
сохраняется — при возобновлении прогресс на месте.

**Отказов нет.**

```json
{ "ok": true, "data": { "space": "org-1", "courses": [
  { "id": "course-basics", "title": "Основы", "organization": "org-1",
    "mandatory": true, "deadline": "2026-09-15", "overdue": false,
    "progress": { "lessons_total": 12, "lessons_completed": 5 },
    "next_lesson": { "id": "lesson-6", "title": "Циклы" },
    "programs": [] } ] } }
```

`programs` — программы курса в том же виде, что у `course_programs`: место
курса в цепочке, предыдущий и следующий курс и `locked_by`, если курс для
ученика заперт порядком (learning-services#405). Курс вне программ —
пустой список.

## `lms_frappe_app.api.student.list_catalog`

Опубликованные курсы, на которые ученик может записаться сам в пространстве,
и анонсы — курсы, которые готовятся.

**Параметры:** `space` (необязательный).

```json
{ "ok": true, "data": { "space": "personal", "courses": [
  { "id": "course-python", "title": "Питон с нуля",
    "summary": "Для тех, кто не программировал", "upcoming": false, "programs": [] },
  { "id": "ops-junctions", "title": "Где теряется работа между отделами",
    "summary": "Стыки между отделами и риски на них", "upcoming": true,
    "objectives": [ "Описать процесс в пять колонок" ], "notify": false,
    "programs": [ {
      "program": "ops-chain", "title": "Операционное управление",
      "number": 1, "total": 3, "enforce_order": true, "member": false,
      "previous": null,
      "next": { "id": "ops-early-signals", "title": "Как заметить проблему заранее" },
      "locked_by": null } ] } ] } }
```

У анонса (`upcoming: true`) записи нет: `enroll` отказывает `course_upcoming`.
Вместо неё — `notify_when_released`. `objectives` — цели курса (как у
`course_map` анонса), `notify` — подписан ли ученик на письмо о выходе; оба
ключа приходят только у анонса.

`programs` — программы курса в том же виде, что у `course_programs`: место
курса в цепочке, предыдущий и следующий курс и `locked_by`, если курс для
ученика заперт порядком (learning-services#405). Курс вне программ —
пустой список. Курс с `locked_by` в каталоге остаётся: `enroll` на нём
откажет `program_order`, а агент назовёт курс, который пройти раньше.

В личном пространстве — весь опубликованный каталог без курсов, на которые
ученик уже записан. В пространстве организации — открытые ею курсы (пустой
список разрешённых — весь каталог) без тех, что уже в её пространстве: курс,
пройденный лично, можно взять и в компанию.

**Отказов нет.**

## `lms_frappe_app.api.student.enroll`

Записывает ученика на курс из каталога пространства.

**Параметры:** `course`, `space` (необязательный).

```json
{ "ok": true, "data": { "space": "org-1",
  "course": "course-python", "title": "Питон с нуля",
  "first_lesson": { "id": "lesson-1", "title": "Переменные" } } }
```

В пространстве организации запись — её назначение ученику с отметкой «выбран
сотрудником» (`chosen_by_member`): курс попадает в её пространство и отчёт,
обучение идёт за её счёт.

**Отказы:** `course_not_published`, `course_upcoming` — курс анонсирован и
ещё готовится, `already_enrolled` — курс уже в этом пространстве,
`course_not_allowed` — организация его не открыла, `space_not_available`,
`program_order` — ученик участник программы с обязательным порядком, а
предыдущий курс не пройден целиком (с `program`, `program_title` и `previous`,
learning-services#405).

## `lms_frappe_app.api.student.notify_when_released`

Подписывает ученика на письмо о выходе анонсированного курса
(learning-services#389) или снимает подписку (learning-services#391). Только
`POST`.

**Параметры:** `course`, `notify` (необязательный, по умолчанию `true`) —
`false` снимает подписку.

```json
{ "ok": true, "data": { "course": "ops-junctions",
  "title": "Где теряется работа между отделами", "notify": true } }
```

Повторный вызов ничего не меняет. Письмо уходит один раз, когда куратор
открывает курс `publish_course`. Отписаться можно и от курса, который уже не
анонс; в ответе тогда `notify: false`.

**Отказы:** `course_not_upcoming` — подписка на курс, который не анонсирован:
он открыт, снят или его нет.

## `lms_frappe_app.api.student.course_outline`

Дерево **курса из релиза** с прогрессом ученика (learning-services#506):
главы, уроки, цели уроков и их статусы, разделы документа, домашка. Способ
узнать идентификатор уже закрытого урока: `list_my_courses` отдаёт только
следующий. Только чтение.

**Параметры:** `course`.

```json
{ "ok": true, "data": { "course": "course-basics", "chapters": [
  { "key": "ch-1", "title": "Основы", "description": "Что изменится после главы",
    "status": "in_progress", "lessons_total": 2, "lessons_started": 1, "lessons_passed": 1,
    "lessons": [
      { "id": "lesson-1", "key": "l-1", "title": "Переменные",
        "hook": "Имя для значения — первое, что нужно программе",
        "completed": true, "current": false,
        "objectives": [ { "key": "l-1-D1", "text": "Называть значения", "status": "covered" } ],
        "sections": [ { "key": "log", "title": "Журнал", "description": "Что сюда записывают" } ],
        "homework": { "title": "Переменные из своей задачи" } },
      { "id": "lesson-2", "key": "l-2", "title": "Циклы", "hook": null,
        "completed": false, "current": true,
        "objectives": [ { "key": "l-2-D1", "text": "Выбирать между while и for",
                          "status": "not_started" } ],
        "sections": [], "homework": null } ] } ],
  "programs": [] } }
```

Главы и уроки — в порядке действующего релиза. У главы — ключ, название,
описание и прогресс ученика: `status` (`not_started`, `in_progress`,
`passed`), сколько уроков в главе, начато и пройдено (см. «Состояние ученика
по релизу»). У урока: `id` — запись `Course Lesson`, `key` — ключ урока в
релизе, `title`, `hook` (зачин; `null`, если автор его не задал);
`completed` — урок пройден (`passed` в прохождении); `current` — первый
непройденный урок курса. `objectives` — цели урока по порядку релиза со
статусом из прохождения (`not_started`, `touched`, `covered`; прохождения нет
— `not_started`); пунктов целей агента здесь нет. `sections` — разделы
документа курса, в которые пишет урок; `homework` — название домашки урока,
`null` — домашки нет.

Метод только читает: статусы — сохранённые в прохождениях, прохождений он не
заводит и с релизом не сверяет.

`programs` — программы курса в том же виде, что у `course_programs`: место
курса в цепочке, предыдущий и следующий курс и `locked_by`, если курс для
ученика заперт порядком (learning-services#405). Курс вне программ —
пустой список.

**Отказы:** `not_enrolled`, `organization_suspended`; `course_not_released`
(с `course`) — у курса нет действующего релиза.

Повторное открытие пройденного урока прогресс не двигает: `complete_lesson`
на нём безвреден, а квиз, если он есть, подчиняется обычному лимиту попыток.

## `lms_frappe_app.api.student.start_lesson`

Начинает занятие по уроку **курса из релиза**: прохождение урока, занятие по
нему и всё, что нужно агенту на старте, — карта урока, следующий шаг, пакет
агента, история ученика по курсу (learning-services#506). Курсу без
действующего релиза метод отказывает.

**Параметры:** `lesson` (необязательный) — имя `Course Lesson`; без него
берётся следующий незакрытый урок; `course` (необязательный) — выбирать только
в этом курсе, без него — по всем курсам ученика: урок последнего занятия, если
он не пройден, иначе следующий урок его курса, а без занятий — курс с
ближайшим дедлайном, обязательные и просроченные вперёд (тот же порядок, что у
`study_options`); при переданном `lesson` не действует; `space`
(необязательный) — в чей документ пишет занятие; без `lesson` и `course` урок
выбирается среди курсов этого пространства; `channel` — `agent` (по
умолчанию, свой агент ученика) или `web` (веб-чат платформы); `frame` (по
умолчанию `true`) — отдать рамку курса (`course_frame`).

`Why:` у `course` — выбор по всем курсам открывал урок курса, который горит
сильнее, когда ученик просил продолжить другой (lms-platform#337). `Why:` у
`frame` — протокол MCP сессий не хранит, и сервер не знает, видел ли агент
рамку в этом разговоре: агент просит её один раз и дальше передаёт `false`.

**Прохождение и занятие.** Прохождение урока (см. «Состояние ученика по
релизу») берётся до записи занятия: найденное сверяется с действующим
релизом, новое заводится; при первом старте ставится время, когда агент
получил список пунктов. Повторный вызов по тому же уроку в том же
пространстве **не создаёт второе занятие**: возвращается незакрытое. В другом
пространстве — другое занятие: оно пишет в другой документ. Занятие, открытое
без прохождения, получает его. Все отказы — до первой записи: отказ не
оставляет ни занятия, ни прохождения.

Канал `web` ограничен числом пробных уроков — `web_demo_lessons` в
`Agent Learning Settings`. Считаются **разные уроки** ученика по всем курсам,
где хоть один вызов пришёл с `web`: урок уже в счёте открывается снова и после
закрытия занятия по бездействию, продолжение урока своего агента в веб-чате
идёт в счёт. Канал подделывать незачем — `web` только ограничивает
передавшего.

```json
{ "ok": true, "data": {
  "session": "sess-01H…", "space": "org-1",
  "lesson": { "id": "lesson-6", "key": "l-6", "title": "Циклы",
              "hook": "Повторять одно и то же вручную — первое, что надоедает",
              "chapter": { "key": "ch-2", "title": "Управление ходом программы" },
              "course": "course-basics", "overdue": false },
  "course_promise": "К концу курса вы пишете программы с циклами и функциями",
  "start": { "opening": "new_lesson", "last_session_at": "2026-09-01T13:05:00" },
  "lesson_map": [
    { "key": "l-6-D1", "text": "Выбирать между while и for", "status": "touched",
      "goals": [
        { "key": "term:T4", "kind": "term", "required": true,
          "title": "Термин «условие цикла»", "status": "done" },
        { "key": "l-6-D1/V1", "kind": "variant", "required": true,

        { "key": "refute:M2", "kind": "misconception", "required": false,

  "next_step": { "kind": "goal", "objective": "l-6-D1", "goal": "l-6-D1/V1",
                 "title": "Выбор: «for по коллекции»" },
  "resume_from": "Начать с примера ученика про отчёты",
  "directive": "…", "material": "…",
  "section_hints": { "log": "…" },
  "diagrams": [ { "key": "task-flow", "title": "Куда отправить задачу",
```

`lesson` — урок: `id` — запись `Course Lesson`, `key` — ключ урока в релизе,
`title`, `hook` (зачин; `null`, если автор его не задал) и глава — из
действующего релиза. С `channel: web` — для шапки веб-чата
(learning-services#404) — в `lesson` ещё место урока в курсе, название курса и
пробные уроки: `"number": 6, "total": 12, "course_title": "Основы
программирования", "web_demo": { "used": 1, "limit": 2, "left": 1 }`. Своему
агенту их нет: пробы у него не считаются, программу он берёт `course_outline`.

`course_promise` — обещание курса, `null`, если его нет. Обещание и зачин
адресованы ученику.

`lesson_map` — цели урока по порядку релиза: ключ, текст, статус цели и пункты
целей агента (ключ, вид, обязательность, название, статус) — из прохождения;
снятые новым релизом не отдаются. Свидетельств к пунктам в ответе нет.

`next_step` — следующий шаг урока данными, без текста:

| `kind` | Когда | Данные |
|---|---|---|
| `goal` | есть открытый обязательный пункт — первый по порядку релиза | `objective`, `goal`, `title` |
| `quiz` | обязательные пункты закрыты (`done` или `planned`), у урока есть вопросы, квиз обязателен | — |
| `complete` | обязательные закрыты, а вопросов нет или квиз не обязателен | — |

Урок пройден — `next_step: null`. Фразу для агента складывает потребитель
контракта (CONTRIBUTING.md, «готовые тексты для агента»).

`resume_from` — заметка «с чего продолжить» из прохождения, её пишет
`mark_goal`; `null`, если её нет.

`directive` и `material` — из среза пакета агента для этого урока
(`agent.lessons.<ключ>` релиза); нет — пустая строка. `section_hints` —
подсказки агенту по разделам документа из того же среза (`sections`): ключ
раздела → текст; пустые не приходят, нет ни одной — `{}`. Ключи — разделы
документа действующего релиза: публикация не пропускает другие. `diagrams` —
схемы урока из того же среза (learning-services#644): ключ, название,
описание для модели и `when` — когда показать (нет — ключа нет); без HTML —
его отдаёт `lesson_diagram` по ключу. Схем нет — `[]`. `course_frame` — рамка
пакета (`frame`, `learn_about_student`, какие есть) — только при `frame:
true`; при `false` ключа нет. **Пакет агента отдаёт только этот метод**,
подробности пункта — `lesson_item`: ученик и руководитель его не видят ни в
одном другом ответе (см. «Запрещённые поля»). `resume_from` пишет `mark_goal`.

`start.opening` — с чего начинать занятие; сервер решает это сам, чтобы агент
не выводил его из признаков на каждом старте. Проверки идут по порядку:

| `opening` | Когда | Что звучит |
|---|---|---|
| `repeat` | по этому уроку уже было другое занятие со следом | ничего |
| `first_in_course` | других занятий со следом по курсу нет | обещание, зачин, цели |
| `return` | у прошлых уроков из `history` есть незакрытые цели, а прошлое занятие по курсу старше `bridge_after_hours` из `Agent Learning Settings` (сутки) | мостик от незакрытых целей `history.lessons`, цели |
| `new_lesson` | всё остальное | зачин, цели |

Незакрытое занятие того же урока переиспользуется, и продолжение повтором не
считается. **Занятие со следом** — с отметкой пункта своего прохождения в
этом занятии или с закрытым уроком: брошенная в начале попытка не в счёт, иначе
человек, не видевший урока, получил бы `repeat` и «сразу к делу»
(learning-services#408). `start.last_session_at` — последняя активность в
прошлых занятиях со следом по курсу, `null` для первого.

`history` — сводка ученика по курсу. `lessons` — прошлые уроки этого курса,
начатые или пройденные, кроме текущего: не больше `carry_over_depth` из
`Agent Learning Settings` самых свежих (по последней отметке пункта, началу
или зачёту); у урока — ключ, название, статус прохождения и цели не в
`covered`, с текстом. Название и тексты у урока, снятого из релиза, — из
последнего релиза, где он был; у прохождения без записи урока Learning
название — `null`. `notes` — заметки об ученике (факты, наблюдения и
проект этого курса): `by_key` — по ключам «что выяснять об ученике» рамки
курса (`learn_about_student[].key`), текст самой свежей заметки с этим
ключом; `other` — остальные, с видом и датой; проекты других курсов — пока у
этого курса своего нет, с `course` и `course_title` (#408). Объём заметок
держит `student_notes_limit`.

`closed_reports` — репорты ученика по этому курсу, получившие итог (`fixed`,
`rejected`, `duplicate`), о котором он ещё не узнал. Элемент — тот же, что в
`my_reports`. Отдаются **один раз**: вызов отмечает их доставленными, и
следующий `start_lesson` их уже не принесёт. Переоткрытый и снова закрытый
репорт приходит снова — это другой итог. Пусто, если нового нет.

`artifact_blocks` — краткие блоки документов курса, привязанные к этому
уроку (см. `course_map`), с заполненностью ученика. Это подсказка «сегодня
собираем этот раздел», а не ограничение: `update_artifact` принимает любой
ключ. Пусто, если к уроку не привязан ни один блок. Колонки и записанное —
`artifact` с ключом документа.

`quiz` — квиз урока: `required` — у урока есть вопросы в релизе и политика
требует квиз; `pass_threshold` — порог урока в действующем релизе долей
(`pass_percentage` / 100), как в итоге квиза. Незавершённая попытка,
перенесённая с прежней версии, оценивается своим порогом — снятым на её
старте; его отдаёт итог попытки (`submit_answer`, `pass_threshold`);
`attempts_left` — сколько попыток ещё можно
начать, по ученику, курсу и ключу урока; `null` — лимита нет или вопросов нет.
Лимит попыток и пауза — платформы, одни на всех (`Agent Learning Settings`).
Организация решает только, обязателен ли квиз; если курс назначили
несколько, квиз обязателен, когда этого требует хоть одна.

`homework` — домашнее задание этого урока, как у `homework`: обязательно ли
оно ученику (`required`) и какой срок для него действует в пространстве
занятия (`due`; у практики — `none`); выдаётся при закрытии урока.
`previous_homework` — задание **предыдущего по порядку курса
урока** и сдача ученика в пространстве занятия: статус, признак `required`,
срок, просрочка, версия и последний комментарий куратора (комментарий последнего возврата на
доработку или отмены приёма); `submission: null` — ученик по нему ничего не
сохранял. Ответ ученика и журнал — `my_homework(lesson=…)`
(learning-services#439). У урока без задания — `null` в обоих ключах,
независимо друг от друга.

`signals` — выводы сервера из истории ученика (learning-services#416); здесь
приходят `abandoned_in_row`, `blocks_empty` и `deadline_pace` — см. «Сигналы»
ниже.

Занятие пишет в журнал событие «указания выданы» — пакет агента выдан.

**Отказы:** `unknown_channel`; `not_enrolled`; `organization_suspended` —
организация ученика приостановлена, зачисление цело и доступ вернётся вместе
со статусом; `lesson_not_found`; `nothing_to_study` — незакрытых уроков не
осталось (только при вызове без `lesson`; с `course` — в этом курсе, с полем
`course`); `program_order` — курс заперт программой, как у `enroll`: запись
могла появиться раньше вступления в программу; `course_not_released` (с
`course` и `lesson`) — у курса нет действующего релиза или урока в нём;
`web_demo_exhausted` (с `lessons_used` и `lessons_limit`) — пробные уроки
веб-чата пройдены; `busy` (с `lesson`) — прохождение урока в эту минуту
меняет другой запрос (сверка после публикации релиза, параллельный вызов
агента): ничего не записано, вызов стоит повторить.

**Поверхность MCP-инструмента у `start_lesson` другая, чем у метода.**
Контракт описывает метод Frappe; инструмент MCP-сервиса — не его зеркало:
параметра `channel` у инструмента нет — сервис подставляет его сам, из
контекста вызова. Модель не может забыть канал, а поверхность инструментов у
своих агентов учеников остаётся прежней. Клиент, разговаривающий с
приложением напрямую, получает то, что описано здесь, и `channel` параметром.

Отзыв разрешения на курс у организации **отдельным кодом не отражается**:
проверка списка разрешённых курсов работает при назначении, а уже выданное
зачисление она не снимает.
Прошедший дедлайн отказом **не является**: урок отдаётся, в ответе
`overdue: true`, зачёт фиксируется как поздний.

### Сигналы

`signals` в ответах `start_lesson` и `mark_goal` — выводы сервера из истории
ученика по курсу из релиза, которых агент по одному разговору сделать не
может: код и данные, без текста. Фразу для агента складывает потребитель
контракта (CONTRIBUTING.md, «готовые тексты для агента»). В ответе не больше трёх сигналов,
по приоритету таблицы; каждый — один раз за занятие: показанный занятие
помнит, и повторный вызов его не принесёт. Пусто — сказать нечего.

| `code` | Данные | Когда |
|---|---|---|
| `abandoned_in_row` | `attempts` | `start_lesson`: два и больше последних занятия по уроку брошены подряд, и ни в одном не отмечен ни один пункт прохождения; занятие с отметкой цепочку рвёт |
| `blocks_empty` | `blocks` — краткие блоки (см. `course_map`) | `start_lesson` и `mark_goal`, разобравший цель: разобрана (`covered`) половина целей урока или больше, а ни один блок документа урока не начат |
| `deadline_pace` | `lessons_left`, `lessons_per_week` (`null` при просрочке), `overdue` | `start_lesson`: срок курса прошёл или к нему нужно от трёх уроков в неделю |

Статусы целей — из прохождения урока. Времени внутри занятия в сигналах нет:
сервер считает по нему сам — брошено ли занятие, успевает ли ученик к сроку —
и отдаёт вывод. Сигналы строятся только по истории самого ученика — без
репортов и без других учеников (решения владельца, learning-services#416).

## `lms_frappe_app.api.student.lesson_item`

Подробности пункта урока по занятию (learning-services#506): вид,
обязательность, название, статус и текст из пакета агента. Только чтение.

**Параметры:** `session`, `goal` — ключ пункта (`lesson_map[].goals[].key` у
`start_lesson`).

```json
{ "ok": true, "data": {
  "goal": { "key": "l-6-D1/V1", "kind": "variant", "required": true,
            "title": "Выбор: «for по коллекции»", "status": "open" },
  "details": "Что сделать ученику и ситуации практики, где ожидается «for по коллекции»." } }
```

`goal` — пункт из действующего релиза; `status` — сохранённый в прохождении
ученика, прохождения ещё нет — `open`. Метод прохождение не заводит, не
сверяет с релизом и не блокирует: сверка на чтении писала бы. `details` — текст пункта
из среза пакета агента (`agent.lessons.<ключ>.items.<пункт>`); нет — пустая
строка. Свидетельства в ответе нет.

**Отказы:** `not_your_session`; `course_not_released` (с `course` и `lesson`)
— у курса нет действующего релиза или урока занятия в нём; `not_enrolled`,
`organization_suspended`; `lesson_not_in_release` (с `course`, `lesson_key`,
`release`) — урок прохождения занятия снят из действующего релиза;
`goal_unknown` (с `goal` и `goals` — ключами пунктов урока в действующем
релизе).

## `lms_frappe_app.api.student.lesson_diagram`

Схема урока по занятию — целиком, с HTML для окна (learning-services#644).
Только чтение.

**Параметры:** `session`, `key` — ключ схемы (`diagrams[].key` у
`start_lesson`).

```json
{ "ok": true, "data": {
  "diagram": { "key": "task-flow", "title": "Куда отправить задачу",
               "description": "Шаги: срок, зона, данные.",
               "when": "когда ученик спрашивает, с чего начать",
               "html": "<!doctype html>…" } } }
```

Схема — из среза пакета агента урока занятия в действующем релизе
(`agent.lessons.<ключ>.diagrams`). HTML — страница автора: публикация
пропускает её только без внешних ресурсов и не больше 100 000 байт
(`releases.diagrams`). `when` — когда показать; нет — ключа нет.

**Отказы:** `not_your_session`; `course_not_released` (с `course` и `lesson`);
`not_enrolled`, `organization_suspended`; `lesson_not_in_release` (с `course`,
`lesson_key`, `release`); `diagram_unknown` (с `key` и `diagrams` — ключами схем
урока).

## `lms_frappe_app.api.student.mark_goal`

Отметка пункта урока по занятию (learning-services#506). Пишет пункт
прохождения (см. «Состояние ученика по релизу») и двигает активность занятия.

**Параметры:** `session`, `goal` — ключ пункта; `status` — `open`, `done`,
`planned` или `not_needed`; `evidence` — свидетельство: что ученик сказал или
сделал, обязательно у всех статусов, кроме `open`, не длиннее 500 знаков;
`resume_from` (необязателен) — заметка «с чего продолжить», не длиннее 500
знаков.

```json
{ "ok": true, "data": {
  "goal": "term:T4", "status": "done",
  "objective": { "key": "l-6-D1", "status": "touched", "open": [ "l-6-D1/V1" ] },
  "lesson": { "status": "in_progress" },
  "next_step": { "kind": "goal", "objective": "l-6-D1", "goal": "l-6-D1/V1",
                 "title": "Выбор: «for по коллекции»" },
  "signals": [] } }
```

`objective` — цель пункта: статус и открытые обязательные пункты этой цели по
порядку релиза. `lesson.status` — статус урока в прохождении. `next_step` — как
у `start_lesson`: первый открытый обязательный пункт урока, квиз, закрытие или
`null`. Отметка не по порядку пишется: следующий шаг скажет, что осталось.
Возврат в `open` стирает прежнее свидетельство. Свидетельство в ответ не
возвращается. `signals` — `blocks_empty`, когда отметка разобрала цель (см.
«Сигналы» у `start_lesson`); иначе пусто.

`resume_from` пишется в прохождение тем же сохранением, что и отметка (одна
версия в истории прохождения); пустой — прежняя заметка остаётся. Её вернёт
`start_lesson` в `resume_from`.

Отметка двигает активность занятия: занятие, где агент только отмечает
пункты, иначе было бы брошено по бездействию. Занятие, открытое без
прохождения, получает его — и тогда, когда отметке потом отказано на пункте.
Повтор той же отметки безвреден, но двигает время
отметки и занятие пункта.

**Отказы** — все до записи, кроме отказов на самом прохождении: прохождение,
сверенное с новым релизом, сохраняется и тогда, когда отметке отказано.
`not_your_session` — занятие другого ученика, а также урока или прохождения,
к которым занятие не относится; `course_not_released` (с `course` и
`lesson`); `not_enrolled`, `organization_suspended`; `session_closed` (с
`status`) — занятие закрыто, `Completed` или `Abandoned`: урок продолжают в
новом занятии, `start_lesson`; `goal_status_unknown` (с
`status` и `allowed`); `evidence_required` (с `status`); `evidence_too_long`
и `resume_from_too_long` (с `limit` и `length`); `goal_unknown` (с `goal` и
`goals`); `goal_removed` — пункт снят новым релизом; `not_needed_required` (с
`allowed`) — обязательный пункт не бывает ненужным; `run_archived` (с `run`)
— прохождение отвязано от ученика сбросом прогресса: урок начинают заново,
`start_lesson`; `lesson_not_in_release` (с `course`, `lesson_key`, `release`)
— урок снят из действующего релиза; `busy` (с `session`) — прохождение в эту
минуту меняет другой запрос: ничего не записано, вызов стоит повторить.

## `lms_frappe_app.api.student.study_options`

Что продолжать: урок, который открыл бы `start_lesson` без аргументов, и
следующие уроки других курсов пространства (learning-services#403). Зовёт веб-чат,
открытый без урока: вместо того чтобы молча начать урок и потратить пробный,
он показывает развилку.

**Параметры:** `space` (необязательный) — пространство; без него — выбранное.

```json
{ "ok": true, "data": {
  "recommended": {
    "lesson": { "id": "lesson-2", "title": "Цели и источники", "number": 2, "total": 8 },
    "course": { "id": "course-risks", "title": "Риски проекта" },
    "deadline": null, "overdue": false, "mandatory": false,
    "reason": "last_lesson", "web": true },
  "others": [ {
    "lesson": { "id": "lesson-7", "title": "Сегменты", "number": 1, "total": 6 },
    "course": { "id": "course-canvas", "title": "Lean Canvas" },
    "deadline": "2026-10-02", "overdue": false, "mandatory": true,
    "reason": "deadline", "web": false } ],
  "web_demo": { "used": 2, "limit": 2, "left": 0 } } }
```

Порядок: урок последнего занятия, если не пройден (`reason: last_lesson`),
иначе следующий урок его курса (`last_course`); дальше курсы по дедлайну
(`deadline`) и без него (`next`). По уроку на курс, пройденные курсы не
попадают. `others` — не больше трёх. `web` — пустит ли веб-чат на урок:
урок, уже начатый в браузере, пробного не тратит. Нечего продолжать —
`recommended: null`.

**Отказы:** нет.

## `lms_frappe_app.api.student.lesson_session`

Последнее занятие ученика по уроку **курса из релиза** — чтобы вернуть его в
разговор, а не начинать с чистого листа.

**Параметры:** `lesson`.

```json
{ "ok": true, "data": {
  "lesson": "lesson-6", "title": "Циклы",
  "course": "course-basics", "course_title": "Основы программирования",
  "number": 6, "total": 12,
  "session": "sess-01H…", "status": "Completed", "has_chat_state": true,
  "completed": true,
  "next_lesson": { "id": "lesson-7", "title": "Функции" },
  "objectives_progress": [
    { "key": "l-6-D1", "text": "Выбирать между while и for", "status": "covered" },
    { "key": "l-6-D2", "text": "Останавливать цикл вовремя", "status": "touched" } ] } }
```

`course`, `course_title`, `number` и `total` — курс урока и место урока в
нём, как в `lesson` у `start_lesson` с каналом `web`: их читает шапка
веб-чата.

`objectives_progress` — цели урока по порядку действующего релиза со
статусом из прохождения урока (`not_started`, `touched`, `covered`); пунктов
целей агента нет. Прохождение одно на урок, а не на занятие: статусы те же,
что у всех занятий урока, и приходят и тогда, когда занятий ещё не было
(прохождения нет — `not_started`).

Занятий по уроку ещё не было — `session` и `status` приходят `null`,
`has_chat_state` — `false`. `next_lesson` считается по курсу, а не по
занятию: это следующий незакрытый урок, и он приходит всегда, пока такой есть.

`Why:` `start_lesson` переиспользует только незакрытое занятие, а закрытое
квизом заводит заново — ученик, вернувшийся к пройденному уроку, видел его с
первого вопроса. По этому методу потребитель решает: показать историю
разговора или заводить занятие.

Метод только читает: занятий и прохождений не создаёт, прохождение с релизом
не сверяет и событий в журнал не пишет — иначе каждый возврат на страницу
оставлял бы след, которого не было.

**Отказы:** `lesson_not_found`, `not_enrolled`, `organization_suspended`;
`course_not_released` (с `course` и `lesson`) — у курса нет действующего
релиза или урока в нём.

## `lms_frappe_app.api.student.report_issue`

Репорт агента о том, что мешает курсу работать на этом уроке. Разбирают его
сотрудники платформы и авторы курса, а статус и ответ видит ученик —
`my_reports` и `closed_reports` у `start_lesson`.

**Параметры:** `session`, `kind`, `text`, `question` (необязателен),
`objective` (необязателен).

`kind` — один из `stuck`, `misconception`, `material_issue`,
`quiz_question_issue`, `directive_mismatch`, `out_of_scope`. `question` —
вопрос квиза этого урока, для репорта о вопросе: ключ вопроса урока в
действующем релизе (`id` вопроса у `request_quiz`). `objective` — цель урока
строкой, не ссылкой: переформулированная автором цель не должна задним числом
переписать то, о чём уже сообщили. Описание режется по 2000 символов, цель —
по 140.

**Курс, урок и действующий релиз курса проставляет сервер** из занятия, и
параметрами они не передаются: привязка от агента указала бы на чужой урок,
а вторая её копия разъехалась бы с занятием. Релиз отвечает на вопрос «это
ещё актуально или курс с тех пор переписали». Урок, снятый из действующего
релиза, вопросов не имеет: репорт о нём доходит без `question`.

```json
{ "ok": true, "data": { "report": "8f3c1a…", "kind": "material_issue" } }
```

Номер — для ученика: по нему он найдёт свой репорт в `my_reports` и узнает,
чем кончилось дело.

**Отказы:** `not_your_session` — занятие принадлежит другому ученику;
`course_not_released` (с `course`) — у курса нет действующего релиза;
`unknown_report_kind` (с `kind`) — вид не из списка; `report_text_required`
(с `kind`) — описание пустое; `question_mismatch` (с `question`) — нет такого
ключа вопроса у урока в действующем релизе.

## `lms_frappe_app.api.student.complete_lesson`

Закрывает урок **курса из релиза**, где квиз не обязателен: у урока нет
вопросов в релизе или политика организации квиза не требует.

**Параметры:** `session`.

```json
{ "ok": true, "data": {
  "lesson": "lesson-6", "session_status": "Completed",
  "next_lesson": { "id": "lesson-7", "title": "Функции" },
  "empty_blocks": [],
  "homework": { "lesson": "lesson-6", "title": "Цикл из жизни",
    "description": "Найдите у себя на работе повторяющееся действие…",
    "answer_mode": "text", "required": false,
    "due": { "mode": "none", "days": null, "date": null } } } }
```

Урок закрыт: прохождение — `passed`, прогресс Learning — пройден, домашка
урока выдана, занятие — `Completed`.

`homework` — задание этого урока, как у `homework`: с признаком `required` и
сроком, который действует для ученика в пространстве занятия; `null` — у
урока нет задания или оно снято из релиза. Ответ о закрытии несёт задание
сам: предложить его ученику агенту нужно именно сейчас, а ответ
`start_lesson` к концу урока у него может уже не храниться.

`empty_blocks` — краткие блоки документов курса (см. `course_map`), которые
собирают на этом уроке (раздел документа урока в релизе), а у ученика они не
заполнены на момент закрытия;
пустой список, если таких нет. Это предупреждение, а не отказ: урок
засчитывается и с пустым документом курса (решение владельца,
learning-services#296).

**Отказы**, по порядку: `not_your_session`; `course_not_released` (с `course`
и `lesson`); `not_enrolled`, `organization_suspended`; `session_closed` (с
`status`) — занятие уже закрыто, `Completed` или `Abandoned`; `run_archived`
(с `run`); `lesson_not_in_release` — урок снят из действующего релиза;
`goals_open` (с `goals` — открытыми обязательными пунктами, как у
`request_quiz`); `quiz_required` — квиз урока обязателен, и закрыть урок можно
только сдачей; `busy` (с `session`) — прохождение этого урока в этот момент
меняет другой запрос, урок не закрыт: повторите вызов.

`quiz_required` — несущее ограничение, а не формальность: без него метод стал
бы обходом проверки, и серверный зачёт, на котором держится вся схема,
потерял бы смысл.

Занятие, брошенное по бездействию, урок не закрывает: иначе урок числился бы
пройденным при брошенном занятии, и прогресс разошёлся бы с журналом. Вернуться
к уроку — `start_lesson`: он заведёт по нему новое занятие, и закрывается уже
оно.

## `lms_frappe_app.api.student.request_quiz`

Квиз урока **курса из релиза** по занятию: попытка и её первый неотвеченный
вопрос. Занятие в работе переходит в `Awaiting Quiz`.

**Параметры:** `session`.

```json
{ "ok": true, "data": {
  "attempt": "att-01H…",
  "question": { "id": "S1/l-6-D1", "text": "Ситуация и вопрос…",
                "kind": "choice", "multiple": false,
                "options": [ { "id": "3f9c1a7e02bd", "text": "…" },
                             { "id": "a41e7c90d5f3", "text": "…" } ],
                "index": 1, "total": 5 } } }
```

Квиз открыт, когда обязательные пункты урока закрыты (`done` или `planned`):
иначе — `goals_open` со списком открытых пунктов по порядку релиза, `{
"objective", "goal", "title" }`. Квиз агент видит всегда, а отказ называет,
что осталось (решение владельца, learning-services#497).

`id` вопроса — ключ релиза; `id` варианта — непрозрачный, свой у попытки, без
ключа релиза. Признака правильности в `options` нет, верный вариант у вопроса
один (`multiple: false`). Попытка снимает все вопросы урока действующего
релиза в своём случайном порядке, варианты каждого вопроса — тоже; `index` —
место вопроса в этой попытке — см. «Квиз урока из релиза».

Незавершённая попытка этого занятия на действующем релизе **возвращается как
есть**, с первым неотвеченным вопросом и со своим снимком вопросов: иначе
ученик бросал бы попытку после каждого вердикта, а лимит считает и брошенные.
Незавершённая попытка не на действующем релизе — её начали в момент
публикации новой версии, и публикация её не застала — аннулируется
(см. «Квиз урока из релиза»), а вызов сразу начинает новую. Если вызов откажет
раньше (`goals_open`, доступ к курсу и другие отказы до попытки), прежнюю
попытку он не трогает — её аннулирует следующий `submit_answer` в неё.

Ответ с **новой** попыткой несёт `previous_attempt_cancelled` — `attempt` и
`reason` аннулированной попытки, о которой агенту ещё не сообщали: вопросы
начались заново, и ученик должен знать почему. Это прежняя попытка,
аннулированная самим вызовом (`attempt_outdated`), а иначе — последняя попытка
ученика по этому уроку, если она аннулирована — обычно публикацией
(`quiz_changed`). Попытка — из этого занятия или из прежнего: занятие
закрывается по бездействию, и вернувшийся ученик просит квиз уже в новом.
Сообщается один раз: агент, получивший отказ `quiz_attempt_cancelled` в
`submit_answer`, уже знает, и `request_quiz` о той попытке молчит; молчит он
и о попытке, после которой ученик уже начинал новую. Продолжение
незавершённой попытки поля не несёт.

```json
{ "ok": true, "data": {
  "attempt": "att-01J…",
  "question": { "id": "S1/l-6-D1", "index": 1, "total": 5, "…": "…" },
  "previous_attempt_cancelled": { "attempt": "att-01H…", "reason": "attempt_outdated" } } }
```

Каждый выданный вопрос — и первый, и возвращённый с незавершённой попыткой —
пишется в журнал проверки (см. `submit_answer`).

**Отказы:** `not_your_session`; `course_not_released` (с `course` и
`lesson`); `not_enrolled` и `organization_suspended` — доступ к курсу отозван;
`run_archived` (с `run`); `goals_open` (с `goals`); `lesson_not_in_release` —
урок снят из действующего релиза (незавершённую попытку по нему, если вызов
до неё дошёл, он перед этим аннулирует); `quiz_not_configured` — у
урока нет вопросов; `quiz_attempts_exhausted` (с `attempts_used`);
`retry_too_soon` (с `retry_after`); `busy` (с `session`) — прохождение или
занятие в этот момент меняет другой запрос: попытка не начата, повторите
вызов.

`retry_after` в отказе `retry_too_soon` — ISO 8601 со смещением часового пояса
сайта, тот же момент, что `retry_after` в итоге проваленной попытки
(`submit_answer`).

## `lms_frappe_app.api.student.submit_answer`

Принимает ответ в попытку квиза урока из релиза, возвращает вердикт и
следующий вопрос, после последнего — итог.

**Параметры:** `attempt`, `question` — `id` вопроса, `answer` — `id` варианта
из этой попытки или его текст, `student_words` — необязательный.

`answer` сверяется без учёта регистра и пробелов, сначала с `id` вариантов
попытки, затем с их текстом: агенты присылают текст вместо `id`. Ключ варианта
в релизе ответом не служит. Список из одного
элемента — как сам элемент, из нескольких — неверный ответ. Неузнанный ответ —
неверный, а не ошибка.

`student_words` — необязательный: что ученик написал в ответ. Сервер его не
проверяет, и на вердикт он не влияет — судит только `answer`. Передан —
хранится в журнале проверки; длиннее 2000 знаков — обрезается, а не
отклоняется.

Ответ — ключ релиза узнанного варианта, неузнанный — как его прислал агент, —
слова ученика, если переданы, и вердикт хранятся в журнале проверки вместе с
выданными вопросами — для разбора курса. Журнал видят только администраторы
платформы; ни ученику, ни руководителю он не отдаётся.

```json
{ "ok": true, "data": {
  "verdict": { "correct": true, "explanation": "…" },
  "next_question": { "id": "S2/l-6-D1", "index": 2, "total": 5, "…": "…" },
  "attempt_finished": false } }
```

Неверный ответ — только `"verdict": { "correct": false }`: ни верного
варианта, ни пояснения.

Когда вопросы кончились:

```json
{ "ok": true, "data": {
  "verdict": { "correct": true },
  "next_question": null, "attempt_finished": true,
  "result": { "score": 0.8, "passed": true, "correct": 4, "total": 5,
              "pass_threshold": 0.7,
              "objective_results": { "l-6-D1": { "correct": 2, "total": 3 },
                                     "l-6-D2": { "correct": 2, "total": 2 } },
              "session_status": "Completed",
              "explanations": [ { "id": "S3/l-6-D1", "text": "…", "explanation": "…" } ],
              "next_lesson": { "id": "lesson-7", "title": "Функции" },
              "empty_blocks": [], "homework": null } } }
```

Попытка не зачтена:

```json
{ "ok": true, "data": {
  "verdict": { "correct": false },
  "next_question": null, "attempt_finished": true,
  "result": { "score": 0.4, "passed": false, "correct": 2, "total": 5,
              "pass_threshold": 0.7,
              "objective_results": { "l-6-D1": { "correct": 0, "total": 3 },
                                     "l-6-D2": { "correct": 2, "total": 2 } },
              "session_status": "Awaiting Quiz",
              "attempts_left": 2,
              "retry_after": "2026-09-25T14:30:00+03:00" } } }
```

`score` — доля верных; `pass_threshold` — порог попытки долей: порог урока,
снятый в попытку на её старте;
`objective_results` — верных из всех по каждой цели урока. Сданная попытка
закрывает урок, как `complete_lesson`, и подтверждает квизом цели, все вопросы
которых отвечены верно (см. «Квиз урока из релиза»). Её итог несёт
`next_lesson`, `empty_blocks` и `homework` — то же, что у `complete_lesson`.

`explanation` — пояснение вопроса — приходит только **вместе с верным**
ответом. Пояснения к неверно отвеченным вопросам — `explanations` — только в
итоге **сданной** попытки: несданная может быть не последней, а пояснение
называет верный вариант.

`attempts_left` и `retry_after` есть только в итоге **незачтённой** попытки.
`attempts_left` — сколько попыток ещё можно начать, `null` — лимита нет.
`retry_after` — момент, с которого `request_quiz` начнёт следующую попытку,
ISO 8601 со смещением часового пояса сайта; при `attempts_left: 0` —
`null`, пересдавать нечем.

**Отказы**, по порядку: `not_your_session` — попытка другого ученика;
`quiz_attempt_cancelled` — попытка аннулирована
новой версией курса (`attempt`, `session`, `reason`): при `reason:
quiz_changed` квиз урока изменился — запросите его заново (`request_quiz` по
`session` начнёт новую попытку), при `reason: attempt_outdated` попытка
начата на прежней версии курса — тоже запросите заново, при `reason:
lesson_removed` урок снят из курса и нового квиза по нему нет; `attempt_finished`; `not_enrolled` и
`organization_suspended` — доступ к курсу отозван, пока шла попытка;
`question_mismatch` — вопроса нет в попытке или на него уже отвечено; `busy`
(с `attempt`) — попытку или прохождение урока в этот момент меняет другой
запрос, ответ не принят: повторите вызов. Отклонённый ответ в журнал проверки
не попадает.

```json
{ "ok": false, "error": { "code": "quiz_attempt_cancelled",
  "message": "Квиз изменился в новой версии курса — запросите его заново: request_quiz",
  "attempt": "att-01H…", "session": "sess-01H…", "reason": "quiz_changed" } }
```

Попытку, которую новая версия курса не застала открытой (её начали в момент
публикации), аннулирует первый же ответ в неё — тем же отказом
`quiz_attempt_cancelled` с `reason: attempt_outdated` (урок снят —
`lesson_removed`) и сообщением «Попытка начата на прежней версии курса —
запросите квиз заново: request_quiz»: квиз с прежней версией не сравнивался,
и изменился ли он, неизвестно. Аннулирование идёт после проверки
доступа к курсу: при снятом зачислении или приостановленной организации ответ
— `not_enrolled` или `organization_suspended`, и попытка остаётся как была.

Доступ к курсу перепроверяется на каждом ответе, а не только при создании
попытки: приостановка организации или снятое зачисление посреди квиза иначе не
мешали бы довести попытку до зачёта по курсу, которого у ученика уже нет.

## `lms_frappe_app.api.student.artifact`

Документы курса, которые ученик собирает по ходу обучения, — перечень или
один документ целиком. Один метод и на обзор, и на чтение: два метода для
одного вопроса агент выбирает наугад.

**Параметры:** `course`, `artifact` (необязательный) — ключ документа, `space`
(необязательный) — чей документ.

Без ключа — перечень с долей заполненности:

```json
{ "ok": true, "data": { "course": "course-p3", "space": "org-1", "artifacts": [
  { "artifact": "agreements_log", "title": "Журнал договорённостей команды",
    "purpose": "Что команда решила и как она решает.",
    "modified": "2026-09-28T22:14:42.064609+05:00",
    "blocks_total": 3, "blocks_filled": 1 } ] } }
```

`purpose` — одна-две фразы автора курса: зачем ученику этот документ; `null`,
если автор не написал. `modified` — когда документ ученика последний раз
менялся, ISO 8601 со смещением пояса сайта; `null`, пока в нём ничего не
записано (learning-services#462).

С ключом — документ и его блоки в порядке схемы, с записанным учеником:

```json
{ "ok": true, "data": {
  "space": "org-1", "course": "3o2hh9e5d0", "artifact": "agreements_log",
  "title": "Журнал договорённостей команды", "purpose": "Что команда решила и как она решает.",
  "modified": "2026-10-13T14:32:05+05:00", "version": 12,
  "blocks": [
    { "key": "agreements", "title": "Договорённости",
      "description": "Что команда решила и кто за это отвечает", "lesson": "lesson-2",
      "rows": "many",
      "columns": [ { "key": "topic", "title": "Тема", "required": true },
                   { "key": "area", "title": "Область",
                     "required": { "if_column": "driver" } },
                   { "key": "note", "title": "Заметка", "required": false } ],
      "items": [ { "id": "A1", "topic": "Ретро раз в две недели" } ],
      "filled": true, "empty_cells": [] },
    { "key": "how_we_decide", "title": "Как мы решаем", "description": null,
      "lesson": "lesson-3", "rows": "one",
      "columns": [ { "key": "default_method", "title": "Способ по умолчанию",
                     "required": true } ],
      "values": { "default_method": "Согласие" },
      "filled": true, "empty_cells": [] } ] } }
```

Блок — раздел документа релиза (см. «Схема документа курса»):

- `rows` — `one`: блок заполняется один раз, его колонки — поля; `many` —
  блок ведётся строками;
- `columns` — колонки в порядке релиза; `required` — `true`, `false` или
  `{"if_column": "<колонка>"}`: обязательна, когда та колонка непуста (у
  строки — в той же строке, у блока `one` — его поле). Значение клетки и
  поля — текст;
- `description` — что сюда записывают, для ученика; `null`, если раздел его
  не задал. `lesson` — урок, на котором блок обычно заполняется; подсказка, а
  не ограничение;
- `items` — строки блока `many`: `id` и непустые клетки; у блока `one` ключа
  нет. `values` — непустые поля блока `one`; у блока `many` ключа нет. Пустые
  клетки и поля не приходят;
- `filled` — блок заполнен: у `many` в нём есть непустые строки и у каждой
  непусты обязательные колонки; у `one` непусто хоть одно поле и непусты
  обязательные поля. Обязательность — с учётом `if_column`. Строка без
  непустых клеток — заведённая, но ещё не заполненная — в заполненность не
  идёт;
- `empty_cells` — чего не хватает: `{row, column}` у непустых строк `many`,
  `{field}` у `one`.

ID строки — первая буква ключа блока в верхнем регистре и номер: `A1`, `A2`.
ID действует внутри блока, номера не переиспользуются: удалённая `A3` не
вернётся другой строкой.

`modified` — когда документ ученика менялся в последний раз (ISO 8601 со
смещением пояса сайта), `version` — сколько раз он сохранялся (по журналу
изменений Frappe); у документа, который ещё не заводился, — `null` и `0`.
Самой истории метод не отдаёт.

Документы идут в порядке, в каком автор их впервые объявил; правка схемы
порядка не меняет. Блок или колонка, убранные из схемы, в ответ не попадают,
но записанное остаётся в базе и вернётся вместе с ними.

**Отказы:** `not_enrolled`, `organization_suspended`, `artifact_not_found`.

## `lms_frappe_app.api.student.update_artifact`

Записывает строки или поля блока документа — или очищает блок.

**Параметры:** `course`, `artifact`, `key` — ключ блока, `rows`, `delete_rows`
— у блока `many`, `fields` — у блока `one`, `clear` (необязательный, по
умолчанию `false`), `space` (необязательный) — в чей документ, `fill_only`
(необязательный, по умолчанию `false`) — только дописать. `rows`,
`delete_rows` и `fields` допустимы и JSON-строкой: так тело запроса отдаёт
форма.

```json
{ "ok": true, "data": { "artifact": "agreements_log", "key": "agreements",
                        "blocks_total": 3, "blocks_filled": 1,
                        "empty_cells": [ { "row": "A2", "column": "area" } ],
                        "created": [ "A2" ] } }
```

Посреди занятия — у ученика есть открытое занятие по уроку курса из релиза —
в ответе ещё `objectives_progress`: цели урока этого занятия, как у
`lesson_session`, — уровень целей, без пунктов. Документ собирают на
занятии, и это место напомнить, где урок по целям (learning-services#409).
Открытого занятия нет или его урока нет в действующем релизе — ключа нет.

```json
{ "ok": true, "data": { "artifact": "agreements_log", "key": "agreements",
                        "blocks_total": 3, "blocks_filled": 1,
                        "empty_cells": [], "created": [],
                        "objectives_progress": [
                          { "key": "l-6-D1", "text": "Выбирать между while и for",
                            "status": "touched" } ] } }
```

`empty_cells` — чего не хватает блоку после записи: `{row, column}` у `many`,
`{field}` у `one`. `created` — ID строк, которые завела эта запись.

- `rows` — строки блока `many`: `{"id": "A1", "<колонка>": "<значение>"}`.
  Строка без `id` заводится, ID выдаёт сервер. Со `id` — правка: названные
  клетки меняются, прочие остаются. ID сравнивается без учёта регистра.
- `delete_rows` — ID строк блока `many` на удаление; удаление идёт раньше
  `rows`.
- `fields` — `{"<поле>": "<значение>"}` блока `one`: названные поля меняются,
  прочие остаются.
- Значение — текст или число (число становится текстом): пробелы по краям
  обрезаются, пустая строка или `null` клетку или поле стирает.
- `clear: true` стирает блок: у `many` — все его строки, у `one` — все его
  поля. Значений при этом не передают. Очистка блока в документе, который ещё
  не заводился, — не отказ: ответ тот же, документ не заводится.
- `fill_only: true` — только дописать: новые строки и пустые клетки или поля.
  Правка заполненного, удаление строк и очистка тогда — отказ
  `artifact_overwrite`. `Why:` дописывание и правка заполненного — разные по
  риску действия, и клиенту нужно знать, когда спрашивать подтверждение
  (learning-services#614).

Всё проверяется до записи: отказ не меняет документ. Экземпляр документа
заводится при первой записи; ключи блока и документа сравниваются без учёта
регистра. Сервер проверяет форму записи и обязательность; отвечает ли текст
разделу, смотрит агент: документ **на зачёт не влияет**, зачёт ставит сервер
по квизу, и подыгрывать здесь нечему.

**Отказы:** `not_enrolled`, `organization_suspended`, `artifact_not_found`,
`artifact_block_not_found`; `artifact_nothing_to_write` — нет ни `rows`, ни
`delete_rows`, ни `fields`, ни `clear`; `artifact_clear_with_content` — `clear`
вместе со значениями; `artifact_wrong_section` (с `rows` — видом блока) —
`rows` или `delete_rows` у блока `one`, `fields` у блока `many`;
`artifact_unknown_column` (с `column` и `columns`) — колонки нет у блока;
`artifact_unknown_field` (с `field` и `fields`) — поля нет у блока;
`artifact_unknown_row` (с `row`) — строки с таким `id` нет;
`artifact_invalid_value` (с `column` или `field`) — значение не текст и не
число или длиннее 4000 знаков (тогда ещё `max`); с `param` — `rows`,
`delete_rows` или `fields` не той формы; `artifact_too_many_rows` (с `max`) —
больше 200 строк в блоке; `artifact_overwrite` (с `touched`) — при
`fill_only` запись меняет заполненное: `touched` — удалённые строки, клетки
`<строка>.<колонка>` или поля, у которых было значение, или `clear`.

Документ принадлежит пространству: личному или организации, давшей курс.
Пространство определяется при первой записи — курс назначен организацией
ученика, значит её, иначе личное — и дальше не меняется: начатый документ
остаётся там, где начат. Личный документ читает только сам ученик. Документ
организации читают ещё её руководители (`Manager`, `Org Admin`) и — если
организация открыла документы всем — её участники; только прямым чтением
записи, методов отчётности с содержимым документа нет. Только у действующих
участников: документы ушедшего в пространстве организации ей больше не видны,
сам он читает свой по авторству и получает копию письмом (`remove_member`);
вернулся — организация видит их снова. `Why:` доступ решает
пространство документа, а не общая организация руководителя и ученика:
человек учится лично и в нескольких компаниях (learning-services#341).

## `lms_frappe_app.api.student.homework`

Домашнее задание урока и сдача ученика в пространстве (learning-services#439).
Зовут страница урока и окно загрузки файлов в чате.

**Параметры:** `lesson`, `space` (необязательный) — чья сдача.

```json
{ "ok": true, "data": {
  "space": "org-1", "lesson_url": "/lms/courses/course-p3/learn/2-1",
  "homework": { "lesson": "lesson-6", "title": "Встреча со спонсором",
    "description": "Проведите встречу и опишите итог…", "answer_mode": "text_and_files",
    "required": true, "due": { "mode": "relative", "days": 5, "date": null } },
  "submission": { "id": "a1b2c3d4e5", "status": "Submitted", "required": true,
    "due_at": "2026-10-06T14:02:11", "overdue": false, "version": 2,
    "assigned_at": "2026-10-01T14:02:11", "submitted_at": "2026-10-02T09:15:40",
    "answer": "Встретился, договорились о бюджете…",
    "files": [ { "id": "f1a2b3c4d5", "name": "protocol.pdf", "type": "pdf", "size": 48213,
                 "uploaded_at": "2026-10-02T09:15:40", "url": "/private/files/protocol.pdf" } ],
    "history": [
      { "event": "assigned", "by": "pupil@example.com", "by_name": "Анна Петрова",
        "at": "2026-10-01T14:02:11",
        "version": null, "comment": null, "due_at": "2026-10-06T14:02:11" },
      { "event": "returned", "by": null, "by_name": "Ирина Смирнова",
        "at": "2026-10-01T21:10:00",
        "version": 1, "comment": "Не хватает решения по бюджету", "due_at": null },
      { "event": "submitted", "by": "pupil@example.com", "by_name": "Анна Петрова",
        "at": "2026-10-02T09:15:40",
        "version": 2, "comment": null, "due_at": null } ],
    "versions": [ { "version": 1, "saved_at": "2026-10-01T20:00:00",
                    "answer": "Черновик…", "files": [] },
                  { "version": 2, "saved_at": "2026-10-02T09:15:40",
                    "answer": "Встретился, договорились о бюджете…", "files": [ { "id": "f1a2b3c4d5",
                      "name": "protocol.pdf", "type": "pdf", "size": 48213,
                      "uploaded_at": "2026-10-02T09:15:40", "url": "/private/files/protocol.pdf" } ] } ] } } }
```

**Задание** — одно на урок, от автора, одинаковое для всех. `answer_mode` —
какие поля есть у ответа: `text`, `files` или `text_and_files`. У урока без
задания `homework: null` — это не отказ: страница урока зовёт метод всегда.

`required` — обязательна ли домашка этому ученику в этом пространстве
(learning-services#627). Обязательная — в пространстве организации, которая
сама назначила ученику курс (назначение, а не курс, взятый участником из
каталога: `chosen_by_member` у `team.allocations`). Остальное — практика:
личное пространство, даже если курс назначен компанией, и курс, взятый
участником из каталога команды самим. Срок ставит тот, кто ждёт результат,
поэтому у практики срока нет: ни `due_at`, ни просрочки, ни напоминаний.
Обязательность курса в назначении (`mandatory`) на домашку не влияет.

`due` — срок, который действует для этого ученика, а не правило автора: у
обязательной — срок назначения организации (см. `team.allocations`), без него
— автора; у практики `due.mode` — `none`. `due.mode` — `none` (без срока),
`relative` (`days` дней после закрытия урока) или `absolute` (до конца дня
`date` по времени платформы). `due` — правило для ещё не выданной домашки;
если у сдачи уже есть `due_at`, срок ученику называют по нему — правило могли
поменять после выдачи. Если сдача уже заведена, `required` задания — её
признак.

**Сдача** — одна на задание, ученика и пространство; `null`, пока ученик не
сохранял ответ и урок не закрывался. Задание выдаётся закрытием урока — сданным
квизом или `complete_lesson`: фоном, через несколько секунд после ответа,
появляется сдача `Assigned` с `assigned_at` и, у обязательной, сроком. Статусы: `Assigned` — выдана, `Submitted` — сдана, `Returned` — на
доработке, `Accepted` — принята. `required` — признак сдачи: ставится, когда
сдача заводится (выдачей или первым сохранением), и потом не пересчитывается.
`due_at` — выставленный срок; относительный считается при выдаче и потом не
пересчитывается. `overdue` — признак, а не статус: срок прошёл, а статус
`Assigned` или `Returned`. `history` — журнал
событий `assigned`, `submitted`, `returned`, `accepted`, `reopened`: `by` —
почта автора, только если событие ваше (по ней страница пишет «Вы»), у
событий куратора — `null`; `by_name` — имя автора (у своих без имени — почта,
у куратора без имени — «Куратор»); `comment` — у действий куратора.
`versions` — снимок ответа на каждое сохранение, файлы старых версий остаются
доступными. `id` файла передаётся в `remove_files` метода `submit_homework`.

Домашка ничего не блокирует: ни следующий урок, ни завершение курса.

**Отказы:** `lesson_not_found`, `not_enrolled`, `organization_suspended`,
`space_not_available`, `course_not_in_space`.

## `lms_frappe_app.api.student.my_homework`

Домашки ученика в пространстве — со статусами, сроками и последним
комментарием куратора.

**Параметры:** `course` (необязательный) — только этого курса; `lesson`
(необязательный) — одна домашка урока целиком; `space` (необязательный).

```json
{ "ok": true, "data": { "space": "org-1", "items": [
  { "id": "a1b2c3d4e5", "course": "course-p3", "course_title": "Управление проектами",
    "lesson": "lesson-6", "lesson_title": "Спонсор проекта",
    "lesson_url": "/lms/courses/course-p3/learn/2-1", "title": "Встреча со спонсором",
    "status": "Returned", "required": true, "due_at": "2026-10-06T14:02:11", "overdue": false,
    "version": 2, "last_comment": "Не хватает решения по бюджету" } ] } }
```

Свежие сверху. `required` — признак сдачи, как в `homework`. `last_comment` — комментарий последнего возврата на доработку
или отмены приёма. С `lesson` строка одна и несёт ещё `homework` — задание, как у
`homework`, — и `submission` — сдачу целиком, без `versions`. Домашки курсов,
на которые ученик больше не записан, в перечень не попадают.

**Отказы:** `lesson_not_found`, `not_enrolled`, `organization_suspended`,
`space_not_available`, `course_not_in_space`.

## `lms_frappe_app.api.student.submit_homework`

Сохраняет ответ на домашку — сдаёт или правит. Каждый вызов — новая версия и
статус `Submitted`; сохранение до закрытия урока заводит сдачу сразу в
`Submitted`.

**Параметры:** `lesson`; `answer` (необязательный) — текст ответа целиком, не
передан — остаётся прежним; `space` (необязательный); `remove_files`
(необязательный) — `id` файлов, которые убрать из ответа; новые файлы — полями
`file` формы `multipart/form-data` (так шлёт страница урока) или списком
`files` из `{ "name": "protocol.pdf", "data": "<base64>" }` (так передаёт
MCP-сервис из окна загрузки в чате). Убранный файл не удаляется: на него
ссылаются прежние версии. Файлы сдачи добавляет только этот метод; править и
удалять их записи `File` может только System Manager.

```json
{ "ok": true, "data": { "space": "org-1",
  "submission": { "id": "a1b2c3d4e5", "status": "Submitted", "required": false,
    "due_at": null, "overdue": false, "version": 1, "assigned_at": null,
    "submitted_at": "2026-10-02T09:15:40", "answer": "Встретился…",
    "files": [],
    "history": [ { "event": "submitted", "by": "pupil@example.com", "by_name": "Анна Петрова",
                   "at": "2026-10-02T09:15:40",
                   "version": 1, "comment": null, "due_at": null } ],
    "versions": [ { "version": 1, "saved_at": "2026-10-02T09:15:40",
                    "answer": "Встретился…", "files": [] } ] } } }
```

Ответ не пустой — есть текст или файл — и несёт только поля из `answer_mode`.
Неполный ответ (`text_and_files` без файлов) принимается: оценки нет, его
видит и возвращает куратор. Пределы: не больше 10 файлов в ответе, размер
файла — `artifact_file_max_mb` из `Agent Learning Settings`, за одно
сохранение — не больше 18 МБ новых файлов: в base64 это около 24 МБ, а тело
запроса Frappe режет до 25 МБ. Типы — `pdf`, `docx`, `xlsx`,
`pptx`, `odt`, `ods`, `odp`, `txt`, `md`, `csv`, `png`, `jpg`, `jpeg`, `gif`,
`webp`, `heic`, `heif`; содержимое сверяется с расширением по первым байтам
(для документов Office и OpenDocument — по составу архива), у текста нет
нулевых байтов. Исполняемые файлы, разметка, архивы и форматы Office с
макросами не принимаются.

**Отказы:** `lesson_not_found`, `not_enrolled`, `organization_suspended`,
`space_not_available`, `course_not_in_space`; `no_homework` — у урока нет
задания; `empty_answer` — нет ни текста, ни файлов; `answer_mode` (с
`answer_mode`) — в ответе поле, которого у задания нет; `too_many_files` (с
`limit`); `file_missing` (с `file`) — файл не передан или пуст (в том числе
битый base64); `invalid_files` — `files` не список объектов `{ name, data }` или
`remove_files` не список `id`; `answer_text_too_long` (с `limit` и `length`) —
текст ответа длиннее 20 000 знаков; `file_too_large` (с `file` и `limit_mb`) — больше
нашего предела или предела Frappe; `file_type_not_allowed` (с `file` и
`allowed` — допустимые расширения) — расширения нет в списке или содержимое
не того типа; `answer_too_large` (с `limit_mb`) — новых
файлов больше предела сохранения; `storage_quota_exceeded` (с `limit_mb`,
`used_mb` и `days`) — новые файлы не помещаются в квоту ученика за последние
`days` дней (раздел «Пределы записи ученика»); `file_rejected` (с `file`) — Frappe не
принял файл; `accepted_locked` — домашку уже приняли; `busy` (с `lesson`) —
ту же сдачу в этот момент сохраняет другой запрос, ничего не сохранено:
повторите вызов. Отказ по файлу ничего не
сохраняет: ни ответа, ни других файлов этого вызова.

## `lms_frappe_app.api.student.remember`

Записывает об ученике то, что пригодится на следующих занятиях. Записанное
возвращается в `history.notes` при каждом `start_lesson`.

**Параметры:** `kind` — `fact`, `observation` или `project`; `key` — короткий
повторяемый ключ (`role`, `pace`, `scenario`); `text`; `session` — обязателен
для наблюдения и проекта; `new_only` (необязательный, по умолчанию `false`) —
только новая заметка.

Факт живёт у ученика целиком — роль и отрасль от предмета не зависят.
Наблюдение (как учится) и проект (на чём учится: свой проект, учебный
сценарий, роль в нём) привязываются к курсу занятия, поэтому без `session` их
записать нельзя. `Why:` учебный сценарий одного курса, записанный фактом,
молча приходил в другой (learning-services#408). Ключи нормализуются к нижнему
регистру.

```json
{ "ok": true, "data": { "key": "role", "kind": "fact" } }
```

С `session` открытого занятия по уроку курса из релиза в ответе ещё
`objectives_progress` — цели урока, как у `lesson_session`: запоминают
посреди занятия, там же напоминание, где урок по целям.

```json
{ "ok": true, "data": { "key": "pace", "kind": "observation",
                        "objectives_progress": [
                          { "key": "l-6-D1", "text": "Выбирать между while и for",
                            "status": "not_started" } ] } }
```

Запись по существующему ключу **замещает** текст, а не заводит вторую: ключ и
есть способ уточнить уже сказанное. С `new_only: true` замены нет: ключ уже
есть — отказ `note_exists`. `Why:` замена записанного о человеке и новая
запись — разные по риску действия, и клиенту нужно знать, когда спрашивать
подтверждение (learning-services#614).

В одном наборе — факты ученика, наблюдения одного курса, проект одного курса — помещается
`student_notes_limit` ключей из `Agent Learning Settings`. Упор в предел —
отказ; замещение записи по существующему ключу предела не двигает.

Факты по ключам профиля (набор отдаёт `my_profile`) в предел не входят: по
ним `remember` не отказывает, и в счёте прочих фактов они не участвуют.
`Why:` ученик с полным набором прочих фактов иначе не смог бы заполнить
профиль (learning-services#463). Набор фиксирован, так что предел остаётся
конечным.

**Отказы:** `unknown_note_kind` (с `kind`) — вид не `fact`, `observation` или
`project`; `note_key_required` (с `key`) — ключ пустой; `note_key_too_long` —
ключ длиннее 140 знаков, `note_too_long` — текст длиннее 2000 знаков (оба с
`limit` и `length`); `not_your_session` —
наблюдение или проект без `session` или по чужому занятию; `note_limit_reached` (с `limit`) — набор
заполнен; `note_exists` (с `key`, прежними `text` и `kind`) — с `new_only`
ключ уже есть; `busy` (с `key`) — заметки ученика в этот момент пишет другой
запрос, ничего не записано: повторите вызов.

## `lms_frappe_app.api.student.forget`

Удаляет заметку по ключу. Ученик вправе стереть о себе всё: заметки ведутся о
нём и доступны ему.
Заметка удаляется без копии в корзине, вместе с историей её правок.

**Параметры:** `key`, `course` (необязательный) — курс наблюдения или
проекта; факт стирается без него.

```json
{ "ok": true, "data": { "key": "role" } }
```

**Отказы:** `note_not_found` (с `key`).

## `lms_frappe_app.api.student.my_notes`

Что агент запомнил об ученике. Те же заметки, что приходят в `history.notes`
от `start_lesson`, — без группировки по ключам.

**Параметры:** `course` (необязательный) — добавляет к фактам наблюдения и
проект этого курса; без него приходят факты, а все проекты — в
`projects_elsewhere`.

```json
{ "ok": true, "data": {
  "facts": [ { "key": "role", "text": "Руководитель отдела",
               "since": "2026-09-01T12:20:00",
               "updated": "2026-09-02T09:10:00" } ],
  "observations": [ { "key": "pace", "text": "Считает в уме быстрее, чем пишет",
                      "since": null, "updated": "2026-09-02T09:10:00" } ],
  "project": [],
  "projects_elsewhere": [ { "key": "scenario",
                            "text": "Учебный сценарий «Северный склад»",
                            "since": null, "updated": "2026-09-24T21:26:04",
                            "course": "course-risks",
                            "course_title": "Риски проекта" } ] } }
```

`project` — проект этого курса. `projects_elsewhere` — проекты других курсов,
пока у этого своего нет: агент спрашивает, берём ли тот же или у ученика свой,
а не подставляет его молча.

`since` — когда факт записали впервые; у наблюдения его нет. `updated` —
когда текст замещали последний раз. Даты наружу не для красоты: наблюдение
трёхмесячной давности и вчерашнее — разные утверждения.

**Отказов нет.**

## `lms_frappe_app.api.student.my_profile`

Профиль ученика: факты агента по блокам и заполненность. Своих полей у
профиля нет — это фиксированный набор ключей фактов (`kind = fact`), тех же,
что пишет `remember` и отдаёт `my_notes`. Правится профиль теми же
`remember` и `forget`. `Why:` отдельные поля профиля разошлись бы с фактом
`role`, который агент и так пишет на уроках (learning-services#463).

**Параметры:** `user` (необязательный) — чей профиль, без него свой;
`summary` (необязательный) — `1`, чтобы получить только заполненность.

```json
{ "ok": true, "data": {
  "user": "ivanov@example.com", "full_name": "Иван Иванов", "user_image": null,
  "blocks": [ { "id": "work", "title": "Контекст работы", "facts": [
      { "key": "role", "label": "Роль", "text": "Руководитель отдела продаж",
        "updated": "2026-10-01T12:00:00" },
      { "key": "industry", "label": "Отрасль", "text": null, "updated": null } ] } ],
  "other_facts": [ { "key": "language", "text": "Пишет на Python",
                     "updated": "2026-09-20T18:40:00" } ],
  "filled": 1, "total": 9, "complete": false,
  "interview_url": "https://lms.example.com/chat?mode=profile" } }
```

`blocks` — блоки профиля по порядку, в каждом все ключи блока, заполненные
или нет: у пустого `text` и `updated` — `null`. `title` и `label` — подписи
на языке пользователя. Набор блоков и ключей потребитель берёт из ответа и
своей копии не держит. `other_facts` — факты вне набора, свежие сверху; подписей у них
нет — ключ придумал агент. Наблюдения и проекты курсов в профиль не входят:
они про курс, а не про человека.

`filled` — сколько ключей набора заполнено, `total` — сколько их всего,
`complete` — заполненных не меньше порога, и подсказку «заполните профиль»
пора гасить.

`interview_url` — адрес интервью с агентом о профиле в веб-чате. Только у
своего профиля и только когда у установки есть сервис агента, иначе `null`.

С `summary=1` — одна заполненность, без фактов: её читает сайдбар на каждой
загрузке.

```json
{ "ok": true, "data": { "filled": 5, "total": 9, "complete": false,
                        "interview_url": "https://lms.example.com/chat?mode=profile" } }
```

Чужой профиль видят только роли платформы (`System Manager`, `Administrator`,
`Agent Service`) — те же, что видят заметки агента. Руководителю организации
и автору курсов (`Moderator`) — отказ.

**Отказы:** `not_your_profile` (с `user`) — чужой профиль без роли платформы,
в том числе по несуществующему логину: отказ не подтверждает, есть ли такой
человек; `user_not_found` (с `user`) — роли платформы, когда такого
пользователя нет.

## `lms_frappe_app.api.student.my_reports`

Репорты с занятий ученика: что с ними стало и что ответили. Свежие сверху, не
больше 50.

**Параметры:** `course` (необязательный) — только репорты этого курса.

```json
{ "ok": true, "data": { "reports": [
  { "id": "8f3c1a…", "kind": "material_issue", "lesson": "lesson-5",
    "lesson_title": "Критический путь", "objective": null,
    "text": "В примере перепутаны сроки задач",
    "reported_at": "2026-09-01T13:02:00", "status": "fixed",
    "resolution": "Пример переписали: сроки задач сверены с диаграммой",
    "resolved_at": "2026-09-02T10:15:00" } ] } }
```

`status` — `new`, `in_progress`, `fixed`, `rejected` или `duplicate`.
`resolution` — ответ ученику от того, кто разбирал репорт; у дубля без своего
ответа — ответ репорта, дублем которого он признан, если тот из того же
курса. `resolution` и `resolved_at` — `null`, пока их нет. `objective` — цель урока, о которой был
репорт, если агент её назвал.

**Отбираются репорты занятий ученика, а не записи от его имени**: репорт,
перенесённый сотрудником платформы, остаётся репортом ученика. Прав на сам
`Agent Course Report` у ученика нет — читать его можно только этим методом.
Занятие и вопрос квиза наружу не идут.

**Отказов нет.**

## `lms_frappe_app.api.student.get_my_progress`

Сводка по себе в пространстве: сколько курсов, сколько просрочено, доля
пройденного, документы и последние занятия.

**Параметры:** `space` (необязательный).

```json
{ "ok": true, "data": { "space": "personal",
  "courses_total": 3, "courses_overdue": 1,
  "courses": [ { "id": "course-basics", "title": "Основы", "deadline": "2026-09-15",
                 "overdue": false, "completion": 0.42,
                 "documents": [ { "artifact": "summary", "title": "Резюме проекта",
                                  "purpose": "Проект на одной странице.",
                                  "modified": "2026-09-28T22:14:42.064609+05:00",
                                  "blocks_total": 6, "blocks_filled": 4 } ] } ],
  "recent_sessions": [ { "lesson": "lesson-6", "status": "Completed",
                         "started_at": "2026-09-01T12:20:00" } ] } }
```

`completion` — доля пройденных уроков курса, округлённая до сотых.
`documents` — документы курса и сколько блоков в них заполнено, как в перечне
`artifact`; отдельно от `completion`, потому что урок засчитывает квиз, а не
документ. У курса без документов — пустой список.
`documents` — документы этого пространства. `recent_sessions` — последние
занятия ученика в этом пространстве, свежие вперёд.

**Отказов нет.**

## `lms_frappe_app.api.student.chat_state`

Сохранённое состояние разговора веб-чата по своему занятию. Формат знает только
тот, кто его записал: backend хранит строку и не разбирает её.

**Параметры:** `session`.

```json
{ "ok": true, "data": { "session": "sess-01H…", "state": "{…}", "version": "1" } }
```

До первого сохранения `state` и `version` — `null`.

**Отказы:** `not_your_session`.

## `lms_frappe_app.api.student.save_chat_state`

Замещает состояние разговора по своему занятию. Одна запись на занятие.

**Параметры:** `session`, `state` — строка JSON, `version` — версия формата
состояния (сменилась — потребитель отбрасывает запись).

```json
{ "ok": true, "data": { "session": "sess-01H…", "version": "1" } }
```

Статус занятия не проверяется: квиз закрывает занятие посреди хода, а
состояние пишется после, и отказ терял бы последний ответ агента.

**Отказы:** `not_your_session`, `invalid_chat_state` — `state` не строка JSON
или `version` не строка до 140 знаков; `state_too_long` (с `limit` и `length`,
в байтах) — `state` больше 4 194 304 байт UTF-8 (4 МиБ).

Записи состояния не читаются напрямую ни учеником, ни руководителем, и ни один
метод отчётности их не отдаёт. `Why:` переписка — не отчётность, а внутри
состояния лежат результаты инструментов, включая директиву; ничего сверх того,
что ученик и так получает `start_lesson`, там нет, эталонов — тоже.

## `lms_frappe_app.api.student.scenario_state`

Сохранённый разговор сценария вне урока — своего. Сценарий — разговор с
агентом в боковой панели, не привязанный к занятию: интервью о профиле
(`profile`), позже знакомство с платформой. Урочный разговор живёт в
`chat_state`: его ключ — занятие. Формат знает только тот, кто его записал.

**Параметры:** `key` — ключ сценария: латиница в нижнем регистре, цифры, `_`
и `-`, начинается с буквы, до 32 знаков.

```json
{ "ok": true, "data": { "key": "profile", "state": "{…}", "version": "1" } }
```

До первого сохранения и после сброса `state` и `version` — `null`.

**Отказы:** `invalid_scenario_key` (с `key`).

## `lms_frappe_app.api.student.save_scenario_state`

Замещает разговор сценария. Одна запись на ученика и сценарий; счётчик ходов
не трогает.

**Параметры:** `key`, `state` — строка JSON, `version` — версия формата
состояния (сменилась — потребитель отбрасывает запись).

```json
{ "ok": true, "data": { "key": "profile", "version": "1" } }
```

**Отказы:** `invalid_scenario_key` (с `key`), `invalid_chat_state` (с `key`) —
`state` не строка JSON или `version` не строка до 140 знаков; `state_too_long`
(с `key`, `limit` и `length`) — как у `save_chat_state`; `busy` (с `key`) — запись разговора в этот момент
меняет другой запрос, и повтор на новом снимке тоже не прошёл: повторите
вызов.

## `lms_frappe_app.api.student.reset_scenario_state`

Начинает разговор сценария заново: стирает `state` и `version`. Нечего
стирать — тоже успех.

**Параметры:** `key`.

```json
{ "ok": true, "data": { "key": "profile" } }
```

Счётчик ходов сброс не трогает. `Why:` иначе лимит ходов обходился бы кнопкой
«начать заново».

**Отказы:** `invalid_scenario_key` (с `key`); `busy` (с `key`) — запись
разговора в этот момент меняет другой запрос, и повтор на новом снимке тоже не
прошёл: повторите вызов.

## `lms_frappe_app.api.student.count_lesson_turn`

Засчитывает ход веб-чата по уроку своего занятия и отвечает, сколько ходов
сделано в текущем окне. Сколько ходов позволено, решает вызывающий: метод
только считает.

**Параметры:** `session`.

```json
{ "ok": true, "data": { "session": "sess-1", "lesson": "lesson-6", "turns": 3 } }
```

Счёт — по прохождению урока, а не по записи занятия: новое занятие того же
урока (после квиза, закрытия без квиза или по бездействию) продолжает счёт.
`Why:` предел ходов даётся на урок, а занятий у урока бывает несколько. Окно —
24 часа от первого хода окна, как у `count_scenario_turn`; счётчик хранится в
базе, и рестарт сервиса его не обнуляет. Ход засчитывается одной записью, без
чтения перед ней, — параллельный ход не теряется.

**Отказы:** `not_your_session` (с `session`) — занятие чужое; `busy` (с
`session`) — прохождение в этот момент меняет другой запрос, и повтор на новом
снимке тоже не прошёл: повторите вызов. Курс занятия без действующего релиза —
`course_not_released`, как у `complete_lesson`.

## `lms_frappe_app.api.student.count_scenario_turn`

Засчитывает ход сценария и отвечает, сколько ходов сделано в текущем окне.
Сколько ходов позволено, решает вызывающий: метод только считает.

**Параметры:** `key`.

```json
{ "ok": true, "data": { "key": "profile", "turns": 3 } }
```

Окно — 24 часа от первого хода окна: истекло — следующий ход открывает новое
окно и считается первым (`1`). `Why:` лимит навсегда закрыл бы сценарий
ученику, который вернётся к нему через полгода. Счётчик хранится в базе, а не
в памяти сервиса, и рестарт его не обнуляет. Ход засчитывается отдельным
вызовом, а не перезаписью вместе с разговором: перезапись затёрла бы ход,
засчитанный параллельно.

Два хода разом база стенда (снимочная изоляция MariaDB) разводит
взаимоблокировкой или уникальным индексом; метод откатывает свою транзакцию и
один раз повторяет счёт на новом снимке. То же у `save_scenario_state` и
`reset_scenario_state`.

**Отказы:** `invalid_scenario_key` (с `key`); `busy` (с `key`) — запись
разговора в этот момент меняет другой запрос, и повтор на новом снимке тоже не
прошёл: повторите вызов.

Записи разговоров сценариев не читаются напрямую ни учеником, ни
руководителем, и ни один метод отчётности их не отдаёт — по той же причине,
что и у `save_chat_state`.

# Методы менеджера

Требуют роль `Organization Manager` и действующее членство `Manager` или
`Org Admin` в организации ученика. Проверка — в самом методе
(`организации_менеджера`, `общие_организации`): выборка идёт через
`frappe.get_all`, к которому `permission_query_conditions` не применяется.
Без роли и членства `org_report` отдаёт пустой `rows`, `student_detail` —
`not_your_student`.

## `lms_frappe_app.api.manager.org_report`

**Параметры:** `course` (необязательный), `status` (необязательный), `organization`
(необязательный) — отчёт одной из своих организаций; чужая — пустой `rows`.

```json
{ "ok": true, "data": { "rows": [
  { "user": "ivanov@example.com", "full_name": "Иван Иванов",
    "course": "course-basics", "organization": "Компания",
    "status": "in_progress", "progress": 0.42,
    "deadline": "2026-09-15", "mandatory": true, "overdue": false,
    "last_activity": "2026-09-01T12:20:00",
    "document": { "blocks_total": 11, "blocks_filled": 7 },
    "quiz": { "passed": 4, "first_try": 3 } } ] } }
```

`document` — сколько блоков во всех документах курса и сколько из них заполнил
ученик в пространстве этой организации: личный документ по тому же курсу не
считается. Считаются блоки действующих схем; у курса без документов — нули.
Отдельно от `progress`: урок засчитывает квиз, и без этой пары пройденный курс
с пустым документом не отличить от собранного.

`quiz` — сколько уроков курса сдано и сколько из них с первой попытки. Зачёт —
без ошибок и без лимита попыток, поэтому «сдан» не отличает понявшего от
перебравшего ответы, а номер зачтённой попытки отличает. Попытки считаются во
всех пространствах: прогресс у человека общий; наружу — только числа.

`status` — `not_started`, `in_progress` или `completed`; параметром `status`
выдача сужается до одного из них. Руководителю без организаций приходит
пустой `rows`.

**Отказов нет.**

## `lms_frappe_app.api.manager.student_detail`

Курсы, занятия и попытки квизов по одному ученику своей организации.

**Параметры:** `user`.

```json
{ "ok": true, "data": {
  "user": "ivanov@example.com", "full_name": "Иван Иванов",
  "courses": [ { "id": "course-basics", "title": "Основы",
                 "deadline": "2026-09-15", "overdue": false, "mandatory": true } ],
  "sessions": [ { "lesson": "lesson-6", "course": "course-basics",
                  "status": "Completed",
                  "started_at": "2026-09-01T12:20:00",
                  "finished_at": "2026-09-01T13:05:00",
                  "objectives": [ { "key": "l-6-D1", "text": "Выбирать между while и for",
                                    "status": "covered" } ] } ],
  "quiz_attempts": [ { "lesson": "lesson-6", "attempt": 1, "status": "Passed",
                       "score": 0.8, "passed": true,
                       "finished_at": "2026-09-01T13:05:00" } ] } }
```

В `courses` только курсы, пришедшие от организаций вызывающего, где ученик
сейчас состоит: человек может состоять в нескольких компаниях, и чужие
назначения — как и его самозапись — руководителя не касаются. `sessions` и
`quiz_attempts` — так же: только занятия в пространствах этих организаций, без
личной работы ученика и работы для другой компании (learning-services#344).
Ушедший из всех организаций вызывающего — отказ `not_your_student`
(learning-services#585).

`quiz_attempts[].status` — `In Progress`, `Passed`, `Failed`, `Abandoned`
(попытку без релиза закрыла миграция при переходе на квиз из релиза; попытки,
закрытые сбросом прогресса, уходят в архив и сюда не попадают) или
`Cancelled` — попытку
аннулировала новая версия курса: квиз урока изменился, урок снят или
попытку начали на прежней версии в момент публикации. У аннулированной
`score` — `0`, `passed` — `false`, `finished_at` — момент аннулирования; в лимит попыток она не идёт, и следующая попытка урока получает
тот же номер `attempt`.

`objectives` — цели урока занятия со статусом из прохождения урока
(`not_started`, `touched`, `covered`; см. «Состояние ученика по релизу»):
видно, какие темы разобраны, а на какие обратить внимание дальше. Пунктов
целей агента и свидетельств нет. Покрытие целей — по прохождению урока,
общему для всех пространств ученика, как и факт прохождения урока: у занятий
одного урока — и в разных пространствах — покрытие одно, каким оно стало к
этому часу.
Прохождение занятия — его собственное, у занятия без него — прохождение
ученика по уроку занятия; тексты целей — из релиза, с которым прохождение
сверено (у урока, снятого из релиза, — из последнего релиза, где он был),
снятые новым релизом цели не отдаются. Занятие курса без релиза — пустой
список.

Тексты ответов ученика на открытые вопросы **не отдаются**, заметки агента об
ученике и состояние разговора — тем более: отчёт про результат, а не про
содержание диалога. Документы ученика (`artifact`) сюда тоже не идут.

**Отказы:** `not_your_student` — запрошенный ученик не состоит ни в одной
организации вызывающего.

# Методы команды

Страница «Команда» в пространстве организации: участники и документы, которые
они собирают в её пространстве (learning-services#355). Доступ — тот же, что у
самих документов: руководители (`Manager`, `Org Admin`) видят всегда,
участники — если организация открыла документы всем
(`documents_visible_to: members`). Прочим, в том числе ушедшим, — отказ
`team_not_available`. Разговоры с наставником, заметки агента и личные
документы сюда не выходят ни при какой настройке.

## `lms_frappe_app.api.team.team`

Участники организации и курсы, которые она назначала, с документами курсов.

**Параметры:** `organization`.

```json
{ "ok": true, "data": {
  "organization": "org-1", "title": "Кофейни", "can_see_report": true,
  "can_manage": true, "can_change_roles": false, "member_limit": 25,
  "members": [ { "user": "ivanov@example.com", "full_name": "Иван Иванов",
                 "role": "Member", "left": false, "left_on": null } ],
  "courses": [ { "id": "course-p3", "title": "Проекты по P3.express",
                 "documents": [ { "artifact": "project_summary",
                                  "title": "Резюме проекта" } ] } ] } }
```

`members` — действующие, затем ушедшие (`left`, `left_on`): ушедший виден
только строкой с датой, его документы, домашки и занятия организации не
видны, пока он не вернётся (`remove_member`). `can_see_report` — зрителю открыт отчёт
(`org_report` с `organization`): только руководителю. `can_manage` — зритель
приглашает и отмечает уход (руководитель), `can_change_roles` — меняет роли
(администратор организации, `Org Admin`). `member_limit` — сколько
действующих участников может быть в неподтверждённой организации
(`own_org_member_limit`); `null` — без лимита.

**Отказы:** `team_not_available`.

## `lms_frappe_app.api.team.team_documents`

Документ курса у каждого участника в пространстве организации — по блокам,
для сравнения: что написал каждый в одном и том же блоке.

**Параметры:** `organization`, `course`, `artifact`.

```json
{ "ok": true, "data": {
  "organization": "org-1", "course": "course-p3", "artifact": "agreements_log",
  "title": "Журнал договорённостей команды",
  "authors": [ { "user": "ivanov@example.com", "full_name": "Иван Иванов",
                 "blocks_filled": 2, "blocks_total": 3,
                 "modified": "2026-09-28T14:02:11" } ],
  "blocks": [ { "key": "how_we_decide", "title": "Как мы решаем", "entries": [
    { "user": "ivanov@example.com", "full_name": "Иван Иванов",
      "filled": true, "markdown": "- Способ по умолчанию: Согласие" } ] } ] } }
```

Только документы действующих участников в пространстве организации: личный
документ по тому же курсу, документ для другой компании и документы ушедших
не входят. `markdown` — записанное участником в
блоке текстом: у блока `many` — таблица с колонкой ID, у блока `one` — поля
строками «Название: значение»; пустой блок — пустая строка.

**Отказы:** `team_not_available`, `course_not_in_organization` — организация
этот курс не назначала, `artifact_not_found`.

## `lms_frappe_app.api.team.create_invite`

Ссылка, по которой вступают в организацию участником (learning-services#363).
Руководитель отправляет её сам — писем платформа не шлёт. Одна ссылка — на
любое число людей. Только `POST`.

**Параметры:** `organization`.

```json
{ "ok": true, "data": { "token": "k3…", "url": "https://lms.example.com/lms/join/k3…" } }
```

**Отказы:** `team_not_available`, `not_allowed` — зритель не руководитель.

## `lms_frappe_app.api.team.invites`

Действующие ссылки организации — чтобы отозвать ненужную.

**Параметры:** `organization`.

```json
{ "ok": true, "data": { "invites": [
  { "token": "k3…", "url": "https://lms.example.com/lms/join/k3…",
    "created_by": "boss@example.com", "created": "2026-09-29T12:00:00" } ] } }
```

**Отказы:** `team_not_available`, `not_allowed`.

## `lms_frappe_app.api.team.revoke_invite`

Отзывает ссылку: по ней больше не вступить, вступившие остаются. Только `POST`.

**Параметры:** `token`.

```json
{ "ok": true, "data": { "token": "k3…", "revoked": true } }
```

**Отказы:** `invite_not_found`, `team_not_available`, `not_allowed`.

## `lms_frappe_app.api.team.invite_info`

Куда ведёт ссылка — страница вступления показывает это до входа, гостю тоже:
ключ — секрет ссылки.

**Параметры:** `token`.

```json
{ "ok": true, "data": { "organization": "org-1", "title": "Кофейни",
  "documents_visible_to": "managers", "suspended": false, "verified": true,
  "member": false } }
```

`documents_visible_to` — кто увидит документы по курсам компании; `verified` —
организацию подключили мы (созданную пользователем — нет, и страница говорит
это до кнопки); `member` — вошедший уже действующий участник.

**Отказы:** `invite_not_found` — ссылки нет или она отозвана.

## `lms_frappe_app.api.team.accept_invite`

Вступает в организацию участником и выбирает её пространство. Ушедший раньше
возвращается: членство снова действующее, курсы, назначенные без него,
догоняют его сами. Только `POST`, нужен вход.

**Параметры:** `token`.

```json
{ "ok": true, "data": { "organization": "org-1", "space": "org-1" } }
```

**Отказы:** `invite_not_found` — ссылки нет, она отозвана или организация
приостановлена; `organization_full` — у неподтверждённой организации
кончились места (`own_org_member_limit` в `Agent Learning Settings`).

## `lms_frappe_app.api.team.set_member_role`

Меняет роль участника: `Member`, `Manager` или `Org Admin`. Только
администратор организации: роль руководителя открывает документы и отчёт.
Роль Frappe `Organization Manager` следует за членством сама. Только `POST`.

**Параметры:** `organization`, `user`, `role`.

```json
{ "ok": true, "data": { "user": "ivanov@example.com", "role": "Manager" } }
```

**Отказы:** `team_not_available`, `not_allowed`, `not_a_member`,
`last_org_admin` — у организации не осталось бы администратора.

## `lms_frappe_app.api.team.remove_member`

Отмечает уход: членство закрывается. Организация видит документы, домашки,
занятия и попытки только действующих участников: работа ушедшего в её
пространстве остаётся в базе, но организации не видна, пока он не вернётся
(по ссылке или в Desk) — тогда видна снова. Свой документ ушедший читает
всегда. Ушедшему письмом уходит копия его документов пространства
организации, файлами `.md`; без исходящей почты письма нет, уход проходит
(learning-services#585). Удалённое членство — тот же уход. Выйти сам
(`user` — он сам) может любой действующий участник. Чужой уход: участника
отмечает руководитель, руководителя и администратора — только администратор;
повторная отметка ничего не меняет и отвечает `ok`. Последний администратор не
уходит. Только `POST`.

**Параметры:** `organization`, `user`.

```json
{ "ok": true, "data": { "user": "ivanov@example.com", "left": true } }
```

**Отказы:** `team_not_available`, `not_allowed`, `not_a_member` (в том числе
повторный выход), `last_org_admin`.

## `lms_frappe_app.api.team.allocations`

Назначения организации и курсы, которые она может назначить
(learning-services#365). Только руководителю.

**Параметры:** `organization`.

```json
{ "ok": true, "data": {
  "allocations": [ { "id": "ca-01", "course": "course-p3", "title": "Проекты по P3.express",
                     "whole_team": false, "members": [ "ivanov@example.com" ],
                     "deadline": "2026-10-31", "mandatory": true,
                     "chosen_by_member": false,
                     "homework": [ { "homework": "hw-01", "lesson": "lesson-6",
                                     "lesson_title": "Спонсор проекта",
                                     "title": "Встреча со спонсором",
                                     "author_due": { "mode": "relative", "days": 5, "date": null },
                                     "due": { "mode": "absolute", "days": null, "date": "2026-10-20" } } ] } ],
  "courses": [ { "id": "course-p3", "title": "Проекты по P3.express" } ] } }
```

`chosen_by_member` — курс взял сам сотрудник из каталога организации;
`courses` — опубликованные курсы, открытые организации. Анонсов в `courses`
нет: назначить их нельзя.

`homework` — домашние задания уроков курса в порядке уроков
(learning-services#452): `author_due` — правило срока автора (те же поля, что
`due` у `student.homework`), `due` — срок этого назначения, `null` — действует
срок автора. Срок назначения действует для всей его группы и только там, где
домашка обязательная, — правило обязательности в `student.homework`; у
назначения, взятого участником самим (`chosen_by_member: true`), сроки не
действуют. Если ученика покрывают несколько назначений организации, берётся
ближайший срок. Срок выставляется
сдаче при выдаче (при первом сохранении до выдачи — если все действующие
правила абсолютные) и потом не пересчитывается.

**Отказы:** `team_not_available`, `not_allowed`.

## `lms_frappe_app.api.team.assign_course`

Назначает курс всей команде (`members` пуст — новичок получит курс сам) или
выбранным людям, со сроком и отметкой обязательности. Адресатам уходит письмо
о назначении, один раз. Только `POST`.

**Параметры:** `organization`, `course`, `members` (необязательный — список
учётных записей), `deadline` (необязательный, `ГГГГ-ММ-ДД`), `mandatory`
(необязательный).

```json
{ "ok": true, "data": { "id": "ca-01" } }
```

За несколько дней до срока (`deadline_reminder_days` в `Agent Learning
Settings`, по умолчанию 3; `0` — не напоминать) тем, кто не прошёл курс,
уходит напоминание — тоже один раз. Тот же порог — у напоминания о сроке
домашки; если от выдачи до срока домашки меньше, напоминание уходит в
середине промежутка. На курс, взятый сотрудником самим, писем нет.

**Отказы:** `team_not_available`, `not_allowed`, `course_not_allowed` —
курс организации не открыт, `course_upcoming` — курс анонсирован и ещё
готовится.

## `lms_frappe_app.api.team.update_allocation`

Правит срок, обязательность, сроки домашек и — у поимённого назначения —
список людей. Дописанным уходит письмо; вычеркнутые остаются зачисленными.
Только `POST`.

**Параметры:** `allocation`, `deadline` (пустая строка снимает срок, не
передан — остаётся), `mandatory`, `members`, `homework_due`.

`homework_due` — сроки домашек назначения списком (или строкой JSON):
`[ { "homework": "hw-01", "due_mode": "relative", "due_days": 3 },
{ "homework": "hw-02", "due_mode": "absolute", "due_date": "2026-10-20" } ]`.
Список **заменяет** сроки целиком; `[]` снимает все; `null` или не передан —
сроки остаются. `due_mode` — `relative` (дней после закрытия урока) или
`absolute` (до конца дня по времени платформы); «как у автора» — строки нет.
Сроки, уже выставленные сдачам, не пересчитываются.

```json
{ "ok": true, "data": { "id": "ca-01" } }
```

**Отказы:** `allocation_not_found`, `team_not_available`, `not_allowed`;
`invalid_due` — `homework_due` не список объектов, режим не `relative` и не
`absolute`, у относительного нет дней, у абсолютного — даты, или задание
повторяется; `homework_not_in_course` (с `homework`) — задание не из курса
назначения. Строка задания, которое ушло из курса вместе с уроком,
отклоняется, только если её меняют; неизменённую назначение молча
выбрасывает.

## `lms_frappe_app.api.team.remove_allocation`

Снимает назначение. Зачисления остаются: прогресс принадлежит человеку.
Только `POST`.

**Параметры:** `allocation`.

```json
{ "ok": true, "data": { "id": "ca-01", "removed": true } }
```

**Отказы:** `allocation_not_found`, `team_not_available`, `not_allowed`.

## `lms_frappe_app.api.team.organization_terms`

Условия своей организации до её создания (learning-services#379): лимит
участников неподтверждённой организации и сколько ещё таких организаций
может создать вызывающий.

**Параметры:** нет.

```json
{ "ok": true, "data": { "member_limit": 25, "organizations_left": 3 } }
```

`null` в любом поле — без лимита.

**Отказы:** нет.

## `lms_frappe_app.api.team.create_organization`

Создаёт организацию: создатель — её администратор (`Org Admin`), её
пространство выбрано (learning-services#366). Созданная пользователем —
неподтверждённая (`verified: 0`): общий каталог, вступление только по ссылке,
не больше `own_org_member_limit` участников, пока мы её не подтвердим; у одного
человека — не больше `own_org_limit` таких организаций. Правила квиза у всех
одни. Только `POST`.

**Параметры:** `title` — название, от 2 до 140 знаков.

```json
{ "ok": true, "data": { "organization": "Моя команда", "title": "Моя команда" } }
```

**Отказы:** `organization_name_invalid`, `organization_name_taken`,
`organization_limit`.

# Методы куратора

Проверка домашек в вебе — очередь «Ждут проверки» и карточка сдачи
(learning-services#452). Все методы — только `POST`.

**Кто проверяет.** Руководитель (роль `Organization Manager`) — сдачи
пространств своих организаций; методист (`Course Creator`) и модератор
(`Moderator`) — все сдачи всех курсов, включая личные пространства. Свою сдачу
не проверяет никто, даже с ролью куратора; архивную (прогресс сброшен) — тоже.
Остальным очередь пуста, а действия отвечают `not_allowed`.

**Ученик** назван полным именем, без имени — почтой: почту ученика куратору
иначе не отдаём. В журнале сдачи (`history`) события самого читателя несут
`by` — его почту, остальные — `by: null` и `by_name`: имя ученика или
«Ученик», имя куратора или «Куратор».

**Проверенная версия** (`reviewed_version`) — `version` последней строки
журнала `returned`, `accepted` или `reopened`; `null` — сдачу ещё не
проверяли. С ней страница сравнивает текущую версию ответа.

**Дайджест.** Раз в день куратору уходит письмо «N домашек ждут проверки» со
ссылкой на очередь — первым ежечасным запуском после 9:00 по времени
платформы, в котором у него есть ожидающие. Руководителю — по его
организациям, модератору — по всем курсам, методисту — только по курсам, где
он в `instructors`. Свои сдачи не считаются; практика (`required: false`) —
тоже: её ученик сдаёт по желанию, и срока у неё нет. В очереди практика есть.
Пустая очередь — письма нет.

## `lms_frappe_app.api.review.queue`

Сдачи, которые куратор вправе проверять, — старые сверху.

**Параметры:** `status` — `Submitted` (по умолчанию), `Returned`,
`Accepted` или `Assigned`; `course` (необязательный), `organization`
(необязательный; `personal` — личные пространства), `limit` (по умолчанию и
не больше 50).

Пример — для методиста: ему видны и личные сдачи.

```json
{ "ok": true, "data": {
  "items": [ { "id": "a1b2c3d4e5", "status": "Submitted", "student": { "name": "Анна Петрова" },
               "course": "course-p3", "course_title": "Управление проектами",
               "lesson": "lesson-6", "lesson_title": "Спонсор проекта",
               "title": "Встреча со спонсором",
               "organization": "org-1", "organization_title": "Кофейни Юга",
               "submitted_at": "2026-10-02T09:15:40", "version": 2, "reviewed_version": 1,
               "required": true, "due_at": "2026-10-06T14:02:11", "overdue": false } ],
  "total": 1,
  "courses": [ { "id": "course-p3", "title": "Управление проектами" } ],
  "organizations": [ { "id": "org-1", "title": "Кофейни Юга" },
                     { "id": "personal", "title": "Личное" } ] } }
```

`total` — сколько сдач под фильтром, `items` — не больше `limit`.
`organization` — имя организации или `personal`, `organization_title` у
личного — «Личное». `courses` и `organizations` — значения для фильтров из всех
видимых куратору сдач, без учёта выбранных фильтров; `personal` в них есть,
только если куратору видны личные. Руководителю фильтр `personal` отдаёт
пустую очередь. `required` и `overdue` — как у `my_homework`: `required:
false` — практика, без срока; в дайджест она не входит (см. «Дайджест»
выше).

**Отказов нет.**

## `lms_frappe_app.api.review.submission`

Карточка сдачи: задание, ответ с версиями, журнал и действия, доступные сейчас.

**Параметры:** `submission`.

```json
{ "ok": true, "data": {
  "submission": { "id": "a1b2c3d4e5", "status": "Submitted", "required": false, "due_at": null,
    "overdue": false, "version": 2, "assigned_at": "2026-10-01T14:02:11", "submitted_at": "2026-10-02T09:15:40",
    "answer": "Встретился, договорились о бюджете…", "files": [],
    "history": [ { "event": "returned", "by": null, "by_name": "Ирина Смирнова",
                   "at": "2026-10-01T21:10:00", "version": 1,
                   "comment": "Не хватает решения по бюджету", "due_at": null } ],
    "versions": [ { "version": 1, "saved_at": "2026-10-01T20:00:00",
                    "answer": "Черновик…", "files": [] } ] },
  "homework": { "lesson": "lesson-6", "title": "Встреча со спонсором",
    "description": "Проведите встречу и опишите итог…", "answer_mode": "text_and_files",
    "required": false, "due": { "mode": "none", "days": null, "date": null } },
  "student": { "name": "Анна Петрова" },
  "course": "course-p3", "course_title": "Управление проектами",
  "lesson": "lesson-6", "lesson_title": "Спонсор проекта",
  "lesson_url": "/lms/courses/course-p3/learn/2-1",
  "organization": "org-1", "organization_title": "Кофейни Юга",
  "reviewed_version": 1,
  "actions": [ "accept", "send_back" ] } }
```

`submission` и `homework` — те же формы, что у `student.homework`: срок и
признак задания — те, что действуют для ученика сдачи. `actions`
— что куратор может сделать сейчас: `accept` и `send_back` у сдачи в статусе
`Submitted`, `reopen` — у `Accepted`; пустой список — карточка только для
чтения. Открыть карточку может всякий, кому видна сдача, — и сам ученик;
своя и архивная сдача приходят без действий.

**Отказы:** `submission_not_found`; `not_allowed` — сдача вам не видна.

## `lms_frappe_app.api.review.accept`

Принимает сдачу. Принятую ученик больше не правит.

**Параметры:** `submission`, `version` — версия, которую куратор видел.

```json
{ "ok": true, "data": { "submission": { "id": "a1b2c3d4e5", "status": "Accepted" },
  "homework": { }, "student": { "name": "Анна Петрова" },
  "course": "course-p3", "course_title": "Управление проектами",
  "lesson": "lesson-6", "lesson_title": "Спонсор проекта",
  "lesson_url": "/lms/courses/course-p3/learn/2-1",
  "organization": "org-1", "organization_title": "Кофейни Юга",
  "reviewed_version": 2, "actions": [ "reopen" ] } }
```

Ответ — карточка, как у `submission`, после действия. В журнал пишется строка
`accepted` с версией.

**Отказы:** `submission_not_found`; `not_allowed` — эту сдачу вы не
проверяете или она ваша; `stale_version` (с `version` — текущей) — ученик
сохранил новую версию, посмотрите её; `wrong_status` (со `status`) — сдача не
в `Submitted` или уже неактивна; `busy` — сдачу в этот момент меняет другой
запрос, ничего не сохранено: повторите.

## `lms_frappe_app.api.review.send_back`

**Параметры:** `submission`, `version`, `comment`.

Возвращённую ученик правит, сохранение снова ставит `Submitted` новой

**Отказы:** как у `accept`, и `comment_required` — комментарий пустой.

## `lms_frappe_app.api.admin.reset_student_progress`

Сбрасывает прогресс ученика по курсу записи — как будто он на курс не
записывался. Кнопка «Сбросить прогресс» на карточке `LMS Enrollment`.

**Параметры:** `enrollment` — запись на курс.

```json
{ "ok": true, "data": {
  "student": "ivanov@example.com", "course": "course-basics",
  "sessions_archived": 2, "attempts_archived": 1, "quiz_events_archived": 3,
  "artifacts_archived": 1, "notes_archived": 1, "homework_archived": 1, "runs_archived": 1,
  "progress_deleted": 1, "enrolled_again": false } }
```

Занятия, попытки квиза и их журнал проверки (`Agent Quiz Event` — в нём слова
ученика), документы курса, заметки агента, сдачи домашки и прохождения уроков
по курсу уходят в архив: ученик переносится в
`archived_student` с датой `archived_at`, поле «Ученик» очищается. Методы
учебного потока ищут по ученику и архив не видят — следующее занятие по курсу
открывается как первое (`first_in_course`), лимит попыток квиза полный,
документ пустой, домашка сдаётся заново новой сдачей, урок курса из релиза
проходится заново новым прохождением. Открытые занятия и попытки закрываются
как брошенные. Заметки без курса — общие факты об ученике — не трогаются.

Удаляются отметки пройденного (`LMS Course Progress`) и сама запись на курс.
Если курс ученику назначила организация, запись выдаётся заново, пустая
(`enrolled_again: true`): иначе обязательный курс пропал бы до пересохранения
назначения.

Репорты не трогаются: `my_reports` находит их и по архивным занятиям, и ответ
автора ученик видит. В карточке пользователя остаётся комментарий: кто, когда
и что сбросил.

Одна транзакция: упало на любом шаге — не изменилось ничего. `Why:` архив, а не
удаление, — решение владельца (learning-services#313): история занятий и
репортов остаётся.

**Права:** администратор платформы (`System Manager`) или автор курса —
преподаватель курса либо модератор, как решает Learning (`can_modify_course`).
Остальным — ошибка прав Frappe.

**Отказы:** `enrollment_not_found`.

# Релиз курса

Курс публикуется целиком — релизом: один JSON-документ формата
`lms-release/1` (learning-services#500). Собирает его компилятор курса вне
платформы; приложение проверяет релиз, хранит снимок новой версией и строит
по нему курс Frappe Learning. Публикует релиз `publish_release` — с
инструкторами курса (`instructors`) или без них, с коммитом источника
(`commit`) или без него. Предел размера релиза — в разделе метода
(`max_file_size`).

Схема публичной и серверной части —
`lms_frappe_app/agent_learning/releases/release.public.schema.json`
(JSON Schema 2020-12). Дом схемы — здесь; копия — у компилятора курса, и
сверяется она с этой.

| Часть | Что | Как с ней обходится приложение |
|---|---|---|
| `format` | `"lms-release/1"` | другой — отказ `release_format_unsupported` |
| `course` | ключ, название, карточка, обещание, корневая цель, атрибуция, глоссарий | карточка — в курсе Learning |
| `chapters` | главы по порядку: ключ, название, описание, уроки | глава Learning по ключу |
| `lessons` | уроки по порядку: ключ, глава, название, зачин, разделы документа, цели с пунктами целей агента, квиз, домашка | урок Learning по ключу; цели, пункты и квиз — в индексе релиза |
| `document` | документ курса: разделы и колонки; `null` — документа нет | схема документа курса |
| `agent` | пакет агента: рамка курса (`frame`, `learn_about_student`) и срезы уроков (`lessons.<ключ урока>`) | раскладывается по индексу релиза как есть: срез — к уроку, рамка — к релизу; содержание не разбирает; части среза и рамки читает по имени; сверяет ключи срезов, `items`, `sections` |
| `map` | карта курса | **непрозрачна**: хранится в снимке как есть, форма не проверяется; приложение читает из неё подписи узлов для заметок и срез урока для кабинета автора — урок `map.lessons.<ключ урока>` и узлы, на которые он ссылается |

Правила:

- **Ключи стабильны.** На ключе держится состояние ученика между релизами;
  переименовать ключ — то же, что удалить узел и завести новый.
- **`lessons[].quiz.answers` — только сервер.** Верный вариант и пояснение не
  уходят ни в один ответ ученику и агенту; пояснение ученик видит после ответа
  — по правилу квиза урока («Квиз урока из релиза»).
  Релиз и его индекс читают только авторские роли.
- **Сверх схемы сервер проверяет** уникальность ключей в своих пространствах,
  ссылки (урок ↔ глава, урок → разделы, вопрос → цель своего урока, ответ →
  вопрос, условие колонки → колонка раздела), порядок уроков по главам, что
  верный вариант — вариант своего вопроса, что документ ложится на движок
  документов (ключи раздела и колонки — латиница в нижнем регистре, поле
  раздела «один раз» не совпадает с другим полем или колонкой), что названия
  влезают в поля Learning, что в названиях глав, уроков, домашек и документа
  нет `<` и `>` — Frappe не принимает их в имени записи, а имя главы и урока
  Learning — номер и название; название домашки и документа Desk выводит без
  экранирования, и шаблон домашки и схема документа не сохраняются с ними ни
  на каком пути записи (`title_forbidden_chars`), — что в пакете агента нет
  ответов квиза — ключей `answers` и `correct` на любой глубине — и что ключи
  пакета агента сходятся с публичной частью: срез `agent.lessons.<ключ>` —
  урока релиза, его `items` — пунктов целей этого урока, его `sections` —
  разделов документа. Сверяются только ключи частей-объектов; полноты пакета
  сервер не требует: урок без среза и пункт или раздел без записи в срезе — не
  ошибка.
- **Поля без очистки HTML.** Угловые скобки и всё, что похоже на HTML, эти
  поля хранят как есть — у любой записи, — и методы отдают их в JSON без
  изменений: описание главы, зачин урока, текст цели, название пункта, текст
  вопроса и пояснение, название и описание раздела документа, обещание курса,
  описание домашки, назначение документа, название, описание и подсказка
  блока документа, тексты целей и пунктов в прохождении урока. Так же, как
  есть, хранятся и отдаются тексты внутри JSON: варианты ответов квиза,
  названия колонок разделов, домашка и срез пакета агента в индексе. Кто
  выводит их в HTML, тот и экранирует. Остальные тексты Frappe при записи
  чистит от HTML: названия глав, уроков, домашек и документа (`<` и `>` в них
  — отказ) и карточка курса Learning — название, краткое и полное описание:
  разметка в ней может быть вырезана, а `<` экранирован («Тексты и HTML»),
  о чём публикация предупреждает (`course_card_markup`).
- **Раздел документа — блок с тем же ключом.** Раздел `rows: many` — таблица
  блока, `rows: one` — поля блока; ячейки — многострочный текст. Блок
  показывается на уроке, который первым пишет в раздел.
- **Снятое из релиза уходит из программы**: запись урока или главы, на которую
  ничего не ссылается, публикация удаляет; запись со следами учеников и автора
  (занятия, прохождения, попытки квиза, сдачи домашки, репорты, прогресс и
  записи на курс Learning; у главы — её оставленные уроки) остаётся вне
  программы. Вернувшийся ключ получает оставленную запись, а ключ удалённой —
  новую. Программа курса с релизом — только главы и уроки релиза.
- **Прогресс записи на курс — по программе.** Доля пройденного в записи на
  курс Learning (`LMS Enrollment.progress`) у курса из релиза считается только
  по урокам программы: пройденный урок, снятый из релиза, в неё не входит, а
  непройденный снятый не держит курс незавершённым. Публикация пересчитывает
  доли записанных фоном, после коммита. На доле держатся сертификат и
  программы Learning и всё, что считает курс пройденным. `Why:` Learning
  делит все пройденные уроки курса на уроки оглавления, а снятый урок со
  следами учеников остаётся записью вне оглавления: доля выходила выше
  настоящей и бывала больше 100 (learning-services#522).
  **Достигнутые 100 не опускаются**: урок, добавленный новой версией, не
  снимает прохождение с тех, кто курс уже прошёл, а доля больше 100
  приводится к 100. Опускают долю только снятые отметки пройденного
  ученика (их снимает администратор или сброс прогресса): удаление отметки
  `Complete` или её переход в другой статус. Сброс к тому же удаляет саму
  запись на курс, и запись, выданная заново, начинается с 0. Ручная правка
  удержанной доли в Desk откатывается к 100. Доли, записанные до этого
  правила, патч `release_course_progress` пересчитал по программе без
  удержания: формула Learning их завышала, и записанные 100 могли быть
  неверными; удержание действует с первой записи после него. `Why:` последствия публикации автора не
  должны снимать прохождение задним числом: вместе с ним закрывались бы
  сертификат и следующий курс программы (решение владельца,
  learning-services#522).
- **Ключ главы и урока — на записи Learning**: `Course Chapter.chapter_key`,
  `Course Lesson.lesson_key`. Ставит его только публикация — при создании
  записи, — и он не меняется: ключ, присланный любым другим путём (редактор
  и импорт курса Learning, `frappe.client`), сервер пропускает: ключ остаётся
  прежним, отказа нет. У глав и уроков курса без релиза ключа нет (`null`).
- **Релиз неизменяем.** Исправление — новый релиз; откат — публикация
  прежнего коммита новой версией.
- **Содержимое хранится только у действующей версии.** Публикация новой
  версии освобождает все прежние: снимок и индекс (главы, уроки, цели, пункты,
  вопросы, разделы документа) удаляются в той же транзакции, и откат
  публикации откатывает и это. От прежней версии остаётся запись — номер,
  дайджест, кто и когда опубликовал, ключ документа, коммит, находки и
  изменения публикации (`course_releases`). Содержимое прежней версии сервер не хранит: у версии
  с коммитом его восстанавливает git по коммиту, у версии без коммита — нет,
  и кандидата из истории источника проверяет `digest`: собранный из него
  релиз даёт тот же дайджест — если собран тем же компилятором и с той же
  нормализацией, что и версия: дайджест считается по собранному релизу, а не
  по источнику. Освобождённая
  версия действующей больше не становится. Данные учеников и автора держатся
  не на содержимом прежних версий: ключ урока — на записи Learning и в
  заметке, тексты целей — в прохождении, открытую попытку квиза публикация
  переносит или аннулирует.

## Состояние ученика по релизу

Прогресс ученика по курсу из релиза держится на ключах релиза, а не на записях
Learning: ученик всегда на действующем релизе, и новый релиз переносит его
состояние по ключам. Здесь — модель; урок по ней ведут методы агента:
`start_lesson`, `lesson_item`, `mark_goal`, `request_quiz`, `submit_answer`,
`complete_lesson` (learning-services#506).

### Прохождение урока

Прохождение — одно на ученика, курс и ключ урока, общее для всех пространств;
занятия по уроку ссылаются на него. В нём — пункты целей агента
(`lessons[].objectives[].goals`) и цели урока со статусами, которые вычисляет
сервер.

| Что | Статусы | Как получается |
|---|---|---|
| Пункт | `open`, `done`, `planned`, `not_needed` | ставит агент; любой статус, кроме `open`, — со свидетельством; `not_needed` — только у необязательного пункта; вернуть в `open` можно |
| Цель урока | `not_started`, `touched`, `covered` | `covered` — все обязательные пункты цели в `done` или `planned`, `touched` — хоть один; цель без обязательных пунктов — `covered` сразу |
| Урок | `not_started`, `in_progress`, `covered`, `passed` | начат с первой отметки пункта не в `open` и обратно не «расначинается»; `covered` — начат и все цели разобраны; `passed` — урок закрыт (квиз сдан или квиза нет) и пересчётом не снимается |
| Глава | `not_started`, `in_progress`, `passed` | не хранится: `passed` — пройдены все уроки главы, `in_progress` — хоть один начат; считаются только уроки действующего релиза |

Отметка пункта — запись с предупреждением, а не отказ: пункт, отмеченный не по
порядку, пишется, а агент получает, что по цели ещё открыто, и следующий шаг —
первый открытый обязательный пункт урока по порядку релиза. Отказ — на ошибку
формы и на прохождение, которое отмечать нельзя (архивное — `run_archived`,
чужое занятие, урок не в релизе). Квиз и закрытие урока ждут, пока закрыты
все обязательные пункты: иначе — `goals_open` со списком.

**Сверка с действующим релизом — по ключам**, при обращении к прохождению и
фоном после публикации нового релиза. Новые пункты — `open`, новые цели —
`not_started`; исчезнувшие снимаются и в статусы не идут, но отметка остаётся:
вернувшийся ключ получает её обратно. Цель пункта, вид, обязательность,
название и порядок — из релиза. Урок исчез из релиза — прохождение читается,
но новое не заводится, пункт не отмечается и квиз не начинается
(`lesson_not_in_release`).

**Прохождение не видят ни ученик, ни руководитель** — ни чтением записи, ни
методами отчётности и интерфейса Learning: пункты и свидетельства —
инструмент агента и автора курса. Пункты со статусами отдают агентские
методы (`start_lesson` — карта урока, `lesson_item`, `mark_goal`, отказ
`goals_open`) и `goal_runs`; свидетельства — только `goal_runs`, инструктору
курса, модератору и администратору. Остальным наружу
уходят статусы целей, урока и главы: цели урока `[{key, text, status}]` —
`course_outline`, `lesson_session`, прогресс открытого занятия в `remember` и
`update_artifact`, `student_detail`; статус начатой цели — `course_map`.
Читающие методы (`course_outline`, `lesson_item`, `lesson_session`,
`course_map`, `student_detail`, прогресс в `remember` и `update_artifact`)
берут сохранённые статусы простым чтением: прохождений не заводят, не
сверяют и не блокируют; прохождения нет — цель `not_started`, пункт `open`.
Агент ходит токеном ученика, и ученик может позвать агентский метод сам —
это принято (решение владельца, learning-services#497). Сброс прогресса
архивирует прохождения курса, и урок проходится заново
(`reset_student_progress`).

**Урок закрывает только занятие** — сданная попытка квиза (`submit_answer`)
или `complete_lesson`. Методы Learning, которые закрывают урок, на уроке
курса из релиза отказывают — `ValidationError`, HTTP 417, — и отметка
пройденного (`LMS Course Progress`) не появляется и не меняется:
`lms.lms.api.mark_lesson_progress`, `save_progress` под любым именем, под
которым он виден по HTTP (`course_lesson.save_progress`,
`lms.lms.api.save_progress`, `lms_quiz.save_progress`), и с `scorm_details`
тоже, а сдача квиза Learning (`submit_quiz`) на таком уроке не сохраняется
вовсе. Мимо занятия отметку урока курса из релиза заводят и правят только
те, кому Desk даёт создавать и править отметки (права DocType). `Why:` по
отметке агент выбирает следующий урок, отчёт руководителя считает
пройденное, а Learning открывает следующий урок, выдаёт сертификат и
открывает следующий курс программы. Своим токеном ученик закрывал бы урок
вызовом Learning без занятия и квиза — а за ним и весь курс
(learning-services#525).

### Квиз урока из релиза

Вопросы, верные варианты, пояснения и порог — из `lessons[].quiz` релиза.

- **Снимок вопросов — в попытке.** Попытка снимает все вопросы урока
  действующего релиза — без верного варианта и пояснения — и порог урока;
  ответы сервер проверяет по релизу попытки. Ответ — `id` варианта в попытке
  или его текст, не место в списке и не ключ релиза.
- **Порядок и `id` вариантов — свои у каждой попытки.** Вопросы и варианты
  каждого вопроса новая попытка получает в случайном порядке, тексты — как в
  релизе, а `id` варианта — случайный, уникальный в вопросе. Снимок хранит
  варианты как `{id, text}`, без ключей релиза: ключ выбранного варианта
  сервер находит на ответе по его тексту — тексты вариантов вопроса различны
  (`duplicate_option_text` у публикации). Порядок и `id` снимаются в попытку
  на старте и держатся до её конца: незавершённую попытку `request_quiz`
  возвращает такой же, пояснения итога идут в её порядке и ссылаются на
  вопрос по `id`.
  `Why:` вопрос проверяет выбор по содержанию варианта, а не по его месту в
  списке или ключу в релизе. Ключей нет и в снимке: запись своей попытки
  ученик читает.
- **Новая версия курса переносит попытку, если квиз урока не изменился, иначе
  аннулирует.** Публикация сравнивает квиз урока каждой незавершённой попытки
  курса с квизом того же урока в новой версии: вопросы по ключам, их тексты,
  цели, варианты (ключи и тексты) и верный вариант; порядок вопросов и
  вариантов не в счёт — он у попытки свой. Совпало —
  попытка продолжается по новой версии: снимок и ответы прежние, пояснения —
  новой версии. Не совпало — попытка аннулируется (`Cancelled`, причина
  `quiz_changed`), урока в новой версии нет — тоже (`lesson_removed`).
  Попытку, которую публикация не застала (её начали в момент публикации),
  аннулирует без сравнения первый ответ в неё или старт квиза
  (`attempt_outdated`).
  Пояснения и порог в сравнение не входят: на вердикт они не влияют, а порог
  попытка несёт со старта. Ответы и журнал проверки аннулированной остаются.
  Аннулированная не идёт в лимит попыток и не даёт паузы перед повтором:
  `request_quiz` по тому же занятию сразу начинает новую попытку — с тем же
  номером. Ответ в аннулированную — отказ `quiz_attempt_cancelled`. Агент,
  не получавший такого отказа, узнаёт об аннулировании из поля
  `previous_attempt_cancelled` новой попытки, если это последняя попытка
  урока и `request_quiz` начал новую. Доставка — не больше одного раза:
  попытка отмечается сообщённой вместе с ответом, и если ответ до агента не
  дошёл, флаг не повторится.
  `Why:` аннуляция — следствие публикации автора, а не действия ученика;
  лимит и пауза защищают от перебора, которого здесь нет.
- **Зачёт:** `верных × 100 ≥ pass_percentage × всего`, порог — снятый в
  попытку на её старте. Лимит попыток, пауза и обязательность квиза — политика
  платформы; попытки считаются по ученику, курсу и ключу урока, аннулированные
  не в счёт.
- **Итог** — доля верных и `objective_results`: верных из всех по каждой цели
  урока. Сданная попытка закрывает урок (`passed`) и подтверждает квизом цели,
  все вопросы которых отвечены верно. «Подтверждено квизом» и статус цели по
  отметкам агента — два разных признака, ни один не выводится из другого.
- **Пояснение** к верному ответу приходит сразу; к неверному — только в итоге
  сданной попытки. Неверный ответ получает лишь `correct: false`, несданная
  попытка — остаток попыток и время пересдачи, без пояснений и верных
  вариантов. `Why:` пояснение к вопросу называет верный вариант, а попытка
  может быть не последней.
- **Ответы попытки** не читает никто, кроме служебных ролей, — ни руководитель,
  ни сам ученик: в записи ответа лежит признак верности. Руководитель видит
  итог попытки.

### Домашка урока из релиза

`lessons[].homework` — часть релиза; публикация переносит её в шаблон домашки
урока, и выдача, сроки и проверка куратором работают как у любой домашки.
Домашка ушла из релиза — шаблон без сдач удаляется, со сдачами снимается:
ученикам без сдачи он не выдаётся и не сдаётся, а выданную домашку ученик
сдаёт и куратор проверяет. Вернулась — снова действует тот же шаблон.

# Методы авторинга

Всё, что ниже, требует одной из авторских ролей: `Course Creator`,
`Moderator`, `System Manager` или `Administrator`. Исключение — роль
`Release Publisher` служебной учётки конвейера курсов: ей открыты только
`publish_release`, `list_courses` и `course_releases`. Вызов без нужной роли
отклоняется **403** (гостя — **401**: сначала вход), а не кодом отказа: у
агента ученика нет сценария, в котором он что-то с этим сделает, и нарушение
доступа должно попадать в журнал Frappe как нарушение.

Из методов эталоны ответов отдаются только здесь и только этим ролям; те же
роли читают релиз курса с эталонами в Desk и через `/api/resource` (раздел
«Кто что видит»). Правило «эталон не выходит наружу» остаётся дословным для
всех методов ученика.

**Объект, которого нет, — доменный отказ, а не 404.** Каждый метод сначала
проверяет, что переданное существует, и отвечает кодом по виду объекта —
`course_not_found`, `lesson_not_found` — с полем `id`. `Why:` агент куратора
работает с идентификаторами, полученными из прошлых ответов, и опечатка в
ссылке — его обычная ошибка, а не нарушение доступа: она должна приходить кодом, по
которому он переспросит, а не HTTP-ошибкой.

**Курс правится только релизом** (learning-services#500). Курс компилируется
вне платформы и публикуется целиком (`publish_release`): программу, директивы,
квиз, домашки и документ курса даёт релиз. Правка мимо релиза — карточки
анонса (`update_course`) и целей анонса (`objectives` у `announce_course`) —
на курсе с действующим релизом отказывает `course_from_release` (с
`course`): правка разошлась бы с релизом и пропала бы на следующей
публикации.

Главы, уроки и порядок глав курса из релиза не правятся и в Desk, и в
редакторе Learning (learning-services#512): ни правкой, ни удалением, ни
переименованием, ни вставкой и удалением строк оглавления. Там отказ приходит не кодом
контракта, а HTTP 417 с текстом «Курс собран из релиза: главы и уроки правит
новый релиз». Карточка курса и признак публикации в Desk и редакторе
Learning правятся без этого запрета. Курс из
релиза здесь — курс с ключом релиза; на практике это курс с действующим
релизом: ключ и действующий релиз ставит одна публикация, и порознь они
бывают только внутри удаления курса.

Шаблоны домашек (`Agent Lesson Homework`) и схемы документа
(`Agent Course Artifact`) у курса из релиза пишет только публикация
(learning-services#526): правка, удаление, переименование схемы, вставка,
правка и удаление её строк в Desk и через `/api/resource` отклоняются
HTTP 417 с текстом «Курс собран из релиза: домашки и документ курса правит
новый релиз». У курса без релиза их правят `Moderator` и `System Manager`.
`Course Creator` их только читает — у любого курса.

Заметки автора (`Agent Author Note`) и репорты (`Agent Course Report`)
`Course Creator` пишет только методами ниже (learning-services#528): в Desk и
через `/api/resource` он их только читает. Строку нити заметки
(`Agent Note Reply`) отдельно от заметки не вставить, не править и не удалить
никому; через сохранение заметки нить меняется по правам на заметку и под её
проверками. `Moderator` и `System Manager` правят заметки и репорты и в Desk,
но правила методов держит сама запись: у заметки не меняются курс, релиз,
место в курсе (`lesson_key`, `target`) и `via`, у репорта — поля, которые
ставит `report_issue`; статус идёт по переходам `set_note_status` и
`resolve_report`, переоткрытый репорт теряет прежний итог, `fixed` и
`rejected` не остаются без ответа, а оригинал дубля — репорт того же курса.
Отказ — HTTP 417 с текстом.
`Why:` ученик видит в `my_reports` репорты своих занятий и ответ оригинала
дубля: репорт, переставленный на чужое занятие, или оригинал из чужого курса
показали бы ему чужой текст и ответ.

## `lms_frappe_app.api.authoring.course_reports`

Репорты агентов по курсу: что мешает курсу работать.

**Параметры:** `course`; необязательные `kind` (вид репорта), `lesson` —
ключ урока, `limit` (не больше 50, оно же по умолчанию), `status` — `new`,
`in_progress`, `fixed`, `rejected`, `duplicate` или `open` (`new` и
`in_progress` вместе). Урок ищется по ключу на записи урока Learning (раздел
«Релиз курса»): находятся и репорты урока, снятого из действующего релиза;
урока с таким ключом в курсе нет — список пуст.

```json
{ "ok": true, "data": { "course": "p3-express", "reports": [
  { "id": "ACR-00004", "kind": "directive_mismatch", "lesson": "0004-urok",
    "lesson_key": "l-4", "objective": null, "question_key": "S1/l-4-D1",
    "text": "Много вопросов подряд без вводного объяснения",
    "reported_at": "2026-09-20T19:50:39", "release": "REL-00007",
    "status": "fixed", "resolution": "Добавили вводное объяснение перед вопросами",
    "resolved_at": "2026-09-21T11:05:00" } ] } }
```

**Кто пожаловался, не отдаётся.** Куратору нужно, что не так с курсом, а не
кто сказал: имя в выдаче превращает обратную связь в донос и отучает
жаловаться. Занятие и ученик остаются в самой записи — сотрудник платформы
разберётся, если дойдёт до разбирательства.

Свежие сверху. `lesson` — запись `Course Lesson`, `lesson_key` — ключ на этой
записи (раздел «Релиз курса»): в репорте он не хранится и читается вместе с
репортом. `objective` и `question_key` заполнены, когда репорт был про
конкретную цель или вопрос квиза: `question_key` — ключ вопроса урока в
релизе. `release` — действующий релиз курса на момент жалобы; у репорта,
заведённого до релиза курса, `release` — `null`, `lesson_key` — тоже, если у
записи урока нет ключа.
`resolution` — ответ ученику, `resolved_at` — когда репорт получил итог; оба
`null`, пока их нет.

**Отказы:** `course_not_found`, `unknown_report_kind` (с `kind`) — с
перечнем видов в сообщении; `unknown_report_status` (с `status`).

## `lms_frappe_app.api.authoring.resolve_report`

Сменить статус репорта и ответить ученику.

**Параметры:** `report`, `status`; необязательные `resolution` — ответ,
который увидит ученик, и `duplicate_of` — репорт, дублем которого признан
этот. Только `POST`.

| Было | Можно перевести в |
|---|---|
| `new`, `in_progress` | любой другой статус |
| `fixed`, `rejected`, `duplicate` | только `in_progress` — переоткрыть |

`fixed` и `rejected` требуют непустой `resolution`; `duplicate` — `duplicate_of`
того же курса, не сам репорт. `resolution` пишется заново при каждой смене
статуса: не передан — ответа нет, и переоткрытый репорт не выдаёт ученику
прежний итог за действующий. `duplicate_of` хранится только у дубля.

```json
{ "ok": true, "data": { "id": "ACR-00004", "status": "fixed",
  "resolution": "Добавили вводное объяснение перед вопросами",
  "resolved_at": "2026-09-21T11:05:00", "duplicate_of": null } }
```

`resolved_at` ставится при переходе в `fixed`, `rejected` или `duplicate` и
снимается при переоткрытии. Итог ученик получит в `my_reports` и один раз — в
`closed_reports` у `start_lesson` на ближайшем занятии курса; после
переоткрытия новый итог придёт снова.

`Why:` закрытый репорт меняет итог только через переоткрытие: итог уже ушёл
ученику, и молча заменить его другим значило бы переписать то, что он прочёл.

**Отказы:** `report_not_found` (с `id`); `unknown_report_status` (с `status`);
`invalid_report_transition` (с `status` — текущим — и `allowed`);
`report_resolution_required` (с `status`) — `fixed` или `rejected` без ответа;
`duplicate_of_required`; `invalid_duplicate_of` (с `duplicate_of`) — такого
репорта нет, он из другого курса или это сам репорт.

## Схема документа курса

Документ, который ученик собирает по ходу курса, задаётся схемой из блоков.
Пишет её публикация релиза (`publish_release`) по `document` релиза (раздел
«Релиз курса»):

- раздел — блок с теми же ключом, названием, описанием, `rows` и колонками
  (`key`, `title`, `required`), как их отдаёт `artifact`;
- блок показывается на уроке, который первым пишет в раздел (`lesson`) —
  подсказка, а не ограничение;
- раздел `rows: one` заполняется один раз — колонки раздела его поля, `rows:
  many` ведётся строками. Клетки и поля — текст; `required: true` —
  обязательно, `{"if_column": "<колонка>"}` — обязательно, когда та колонка
  непуста: у строки — в той же строке, у раздела `one` — его поле.

Порядок блоков — порядок разделов: ученик видит их в нём же. Действующая
схема одна на пару «курс + ключ документа». Тот же документ в новом релизе —
та же версия схемы; изменённый — новая версия, она снимает прежнюю с
действия; документ ушёл из релиза или сменил ключ — его схема перестаёт
действовать. Записанное учеником хранится по ключам разделов и колонок и
правку схемы переживает: добавленный блок появится пустым, убранный исчезнет
со страницы, не стирая написанного.

Ключ поля раздела `one` уникален в документе: не совпадает ни с полем другого
раздела `one`, ни с колонкой раздела `many` — иначе релиз не проходит,
проблема `document_key`. `Why:` поля всех разделов `one` у ученика лежат одним
словарём.

(`lesson`) их нет.

агента как в релизе: рамка курса (`frame`, `learn_about_student` — те, что
есть) и срез урока (`lesson`, `{}` — среза нет); их форму задаёт компилятор
курса. Без `lesson` пакета агента в ответе нет.

действующего релиза (`course`); `lesson_not_in_release` — урока с таким
ключом нет в действующем релизе (`course`, `lesson_key`, `release`), как у
методов ученика.

## `lms_frappe_app.api.authoring.course_releases`

История релизов курса (learning-services#512).

**Параметры:** `course`.

```json
{ "ok": true, "data": { "course": "primer-kursa", "releases": [
  { "release": "REL-00007", "version": 3,
    "published_at": "2026-10-08T12:20:00.118204",
    "published_by": "curator-a@example.com",
    "digest": "9f2c…64 hex", "commit": "3e7a1c0d…40 hex",
    "document_key": "notebook", "active": true,
    "findings_count": 1, "changes": { "against": 2, "count": 2, "truncated": false } },
  { "release": "REL-00005", "version": 2,
    "published_at": "2026-10-01T09:00:00.000000",
    "published_by": "curator-b@example.com",
    "digest": "1ab4…", "commit": null,
    "document_key": "notebook", "active": false,
    "findings_count": null, "changes": null } ] } }
```

Свежие вперёд — по версии. `digest` — sha256 канонического JSON релиза: тот
же файл — тот же дайджест. `commit` — коммит git, из которого версия впервые
опубликована (`publish_release`, `commit`); `null` — публикатор его не
передал. Содержимое прежней версии сервер не хранит: оно — в git по этому
коммиту, а у версии без коммита кандидата из истории источника проверяет
`digest` — пересобрать тем же компилятором и с той же нормализацией, что и
версию, и сравнить. `document_key` —
ключ документа релиза, `null` — документа нет. `active` — действующий релиз
курса. `findings_count` — сколько находок проверки карты публикатор передал с
версией; `changes` — изменения против действующей версии числом:
`against` — с какой версией сравнивали (`null` — сравнения не было),
`count` — путей, `truncated` — список обрезан публикатором. `null` — не
переданы (`publish_release`). Сами находки и пути действующей версии отдаёт
`course_release`; у прежних версий остаются и они — освобождение их не
трогает. У курса без релиза `releases` пуст.

**Отказы:** `course_not_found`.

## `lms_frappe_app.api.authoring.goal_runs`

Прохождения уроков курса учениками — только чтение (learning-services#512):
статусы урока, целей и пунктов, свидетельства отметок и когда они сделаны.

**Параметры:** `course`; необязательные `lesson` — ключ урока, `start` —
смещение (целое от 0, по умолчанию 0), `limit` — размер страницы (целое от 1;
больше 20 — 20, оно же по умолчанию). Ключ урока ищется в самих
прохождениях: находятся и прохождения урока, снятого из действующего релиза;
ключа нет ни в одном — список пуст.

**Кто читает:** инструктор курса (`LMS Course.instructors`), `Moderator`,
`System Manager`, `Administrator` — модератор как в Learning, плюс
администраторы платформы. Прочие авторские роли, в том числе `Course
Creator`, который курс не ведёт, — **403**; гость — **401**.

```json
{ "ok": true, "data": { "course": "primer-kursa", "lesson": null,
  "start": 0, "limit": 20, "has_more": false, "runs": [
  { "student": { "id": "anna@example.com", "name": "Анна Петрова" },
    "lesson": { "key": "l-1", "title": "Урок первый" },
    "status": "in_progress",
    "accepted_at": "2026-10-01T10:00:02.413120",
    "started_at": "2026-10-01T10:04:11.209554",
    "passed_at": null,
    "resume_from": "С выбора варианта",
    "objectives": [
      { "objective_key": "l-1-D1", "status": "touched",
        "quiz_confirmed": false, "removed": false },
      { "objective_key": "l-1-D2", "status": "not_started",
        "quiz_confirmed": false, "removed": true } ],
    "goals": [
      { "objective_key": "l-1-D1", "goal_key": "term:T1",
        "title": "Термин «пример»", "status": "done",
        "evidence": "Назвал термин своими словами",
        "marked_at": "2026-10-01T10:04:11.209554",
        "session": "sess-01H…", "removed": false },
      { "objective_key": "l-1-D1", "goal_key": "l-1-D1/V1",
        "title": "Выбор: «первый»", "status": "open", "evidence": null,
        "marked_at": null, "session": null, "removed": false } ] } ] } }
```

Прохождение — одно на ученика и ключ урока («Прохождение урока»).
Архивные прохождения — после сброса прогресса — не отдаются. Прохождения
читаются как сохранены: метод их не заводит, не сверяет с действующим
релизом и не блокирует.

`student.id` — пользователь, `student.name` — его полное имя (`null` — имени
нет). `lesson.title` — название урока в действующем релизе, у урока, снятого
из релиза, — в последнем релизе, где он был; у прохождения без записи урока
Learning — `null`. Статусы и поля урока, целей и пунктов — как в разделе
«Прохождение урока»: `accepted_at` — первый старт урока, `started_at` —
первая отметка пункта не в `open`, `passed_at` — зачёт, `resume_from` —
заметка «с чего продолжить», `quiz_confirmed` — цель подтверждена квизом.
Пункт: `evidence` — свидетельство последней отметки (`null` у `open`:
возврат в `open` его стирает), `marked_at` и `session` — когда и в каком
занятии она сделана; пункт не отмечали — `null`. `removed` — цели или пункта
нет в релизе прохождения; отметка остаётся.

Порядок — свежее начало сверху: по `started_at` по убыванию, не начатые — в
конце, свежие заведённые среди них — выше. Цели и пункты — по порядку релиза
прохождения, снятые — в конце. `has_more` — есть следующая страница: её
`start` — `start` + число прохождений на этой.

**Отказы:** `course_not_found` (с `id`); `course_not_released` (с `course`) —
у курса нет релиза: прохождения ведутся только по урокам релиза;
`invalid_page` (с `where` — `start` или `limit` — и `value`) — не целое или
меньше допустимого.

  | `agent.frame` | рамка пакета агента (`frame`, `learn_about_student`) |
  | `agent.lesson.<ключ>` | срез пакета агента для урока |
  | `agent.item.<урок>/<пункт>` | подробности пункта в срезе урока (`items`) |
  | `map.<узел>` | узел карты курса |

  Ключ пишется как в релизе: ключи с `/` и `.` допустимы, `<урок>/<пункт>`
  делится по ключам уроков релиза. Узел карты — объект с непустым `text`,
  `title` или `when` (ловушка варианта) под своим ключом на любой глубине
  `map`.
- `quote` — выделенный текст, необязательный.
- `via` — кто пишет: `author` (по умолчанию) или `agent`. Признак для
  очереди, а не защита: писать могут только авторские роли.

Заметка помнит релиз, к которому написана (действующий на момент записи), и
ключ урока места.

```json
{ "ok": true, "data": { "id": "AAN-00012", "course": "course-basics",
  "target": "goal.l-1/term:T1", "release": "REL-00007", "version": 3,
  "lesson_key": "l-1", "label": "Урок 1 «Урок первый» · пункт «Термин «пример»»",
  "missing": false, "status": "open", "waiting_on": "agent" } }
```

`release` и `version` — релиз заметки и его версия; `lesson_key` — ключ урока
места, его хранит заметка; у мест вне урока (`course`, `chapter`, `section`,
`agent.frame`, `map`) — `null`; `label` — место словами по действующему
релизу; `missing` — места нет в действующем релизе (у новой заметки всегда
`false`).

**Отказы:** `course_not_found`; `course_not_released` (с `course`) — у курса
нет действующего релиза; `invalid_target` (`where: target`) — адрес не по
форме таблицы; `note_target_unknown` (с `target` и `release`) — адрес по
форме, а места с таким ключом в действующем релизе нет; `invalid_note` с
`where` — пустой `text` или неизвестный `via`.

## `lms_frappe_app.api.authoring.list_notes`

Заметки курса с нитью ответов, старые сверху.

**Параметры:** `course`; необязательные `status` (`open`, `done`, `accepted`)
и `lesson` — ключ урока: заметки мест этого урока (урок, его цели, пункты,
вопросы, срез пакета и его пункты) по ключу, который хранит заметка:
находятся и заметки урока, снятого из действующего релиза; заметок с таким
ключом нет — список пуст.

```json
{ "ok": true, "data": { "course": "course-basics", "notes": [
  { "id": "AAN-00012", "target": "goal.l-1/term:T1",
    "release": "REL-00007", "version": 3, "lesson_key": "l-1",
    "label": "Урок 1 «Урок первый» · пункт «Термин «пример»»",
    "missing": false, "quote": "Термин без примера",
    "text": "Дай пример из работы склада", "via": "author",
    "author": "curator@example.com", "author_name": "Куратор",
    "status": "done", "waiting_on": "author",
    "created_at": "2026-10-08T15:40:02.118305", "updated_at": "2026-10-08T15:52:40.004411",
    "replies": [ { "via": "agent", "author": "curator@example.com",
      "author_name": "Куратор", "text": "Добавил пример склада, релиз v4",
      "created_at": "2026-10-08T15:52:40.001037" } ] } ] } }
```

Поля места — как у `add_note`. `label` и `missing` — по действующему
релизу: `missing: true` — ключа места в нём нет (урок снят, пункт убран,
раздела нет в документе, узла — в карте); подпись тогда — вид места и ключ,
например `Урок l-3`. `release` и `version` — релиз, к которому заметка
написана, а не действующий; `lesson_key` — сохранённый в заметке: у места,
которого больше нет, он тот же, что при записи. Заметка без `release` —
архив, места у неё нет: `target` — адрес как есть, `label` — он же,
`version` — `null`, `missing` — `true`. Так же отдаётся заметка, чей адрес не
разбирается.
`waiting_on` — чей ход: `done` ждёт автора; открытая — того, кто не сказал
последнего слова: вопрос агента ждёт автора, заметка автора — агента; у
принятой — `null`.

**Отказы:** `course_not_found`; `invalid_note` с `where: status`. Курс без
релиза отказом не отвечает: его заметки — архив прежних мест.

Курс Learning без релиза, у которого есть заметки автора, удалением Learning
не удаляется (`LinkExistsError`): заметки ссылаются на курс.

## `lms_frappe_app.api.authoring.publish_release`

Публикует релиз курса целиком — новой версией. Только `POST`.

**Параметры:** `release` — релиз (объект или строка JSON), формат — раздел
«Релиз курса»; `course` (необязательно) — курс без уроков (анонс), к которому
привязать первый релиз. Без `course` курс ищется по `release.course.key`; нет
такого — заводится черновиком. `instructors` (необязательно) — почты или имена
пользователей (список или строка JSON со списком):

- список **заменяет** инструкторов курса; вызвавший, если его нет в списке,
  инструктором не становится;
- не передан — инструкторы не трогаются; новый курс получает инструктором
  вызвавшего, а у вызвавшего без авторской роли (`Release Publisher`) — отказ
  `instructors_empty`: публикатор курс не ведёт;
- проверяется до первой записи: пустой — `instructors_empty`, нет действующей
  учётной записи — `instructor_not_found`, нет авторской роли (Course
  Creator, Moderator, System Manager или Administrator — те же, что пускают
  к методам авторинга) — `instructor_not_author`. Публикатору оба случая —
  один отказ `instructor_not_found` без `users`: пользователи и их роли ему
  закрыты;
- применяется и к неизменному релизу (`unchanged`): в дайджест релиза
  инструкторы не входят, смена кураторов новой версии не требует.

`commit` (необязательно) — коммит git, из которого собран релиз: полный хеш,
40 или 64 знака `0-9a-f` в нижнем регистре, как его печатает `git rev-parse
HEAD`:

- пишется в новую версию; иное значение — отказ `invalid_commit` до первой
  записи;
- в дайджест релиза не входит: тот же релиз из другого коммита —
  `unchanged`, и у версии остаётся коммит её первой публикации;
- версия, впервые опубликованная без `commit`, так и остаётся без него:
  запись релиза неизменяема, и повтор с `commit` её не дополняет;
- не передан — версия без коммита: у публикатора git может не быть.

`findings` (необязательно) — находки проверки карты на момент публикации
(список или строка JSON со списком), не больше 500:
`{"code", "severity", "target", "message"}` — `code`, `severity`, `message`
— непустые строки (`message` — до 1000 знаков, код и уровень — до 200),
`target` — ключ узла карты или урока (до 200 знаков); пусто или `null` —
находка без цели. `changes` (необязательно) — отличия релиза от действующей
версии (объект или строка JSON): `against` — номер версии, с которой
сравнивали, `null` — сравнения не было, и тогда путей нет; `paths` — не
больше 2000 `{"op", "path"}`, `op` — `+`, `-` или `~`, `path` — непустой путь
до 1000 знаков; `truncated` (необязательно) — путей было больше, список
обрезан. Других полей нет. Оба поля:

- проверяются до первой записи: форма не та — отказ
  `release_findings_invalid` с `where` — путь до неверного поля
  (`findings[3].message`, `changes.paths[0].op`) — и сообщением, что не так;
- пишутся в новую версию как есть (`course_release`, `course_releases`); в
  дайджест не входят, на ответ публикации и прежние версии не влияют;
- на `unchanged` `changes` не пишутся, а `findings` дописываются действующей
  версии, только если у неё их нет (`null`): переданные однажды находки не
  переписываются.

```json
{ "release": { "format": "lms-release/1", "course": { "key": "sample-course", "…": "…" }, "…": "…" },
  "instructors": [ "curator-a@example.com", "curator-b@example.com" ],
  "commit": "3e7a1c0d9b2f4e6a8c1d3f5b7e9a0c2d4f6b8e1a",
  "findings": [ { "code": "quiz_echo", "severity": "attention", "target": "l-1-S2",
                  "message": "Ситуация зачёта повторяет ситуацию практики." } ],
  "changes": { "against": 2, "paths": [ { "op": "~", "path": "agent.lessons.l-1.directive" } ] } }
```

```json
{ "ok": true, "data": { "course": "primer-kursa", "course_key": "sample-course",
  "release": "REL-00007", "version": 3,
  "commit": "3e7a1c0d9b2f4e6a8c1d3f5b7e9a0c2d4f6b8e1a",
  "unchanged": false, "course_created": false, "published": true,
  "chapters": { "created": [], "updated": ["ch-1"], "removed": [], "restored": [] },
  "lessons": { "created": ["l-4"], "updated": ["l-1"], "removed": ["l-3"], "restored": ["l-2"] },
  "document": { "artifact": "notebook", "version": 4 },
  "instructors": [ "curator-a@example.com", "curator-b@example.com" ],
  "warnings": [ { "code": "public_text_empty", "where": "chapters[ch-2].description" } ] } }
```

`chapters` и `lessons` — ключи созданных, изменённых и снятых из программы
узлов; `restored` — вернувшихся в программу: их не было в прежнем релизе, и
они получили свою прежнюю запись, оставленную по ссылкам (могут быть и в
`updated`); вернувшийся ключ, чью запись публикация удалила, — в `created`. `document` — ключ и версия действующей схемы документа курса; у
релиза без документа — `null`. `commit` — коммит версии `version`: при
`unchanged` — коммит её первой публикации, а не переданный; `null` — версия
опубликована без коммита. Ключ есть в каждом ответе. `instructors` —
инструкторы курса после публикации, и при `unchanged` тоже. `warnings` — то, что публикации не мешает:
`public_text_empty` (пустой текст ученику; на месте пустой карточки курса —
его название), `explanation_missing`, `course_card_markup` —
`<` или `>` в названии или карточке курса: в ней чистится HTML, и разметка
может быть вырезана, а `<` — прийти как `&lt;` (`where`, `chars`).

Тот же релиз ещё раз — `unchanged: true`, версия прежняя, релиз не пишется;
переданные `instructors` применяются: повтор вызова после обрыва связи не
плодит версий. Признак «опубликован» не
меняется: новый курс — черновик, новый релиз опубликованного курса действует
сразу. Открывает курс из релиза `publish_course`: его готовность проверена
при публикации релиза. Незавершённые попытки квиза курса новая версия
переносит или аннулирует (см. «Квиз урока из релиза»); `unchanged` их не
трогает. Содержимое прежних версий новая версия освобождает (раздел
«Релиз курса»); `unchanged` его не трогает. Всё или ничего: отказ на любом
шаге оставляет курс, попытки и прежние версии как были.

**Отказы:** `release_invalid` — релиз не JSON, не объект, несёт `NaN` или
бесконечность в любой части (и в `agent`, `map`) или не проходит схему
(`errors` — до 20 расхождений `{path, message}`, `total`);
`release_format_unsupported` (`format`, `supported`); `release_inconsistent`
(`problems` — до 20 `{code, where, …}`: `duplicate_key`, `broken_ref` (и
ключ пакета агента не из публичной части: `where` — `agent.lessons`,
`agent.lessons.<урок>.items` или `agent.lessons.<урок>.sections`, `key` —
лишний ключ), `chapter_order`, `quiz_correct`, `duplicate_option_text` — тексты
вариантов вопроса совпадают без учёта регистра и пробелов (`where` —
`questions[<вопрос>].options`), `document_key`, `text_too_long`,
`title_forbidden_chars` — `<` или `>` в названии главы, урока, домашки или
документа (`chars` — какие из них), `agent_leak` — ключ `answers` или `correct` в пакете агента,
`where` — путь до него, например `agent.lessons.l-1.answers`; схемы уроков
(`releases.diagrams`, `where` — `agent.lessons.<урок>.diagrams[<ключ>]`,
`key`): `diagram_shape` — `diagrams` не список записей, ключ схемы не
`^[a-z0-9][a-z0-9-]{0,63}$` (`where` — `agent.lessons.<урок>.diagrams`,
`index` — номер записи), поле не строка или лишнее; `duplicate_key` —
ключ повторяется в уроке; `diagram_no_title`, `diagram_no_description`,
`text_too_long` — название длиннее 140 знаков (`limit`, `length`), `diagram_empty`,
`diagram_too_large` — HTML больше 100 000 байт (`limit`), `diagram_external` —
HTML зависит от сети: внешний адрес в атрибуте или `url()`, `@import`,
`<iframe>`, `<base>`, запрос из скрипта (`found`); `total`);
`course_not_found` (`id`); `course_key_mismatch` — у переданного курса другой
ключ (`course`, `course_key`, `release_key`); `course_key_taken` — ключ
релиза уже у другого курса или его курс сейчас заводит другая публикация,
повтор вызова найдёт курс (`release_key`; `course` — курс с этим ключом,
`null`, если он ещё не виден); `course_has_content` — у переданного курса
без ключа есть уроки (`course`, `lessons`); `course_keys_missing` — у глав
или уроков действующего релиза курса нет ключа на записи Learning: сайт не
прошёл миграцию, и публикация завела бы их заново (`course`; `chapters`,
`lessons` — сколько таких записей), проверяется после `unchanged`;
`instructors_empty`; `instructor_not_found`, `instructor_not_author`
(`users` — кто не прошёл); `invalid_commit` — `commit` не полный хеш git в
нижнем регистре; `release_findings_invalid` — `findings` или `changes` не
по форме (`where`); `busy` — курс, попытку квиза курса, его главу или урок в
этот момент меняет другой запрос (ответ ученика, другая публикация), и база
ответила взаимоблокировкой или таймаутом ожидания блокировки: публикация
откатилась целиком, повторите вызов.

Тело запроса больше `max_file_size` сайта Frappe (по умолчанию 25 МБ)
отвергает Frappe до метода — HTTP 413, без кода контракта.

## `lms_frappe_app.api.authoring.publish_course`

Открывает ученикам курс с действующим релизом.

**Параметры:** `course`.

```json
{ "ok": true, "data": { "id": "course-basics", "published": true,
                        "warnings": [ { "code": "public_text_empty",
                                        "where": "chapters[ch-2].description" } ],
                        "notified": 0 } }
```

Релиз проверен целиком при публикации (`publish_release`); `warnings` —
предупреждения проверок действующего релиза по его снимку, те же, что вернула
его публикация. Публикация анонса открывает его для записи. Тем, кто просил
сообщить о выходе, уходит письмо, один раз; `notified` — сколько писем ушло.

**Отказы:** `course_not_found`; `course_not_released` — у курса нет
действующего релиза (`course`).

## `lms_frappe_app.api.authoring.announce_course`

Показывает курс в каталоге как анонс (learning-services#389): записаться
нельзя, можно попросить сообщить о выходе. Только `POST`.

**Параметры:** `course`; `objectives` (необязательно) — цели анонса: список
строк или текст по строке на цель.

```json
{ "ok": true, "data": { "id": "ops-junctions", "published": true, "upcoming": true,
  "objectives": [ "Описать процесс в пять колонок",
                  "Найти стыки между отделами" ] } }
```

Готовности анонс не требует: курс без релиза анонсируется без уроков. Требует целей курса:
у анонса наружу выходят только они (`objectives` в каталоге и на
`course_map`). У курса без релиза `objectives` пишутся в курс и заменяют
прежние; не переданы — действуют записанные раньше. У курса из релиза цели —
названия глав действующего релиза по порядку, `objectives` к нему не
передаются. Открывает анонс `publish_course` после первого релиза, снимает —
`unpublish_course`.

**Отказы:** `course_not_found`; `course_objectives_missing` — у курса нет
целей; `course_from_release` — `objectives` переданы курсу из релиза;
`course_has_content` — у курса без релиза есть уроки (`course`, `lessons`):
программу курсу даёт релиз; `course_already_published` — курс уже открыт
ученикам.

## `lms_frappe_app.api.authoring.unpublish_course`

Снимает курс с публикации — и анонс тоже.

**Параметры:** `course`.

```json
{ "ok": true, "data": { "id": "course-basics", "published": false } }
```

Прогресс учеников снятие не трогает: зачисления и записи прогресса остаются,

**Отказы:** `course_not_found`.

**Отказы:** `course_not_found`.

## `lms_frappe_app.api.authoring.add_testers`

Записывает тестерами курса людей с учётной записью на платформе. Зовёт
кабинет автора, в MCP не выставляется. Только `POST`.

**Параметры:** `course`, `users` — список адресов или текст, где они
разделены запятыми, пробелами или переводами строк.

```json
{ "ok": true, "data": { "course": "ops-junctions",
  "added": [ { "user": "anna@example.com", "notified": true } ],
  "skipped": [ { "user": "ivan@example.com", "reason": "user_not_found" } ],
  "testers": [ { "user": "anna@example.com", "name": "Анна Петрова",
                 "progress": 0, "since": "2026-09-29" } ] } }
```

Каждому записанному уходит приглашение со ссылкой на курс; `notified: false` —
почта не настроена, и сообщить надо самому. `reason` у пропущенного:
`user_not_found` — учётной записи нет или она отключена, `already_tester`,
`already_enrolled` — человек уже учится на курсе, и тестером его не делаем.

**Отказы:** `course_not_found`, `users_required` — ни одного адреса.

## `lms_frappe_app.api.authoring.remove_tester`

Закрывает тестеру доступ тем же сбросом, что `reset_student_progress`:
занятия, попытки квиза и документ уходят в архив, запись удаляется. Зовёт
кабинет автора, в MCP не выставляется. Только `POST`.

**Параметры:** `course`, `user`.

```json
{ "ok": true, "data": { "course": "ops-junctions", "user": "anna@example.com",
  "testers": [] } }
```

**Отказы:** `course_not_found`, `tester_not_found` — человек не тестер курса.

## Метки времени

Приходят **без указания зоны**, в часовом поясе сайта Frappe. Трактовать их
как UTC нельзя: разойдётся на смещение сервера.

Исключение — `retry_after` (итог проваленной попытки в `submit_answer`, отказ
`retry_too_soon`): он приходит со смещением пояса сайта. Этот момент агент
называет ученику, и строка без пояса читалась как UTC.

## Версионирование

Пока нет внешних потребителей, контракт меняется вместе с реализацией и
описывает текущее состояние. Появится первый сторонний клиент — версия
переедет в путь метода.

## Чего в контракте нет

- **Административных операций платформы** — выдача ролей Frappe, отметка
  `verified` у организации и настройки делаются в Desk. Организации, состав
  команды и назначения курсов заводят методы команды.
