# REST-контракт приложения

Единственный канал наружу: всё, что приложение отдаёт и принимает, перечислено
здесь. Потребитель на платформе MCP-LMS — MCP-сервис, живущий отдельным
процессом; любой другой клиент разговаривает с приложением теми же методами.

Описание живёт рядом с реализацией — в одном репозитории с `api/`. `Why:`
описание в соседнем репозитории отстаёт молча: дрейф возникает в PR этого
приложения, и ловиться должен здесь же.

Держат его ворота `lms_frappe_app/api/test_contract.py`: раздел на каждый
whitelisted-метод и ни одного лишнего, а ключи примера ответа сверяются с
настоящим ответом метода на фикстуре. Параметры и списки отказов ворота не
проверяют — они остаются на ревью.

**Статус:** описывает текущее состояние `lms_frappe_app/api/`, покрыто тестами.

## Зачем контракт именно такой

Граница между AGPL-частью и закрытой проходит по этому интерфейсу. Чтобы она
держалась, контракт обязан оставаться **интерфейсом общего назначения, который
в принципе мог бы реализовать другой backend**. Отсюда три правила, которые
здесь не обсуждаются:

1. **Никаких структур Frappe наружу.** Ни `doctype`, ни `owner`, ни
   `modified_by`, ни `docstatus`. Идентификатор записи называется `id`, а не
   `name`. Исключение по имени, не по смыслу: `owner` у таблицы документа
   (`artifact`, `tables`) — ключ блока, который её заводит, а не пользователь.
2. **Никакого сырого REST к DocType.** Только перечисленные методы. Универсальный
   `query_doctype` не появится: агент начнёт изобретать сценарии в обход
   педагогики и прав.
3. **Никаких эталонов ответов.** См. раздел «Запрещённые поля».

## Транспорт

```
POST {frappe_url}/api/method/{method}
Authorization: Bearer {access_token ученика}
Content-Type: application/json
```

MCP-клиент зовёт методы только `POST`, поэтому метод принимает `POST`.
Исключение — метод, которого зовёт страница, а не агент: он бывает только
`GET`, и тогда это сказано в его разделе. Метод без `POST` и без такой
пометки валит ворота в `test_contract.py`. `Why:` на неподходящий глагол
Frappe отвечает `403`, и агент передаёт его как «нет доступа к этим данным» —
так `course_reports` не работал через MCP (learning-services#281).

Токен — личный токен пользователя, полученный по OAuth. Именно поэтому
проверки прав не дублируются в MCP-сервисе: Frappe применяет роли и
`permission_query_conditions` сам, и ученик не увидит курс, на который не
зачислен, даже если его агент попросит напрямую.

Сервисная роль `Agent Service` используется только там, где действие исходит
не от ученика.

## Формат ответа

Frappe заворачивает результат whitelisted-метода в поле `message`. Успех:

```json
{ "message": { "ok": true, "data": { } } }
```

**Ожидаемый доменный отказ** — тоже HTTP 200, с машинным кодом:

```json
{ "message": { "ok": false, "error": { "code": "quiz_attempts_exhausted",
                                        "message": "Попытки исчерпаны до 14:30",
                                        "retry_after": "2026-09-01T14:30:00+03:00" } } }
```

`Why:` доменные отказы не могут ехать HTTP-ошибкой. Тело ошибки Frappe
формирует фреймворк: в API v1 туда попадают `exc_type` и `exception`, причём
`exception` кладётся **только когда разрешён traceback** — в проде его нет, и
машинного кода отказа в ответе не остаётся. Агенту нужен предсказуемый код, а
не текст исключения.

**Ошибка уровня фреймворка** приходит HTTP-статусом; тело разбирать не следует:

| Статус | Когда | Что делает MCP-сервис |
|---|---|---|
| 401 | токен истёк или отозван между интроспекцией и вызовом | «требуется повторная авторизация» |
| 403 | нет прав на уровне Frappe | «нет доступа к этим данным» |
| 404 | объекта нет | «запрошенного объекта не существует» |
| 417 | `ValidationError` — нарушение инварианта | «сервис отклонил запрос как некорректный» |
| 429 | rate limit | «слишком много запросов, попробуйте позже» |
| 5xx, обрыв связи | сбой или недоступность | «учебный сервис недоступен, попробуйте позже» |

Тело ответа Frappe агенту не пересказывается: там имя питоновского класса
исключения, а при `developer_mode` и трассировка. Автоматических повторов
нет — решение о повторе принимает агент, у него есть контекст занятия.

**Чужая сессия и чужая попытка отклоняются доменным кодом** `not_your_session`,
а чужой ученик в отчёте — `not_your_student`. Проверка идёт по принадлежности
записи, и это не дублирование прав Frappe, а необходимость:

- `frappe.get_all` — это `get_list(ignore_permissions=True)`, и
  `permission_query_conditions` к нему не применяются **никогда**. Изоляция,
  построенная только на хуках, в методах отчётности не работала вовсе;
- читать занятие вправе ещё и руководитель — если оно в пространстве его
  организации, — но **действовать** в нём он не должен: иначе сожжёт ученику
  попытку квиза или ответит за него.

Права Frappe при этом остаются: они закрывают прямое обращение к
`/api/resource/...`, где записи для роли ученика нет вовсе — только чтение
своих записей.

## Запрещённые поля

Ни один ответ методов ученика и руководителя не содержит:

- текста эталонного ответа и признака правильности вариантов (`LMS Question`:
  `option_*`, `is_correct_*`, `answer`; `explanation` верного варианта — до
  вынесения вердикта и при неверном ответе);
- директивы преподавателя в методах, кроме `start_lesson`, где она приходит
  отдельным полем с явной пометкой;
- полей других учеников в методах ученика.

Методы авторинга — единственное исключение, и оно обозначено ролью, а не
адресом: `get_lesson` и `course_draft` отдают эталоны и директивы тому, кто
собирает курс. Ученик до них не доходит — вызов без роли куратора
отклоняется 403.

На это вешается регрессия `lms_frappe_app/api/test_no_leak.py`: прогон всех
методов ученика и руководителя с проверкой ответов на присутствие этих полей.
Утечка эталона обесценивает серверный квиз целиком — а он несущее решение
всей схемы зачёта.

# Методы витрины

Единственные методы, доступные **без входа**. Они ничего не знают о вызывающем,
кроме того, зачислен ли он: гостю отдаётся состав курса, зачисленному — он же
плюс его собственное покрытие целей.

## `lms_frappe_app.api.public.course_map`

Карта курса: главы, уроки с зачином, цели уроков и покрытие целей, а
зачисленному — ещё пройденность уроков и следующий урок. Зовёт страница курса
для программы курса, в MCP не выставляется.

**Параметры:** `course`, `space` (необязательный) — чей документ показывать зачисленному. Только `GET`.

```json
{ "ok": true, "data": {
  "course": "p3-express", "title": "P3.express", "next_lesson": "lesson-2",
  "documents": [ { "artifact": "project_summary", "title": "Резюме проекта",
                   "blocks_total": 6, "blocks_filled": 2 } ],
  "chapters": [
    { "title": "Запуск", "lessons": [
      { "id": "lesson-1", "number": 1, "title": "Запуск проекта",
        "hook": "Проект без спонсора глохнет на первом споре о деньгах.",
        "completed": true,
        "blocks": [ { "artifact": "project_summary", "key": "sponsor",
                      "title": "Спонсор и менеджер", "filled": true } ],
        "objectives": [ { "text": "Назвать спонсора проекта", "status": "covered" },
                        { "text": "Отличить проект от операций" } ] } ] } ] } }
```

`hook` — зачин урока, обращённый к ученику; виден всем, `null`, если автор
его не задал.

`documents` — документы, которые ученик собирает по ходу курса, у урока
`blocks` — какие их блоки собирают на этом уроке (learning-services#340). Видны
всем: что курс оставит после себя, — его обещание. Зачисленному — ещё
`blocks_total` и `blocks_filled` у документа и `filled` у блока, по тем же
правилам, что у `artifact`. Подсказки автора сюда не выходят: они адресованы
агенту. У курса без документа — пустые списки.

`tester: true` приходит зачисленному тестеру курса — его записал автор, чтобы
проверить курс до публикации (learning-services#393). У остальных ключа нет.

`completed` у урока и `next_lesson` у курса приходят **только зачисленному**,
по тому же правилу, что `status` у цели: у прочих ключей нет. `completed` —
урок закрыт квизом или `complete_lesson`; `next_lesson` — первый незакрытый
урок, тот же, что у `lesson_entry(course=…)`, у пройденного курса — `null`.

`status` у цели появляется **только у зачисленного** и только по его
собственным занятиям: `covered`, `touched` или `skipped` из `report_outcomes`.
У гостя и у вошедшего, но не зачисленного, ключа нет вовсе — `null` был бы
неотличим от «цель не разобрана». Цель без отчёта приходит без `status` и у
зачисленного: это и есть «не дошли».

Занятий по уроку бывает несколько — урок открывают повторно. Побеждает более
позднее: карта показывает, как дела обстоят сейчас.

Из директивы наружу выходят только цели. Как вести урок, проверочные
вопросы, заблуждения и критерии усвоения остаются на сервере.

**Анонс** (learning-services#389) — курс, который готовится: главы, уроки и
документы у него закрыты, наружу выходят только цели курса из действующей
директивы курса. Незачисленному карта анонса приходит в другом виде:

```json
{ "ok": true, "data": {
  "course": "ops-junctions", "title": "Где теряется работа между отделами",
  "upcoming": true, "notify": false,
  "objectives": [ "Описать процесс в пять колонок",
                  "Найти стыки между отделами" ],
  "documents": [], "chapters": [] } }
```

`upcoming` приходит только у анонса. `notify` — подписан ли вызывающий на
письмо о выходе (`notify_when_released`); у гостя ключа нет.

**Отказы:** `course_not_found` — курса нет или он не опубликован, а вызывающий
на него не зачислен. Непубликованный курс для постороннего не существует.

## `lms_frappe_app.api.public.course_programs`

В какие программы Learning входит курс и заперт ли он программой
(learning-services#405). Зовёт страница курса: «курс 2 из 3 программы …», а у
запертого курса — «сначала пройдите …» вместо записи. В MCP не выставляется:
агенту те же сведения приходят полем `programs` у курса в `list_catalog`,
`list_my_courses` и `course_outline`. Доступен и гостю.

**Параметры:** `course`. Только `GET`.

```json
{ "ok": true, "data": {
  "course": "course-early-signals",
  "programs": [ {
    "program": "Работа между отделами", "title": "Работа между отделами",
    "number": 2, "total": 3, "enforce_order": true, "member": true,
    "previous": { "id": "course-handoffs", "title": "Где теряется работа между отделами" },
    "next": { "id": "course-risk-matrix", "title": "Матрица рисков и контролей" },
    "locked_by": { "id": "course-handoffs", "title": "Где теряется работа между отделами" } } ] } }
```

Видны опубликованные программы и те, где вызывающий участник. `previous` —
курс перед этим в программе, у первого — `null`; `next` — курс после, у
последнего — `null`. `locked_by` — курс, который
пройти раньше: только участнику программы с обязательным порядком
(`enforce_order`), пока предыдущий курс не пройден целиком; прочим — `null`.
Порядок действует только для участников: второй курс напрямую из каталога
берётся без условий (решение владельца).

**Отказы:** `course_not_found` — курса нет или он не опубликован, а вызывающий
на него не записан.

## `lms_frappe_app.api.public.lesson_entry`

Вход в урок: зачин, пройден ли урок и куда вести ученика на занятие. Зовёт
страница урока в браузере — она показывает не материал, а дорогу к агенту.
В MCP не выставляется. Требует входа.

**Параметры:** `lesson` или `course`; `space` (необязательный) — чей документ
показывать в `blocks`. Только `GET`.

Только `course` — вход в следующий незакрытый урок курса, у пройденного
курса — в первый урок: так кнопка «Продолжить» на странице курса ведёт прямо
на занятие. Какой урок выбран, видно по `lesson`.

```json
{ "ok": true, "data": {
  "lesson": "lesson-1", "course": "p3-express", "title": "Запуск проекта",
  "hook": "Проект без спонсора глохнет на первом споре о деньгах — разберём, кто он у вас.",
  "completed": false,
  "study": { "channel": "web", "url": "https://lms.example.com/chat?lesson=lesson-1", "demo_left": 2 },
  "program_lock": null,
  "blocks": [ { "artifact": "project_summary", "key": "sponsor",
                "title": "Спонсор и менеджер", "filled": false } ] } }
```

`study.channel`:

- `web` — веб-чат платформы на этот урок. Так бывает, пока у ученика остались
  пробные уроки, и для урока, уже начатого в веб-чате: возврат в него пробного
  не тратит — то же правило, что у `start_lesson` с `channel: "web"`;
- `agent` — пробные кончились или сервиса агента у установки нет; `url` ведёт
  на `/lms/agent`, где шаги подключения своего ассистента.

`demo_left` — сколько пробных уроков веб-чата осталось, с учётом уже начатых.

`hook` — зачин урока, обращённый к ученику; `null`, если автор его не задал.
Материал и директива сюда не выходят: материал написан для агента.

`completed` — урок закрыт квизом или `complete_lesson`.

`program_lock` — курс заперт программой (learning-services#405): ученик —
участник программы с обязательным порядком, а предыдущий курс не пройден
целиком. Тогда `{ "program": "…", "program_title": "…", "previous": { "id": "…",
"title": "…" } }`, и страница ведёт к предыдущему курсу, а не на занятие;
иначе `null`.

`blocks` — блоки документа курса, которые собирают на этом занятии, как у
урока в `course_map`; у ученика курса — с `filled`.

**Отказы:** `lesson_not_found` — урока нет, в курсе нет уроков или не передано ни `lesson`, ни `course`.

# Методы ученика

**Пространства** (learning-services#346). Прогресс у ученика один, а курсы и
документы — у пространства: личного или организации, в которой он состоит.
Параметр `space` — имя организации или `personal`; чужое или приостановленное
пространство — отказ `space_not_available`. Без `space` методы списков
(`list_my_courses`, `list_catalog`, `enroll`, `get_my_progress`, `my_homework`
без курса и урока) работают в
**выбранном** пространстве (`my_spaces`, `set_space`), а методы курса
(`start_lesson`, `artifact`, `update_artifact`, `upload_artifact_file`,
`homework`, `submit_homework`, `my_homework` с `course` или `lesson`,
`course_map`, `lesson_entry`) — в пространстве открытого занятия по курсу,
иначе в выбранном, если курс в нём есть, иначе в личном. `Why:` агент, начавший
урок в компании, пишет документ туда же, не повторяя `space`. Названное
пространство, в котором курса нет, — отказ `course_not_in_space`.

## `lms_frappe_app.api.student.whoami`

Под какой учётной записью вошёл ученик и в каких он организациях.

**Параметры:** нет.

```json
{ "ok": true, "data": {
  "login": "ivanov@example.com", "full_name": "Иван Иванов",
  "organizations": [ { "id": "org-1", "title": "Компания",
                       "role": "Member", "suspended": false } ],
  "space": "org-1" } }
```

`Why:` пустой список курсов сам по себе ничего не объясняет — «вошли не тем
аккаунтом» и «тем, но без зачислений» выглядят одинаково. Приостановленная
организация закрывает доступ к своим курсам, и без `suspended` пустой каталог
необъясним.

Наружу идут только собственные данные ученика. `role` — роль в организации (`Member`,
`Manager`, `Org Admin`), а не на платформе: ролей Frappe здесь нет. Организации,
из которых ученик вышел, в список не входят. `space` — выбранное пространство.

**Отказов нет.**

## `lms_frappe_app.api.student.my_spaces`

Пространства ученика и какое выбрано.

**Параметры:** нет.

```json
{ "ok": true, "data": { "current": "org-1", "spaces": [
  { "id": "personal", "title": null, "role": null, "suspended": false,
    "documents_visible_to": "only_me" },
  { "id": "org-1", "title": "Компания", "role": "Member", "suspended": false,
    "documents_visible_to": "managers" } ] } }
```

`documents_visible_to` — кто, кроме автора, читает документы пространства:
`only_me` (личное), `managers` — руководители организации, `members` — все её
участники. Интерфейс пишет это ученику на документе.

Личное — всегда первым. Не выбирал — выбрана первая действующая организация,
иначе личное: сотрудник приходит прежде всего за курсами компании. Выбор,
который перестал действовать (вышел, организацию приостановили), уступает тому
же правилу.

**Отказов нет.**

## `lms_frappe_app.api.student.set_space`

Выбирает пространство. Выбор хранится на сервере: по нему работают и
интерфейс, и агент, и веб-чат. Только `POST`.

**Параметры:** `space` — организация или `personal`.

```json
{ "ok": true, "data": { "current": "personal" } }
```

**Отказы:** `space_not_available`.

## `lms_frappe_app.api.student.list_my_courses`

Курсы пространства с прогрессом и дедлайнами.

**Параметры:** `space` (необязательный).

В личном пространстве — все курсы ученика, в том числе назначенные компанией:
прогресс у него один (решение владельца, learning-services#346). В
пространстве организации — курсы, которые она назначила ему или которые он
выбрал в её каталоге; `deadline` и `mandatory` — её.

Список строится **по зачислениям**, а не по назначениям: ученик, записавшийся
сам, назначений не имеет вовсе. Назначение организации добавляет поверх
`deadline`, `mandatory` и `organization`; у частного ученика эти поля пустые.

Курсы приостановленной организации в список не попадают, но зачисление на них
сохраняется — при возобновлении прогресс на месте.

**Отказов нет.**

```json
{ "ok": true, "data": { "space": "org-1", "courses": [
  { "id": "course-basics", "title": "Основы", "organization": "org-1",
    "mandatory": true, "deadline": "2026-09-15", "overdue": false,
    "progress": { "lessons_total": 12, "lessons_completed": 5 },
    "next_lesson": { "id": "lesson-6", "title": "Циклы" },
    "programs": [] } ] } }
```

`programs` — программы курса в том же виде, что у `course_programs`: место
курса в цепочке, предыдущий и следующий курс и `locked_by`, если курс для
ученика заперт порядком (learning-services#405). Курс вне программ —
пустой список.

## `lms_frappe_app.api.student.list_catalog`

Опубликованные курсы, на которые ученик может записаться сам в пространстве,
и анонсы — курсы, которые готовятся.

**Параметры:** `space` (необязательный).

```json
{ "ok": true, "data": { "space": "personal", "courses": [
  { "id": "course-python", "title": "Питон с нуля",
    "summary": "Для тех, кто не программировал", "upcoming": false, "programs": [] },
  { "id": "ops-junctions", "title": "Где теряется работа между отделами",
    "summary": "Стыки между отделами и риски на них", "upcoming": true,
    "objectives": [ "Описать процесс в пять колонок" ], "notify": false,
    "programs": [ {
      "program": "ops-chain", "title": "Операционное управление",
      "number": 1, "total": 3, "enforce_order": true, "member": false,
      "previous": null,
      "next": { "id": "ops-early-signals", "title": "Как заметить проблему заранее" },
      "locked_by": null } ] } ] } }
```

У анонса (`upcoming: true`) записи нет: `enroll` отказывает `course_upcoming`.
Вместо неё — `notify_when_released`. `objectives` — цели курса из его
директивы, `notify` — подписан ли ученик на письмо о выходе; оба ключа
приходят только у анонса.

`programs` — программы курса в том же виде, что у `course_programs`: место
курса в цепочке, предыдущий и следующий курс и `locked_by`, если курс для
ученика заперт порядком (learning-services#405). Курс вне программ —
пустой список. Курс с `locked_by` в каталоге остаётся: `enroll` на нём
откажет `program_order`, а агент назовёт курс, который пройти раньше.

В личном пространстве — весь опубликованный каталог без курсов, на которые
ученик уже записан. В пространстве организации — открытые ею курсы (пустой
список разрешённых — весь каталог) без тех, что уже в её пространстве: курс,
пройденный лично, можно взять и в компанию.

**Отказов нет.**

## `lms_frappe_app.api.student.enroll`

Записывает ученика на курс из каталога пространства.

**Параметры:** `course`, `space` (необязательный).

```json
{ "ok": true, "data": { "space": "org-1",
  "course": "course-python", "title": "Питон с нуля",
  "first_lesson": { "id": "lesson-1", "title": "Переменные" } } }
```

В пространстве организации запись — её назначение ученику с отметкой «выбран
сотрудником» (`chosen_by_member`): курс попадает в её пространство и отчёт,
обучение идёт за её счёт.

**Отказы:** `course_not_published`, `course_upcoming` — курс анонсирован и
ещё готовится, `already_enrolled` — курс уже в этом пространстве,
`course_not_allowed` — организация его не открыла, `space_not_available`,
`program_order` — ученик участник программы с обязательным порядком, а
предыдущий курс не пройден целиком (с `program`, `program_title` и `previous`,
learning-services#405).

## `lms_frappe_app.api.student.notify_when_released`

Подписывает ученика на письмо о выходе анонсированного курса
(learning-services#389) или снимает подписку (learning-services#391). Только
`POST`.

**Параметры:** `course`, `notify` (необязательный, по умолчанию `true`) —
`false` снимает подписку.

```json
{ "ok": true, "data": { "course": "ops-junctions",
  "title": "Где теряется работа между отделами", "notify": true } }
```

Повторный вызов ничего не меняет. Письмо уходит один раз, когда куратор
открывает курс `publish_course`. Отписаться можно и от курса, который уже не
анонс; в ответе тогда `notify: false`.

**Отказы:** `course_not_upcoming` — подписка на курс, который не анонсирован:
он открыт, снят или его нет.

## `lms_frappe_app.api.student.course_outline`

Программа курса с отметками пройденного. Единственный способ узнать
идентификатор уже закрытого урока: `list_my_courses` отдаёт только следующий.

**Параметры:** `course`.

```json
{ "ok": true, "data": { "course": "course-basics", "chapters": [
  { "title": "Основы", "lessons": [
    { "id": "lesson-1", "title": "Переменные", "completed": true, "current": false },
    { "id": "lesson-2", "title": "Циклы", "completed": false, "current": true } ] } ],
  "programs": [] } }
```

Порядок глав и уроков — тот же, что показывает браузер: Frappe Learning
хранит его в строках-ссылках, а не в самих записях, где `idx` всегда ноль.

`programs` — программы курса в том же виде, что у `course_programs`: место
курса в цепочке, предыдущий и следующий курс и `locked_by`, если курс для
ученика заперт порядком (learning-services#405). Курс вне программ —
пустой список.

**Отказы:** `not_enrolled`, `organization_suspended`.

Повторное открытие пройденного урока прогресс не двигает: `complete_lesson`
на нём безвреден, а квиз, если он есть, подчиняется обычному лимиту попыток.

## `lms_frappe_app.api.student.start_lesson`

Начинает занятие: создаёт учебную сессию и отдаёт всё нужное для урока.

**Параметры:** `brief` (необязательный, по умолчанию `false`) — лёгкий
старт, см. ниже; `lesson` (необязательный) — без него берётся следующий
незакрытый урок; `course` (необязательный) — выбирать только в этом курсе,
без него — по всем курсам ученика: урок последнего занятия, если он не
пройден, иначе следующий урок его курса, а без занятий — курс с ближайшим
дедлайном, обязательные и просроченные вперёд (тот же порядок, что у
`study_options`); при переданном `lesson` не действует; `segment` (по
умолчанию 1) — часть длинного урока; `channel` — `agent` (по умолчанию, свой
агент ученика) или `web` (веб-чат платформы); `space` (необязательный) — в чей
документ пишет занятие; без `lesson` и `course` урок выбирается среди курсов
этого пространства.

`Why:` у `course` — выбор по всем курсам открывал урок курса, который горит
сильнее, когда ученик просил продолжить другой (lms-platform#337).

Повторный вызов по тому же уроку в том же пространстве **не создаёт второе
занятие**: возвращается незакрытое. В другом пространстве — другое занятие: оно
пишет в другой документ. Иначе на один урок копятся сессии, которые потом закрывает
фоновая задача.

Канал `web` ограничен числом пробных уроков — `web_demo_lessons` в
`Agent Learning Settings`. Считаются **разные уроки** ученика по всем курсам,
где хоть один вызов пришёл с `web`: урок уже в счёте открывается снова и после
закрытия занятия по бездействию, продолжение урока своего агента в веб-чате
идёт в счёт. Канал подделывать незачем — `web` только ограничивает
передавшего.

`homework` — домашнее задание этого урока, как у `homework`; выдаётся при
закрытии урока. `previous_homework` — задание
**предыдущего по порядку курса урока** и сдача ученика в пространстве занятия:
статус, срок, ответ, файлы и журнал с комментариями куратора
(learning-services#439); `submission: null` — ученик по нему ничего не
сохранял, `last_comment` — комментарий последнего возврата на доработку или
отмены приёма. У
урока без задания — `null` в обоих ключах, независимо друг от друга.

С `channel: web` — для шапки веб-чата (learning-services#404) — в `lesson`
ещё место урока в курсе и название курса (`"number": 6, "total": 12,
"course_title": "Основы программирования"`), а в ответе `web_demo` — пробные
уроки: `{ "used": 1, "limit": 2, "left": 1 }`. Своему агенту их нет: пробы у
него не считаются, программу он берёт `course_outline`.

`course_promise` и `lesson_hook` — обещание курса и зачин урока, `null`, если
автор их не задал. Адресат — ученик, поэтому они лежат верхним уровнем рядом с
`objectives`, а не внутри `directive` с грифом `teacher_only`.

`start.opening` — с чего начинать занятие; сервер решает это сам, чтобы агент
не выводил одно из пяти признаков на каждом старте. Проверки идут по порядку:

| `opening` | Когда | Что звучит |
|---|---|---|
| `next_segment` | отдан не первый сегмент урока | ничего |
| `repeat` | по этому уроку уже было другое занятие со следом | ничего |
| `first_in_course` | других занятий со следом по курсу нет | обещание, зачин, цели |
| `return` | есть `carried_over`, а прошлое занятие по курсу старше `bridge_after_hours` из `Agent Learning Settings` (сутки) | мостик от `resume_from`, цели |
| `new_lesson` | всё остальное | зачин, цели |

Незакрытое занятие того же урока переиспользуется, и продолжение повтором не
считается. **Занятие со следом** — с отчётом по целям или закрытым уроком:
брошенная в начале попытка не в счёт, иначе человек, не видевший урока,
получил бы `repeat` и «сразу к делу» (learning-services#408). `start.last_session_at` — последняя активность в прошлых занятиях
по курсу, `null` для первого.

`artifact_blocks` — блоки документов курса, привязанные к этому уроку, с
содержимым ученика. Это подсказка «сегодня собираем резюме проекта», а не
ограничение: `update_artifact` принимает любой ключ. Пусто, если к уроку не
привязан ни один блок. Поля блока — как у `artifact` с ключом, включая вид,
файл и срез.

Политика квиза в ответе — **действующая для этого ученика на этом курсе**.
Порог, лимит попыток и пауза перед повтором — платформы, одни на всех
(`Agent Learning Settings`; по умолчанию зачёт только без ошибок, без лимита,
пауза 10 минут — решение владельца, learning-services#353). Организация
решает только, обязателен ли квиз; если курс назначили несколько, квиз
обязателен, когда этого требует хоть одна.

`content.markdown` — результат нормализатора: связный текст без макросов
Frappe Learning, медиа вынесены в `media`. Длинный урок отдаётся сегментами.

Места урока, которые проводит **не агент**, приходят в тексте **структурными
маркерами** — вид места и его положение в материале, без прозы:

| Маркер | Место |
|---|---|
| `[[lms:quiz]]` | по плану урока здесь проверка знаний; её ставит сервер |
| `[[lms:exercise:Название]]` | упражнение браузерного интерфейса; название может отсутствовать — тогда `[[lms:exercise]]` |

Идентификатора квиза, вопросов и эталонов в маркере нет. Название очищено от
`[`, `]` и переводов строки — иначе оно рвало бы маркер.

Фразу для агента по маркеру складывает потребитель контракта; незнакомый вид
места он обязан вырезать, а не зачитывать. `Why:` инструктивный текст,
порождённый этим приложением, публикуется под AGPL вместе с ним — см.
[CONTRIBUTING.md](CONTRIBUTING.md), «готовые тексты для агента».

`directive` помечена `audience: teacher_only` и приходит **отдельным полем от
материала** — это одна из трёх митигаций против пересказа директивы ученику.
Гарантий она не даёт; гарантию даёт серверный квиз.

`course_directive` — сквозная директива курса, действующая на всех его
занятиях; помечена так же. Внутри неё `remember_about_student` — что в этом
курсе стоит помнить об ученике между занятиями; поле идёт под той же пометкой
`teacher_only`, что и остальная директива, и задаётся `set_course_directive`.
`course_objectives` идут наружу, как и `objectives` урока: цели агент вправе
озвучить ученику. Директивы курса нет — оба поля приходят пустыми, урок
открывается как обычно.

`student_context` — заметки об ученике (`facts`, `observations`, `project`,
`projects_elsewhere` — те же, что отдаёт `my_notes`) и `carried_over` — цели прошлых уроков курса, оставшиеся
`touched` или `skipped` в отчётах `report_outcomes`. Глубина переноса —
`carry_over_depth` в `Agent Learning Settings`, считаются разные уроки.
Заметки идут отдельным полем от директивы: они ведутся об ученике и доступны
ему, грифа «не показывать» на них нет.

`objectives_progress` — отметки целей этого занятия, как у `mark_objective`;
у продолженного занятия они уже могут быть.

`student_context.recent_work` — что ученик сделал по разобранным целям прошлых
уроков курса: заметки `covered` из `mark_objective`. Глубина та же, что у
`carried_over`; брошенные занятия в счёт — отметки в них ставились по ходу.

`student_context.closed_reports` — репорты ученика по этому курсу, получившие
итог (`fixed`, `rejected`, `duplicate`), о котором он ещё не узнал. Элемент —
тот же, что в `my_reports`. Отдаются **один раз**: вызов отмечает их
доставленными, и следующий `start_lesson` их уже не принесёт. Переоткрытый и
снова закрытый репорт приходит снова — это другой итог. Пусто, если нового
нет.

**Лёгкий старт** — `brief: true` (learning-services#410). Ответ — занятие,
урок, цели, зачин и обещание, `start`, квиз и сигналы, без материала, указаний
и контекста ученика: их агент берёт `lesson_material`, `teaching_notes` и
`student_context`, когда они нужны. `context` говорит, сколько ждёт в
`student_context`, — по нулям туда незачем ходить. Итоги репортов лёгкий старт
доставленными не отмечает: их доставит `student_context`. Событие «указания
выданы» не пишется — его пишет `teaching_notes`.

```json
{ "ok": true, "data": {
  "session": "sess-01H…", "space": "org-1",
  "lesson": { "id": "lesson-6", "title": "Циклы", "course": "course-basics",
              "overdue": false },
  "content": { "segment_index": 1, "total_segments": 3 },
  "objectives": [ "Понимать разницу между while и for" ],
  "objectives_progress": { "marked": 0, "total": 1,
    "open": [ { "number": 1, "text": "Понимать разницу между while и for" } ] },
  "course_promise": "К концу курса вы пишете программы с циклами и функциями",
  "lesson_hook": "Повторять одно и то же вручную — первое, что надоедает",
  "start": { "opening": "new_lesson", "last_session_at": "2026-09-01T13:05:00" },
  "course_objectives": [ "Вести проект по системе" ],
  "quiz": { "required": true, "pass_threshold": 1.0, "attempts_left": null },
  "context": { "notes": 2, "carried_over": 1, "recent_work": 0, "closed_reports": 0 },
  "signals": [],
  "homework": { "lesson": "lesson-6", "title": "Цикл из жизни",
    "description": "Найдите у себя на работе повторяющееся действие…",
    "answer_mode": "text", "due": { "mode": "relative", "days": 3, "date": null } },
  "previous_homework": { "lesson": "lesson-5", "title": "Критический путь своего проекта",
    "submission": { "id": "a1b2c3d4e5", "status": "Returned",
      "due_at": "2026-09-04T13:05:00", "overdue": true, "version": 1 },
    "last_comment": "Не хватает сроков по закупке" } } }
```

Домашка в лёгком старте: задание текущего урока — целиком, по прошлому — статус,
срок, просрочка и последний комментарий куратора; ответ ученика и журнал —
`my_homework(lesson=…)`.

Без `brief` — прежний полный ответ. `Why:` подключения с кэшем инструментов не
знают новых методов, и лёгкий ответ послал бы их к тому, чего у них нет.

`signals` — выводы сервера из истории ученика (learning-services#416); здесь
приходят `objective_struggling`, `abandoned_in_row` и `deadline_pace`, описание
кодов — в разделе «Сигналы» у `mark_objective`.

**Отказы:** `not_enrolled`; `organization_suspended` — организация ученика
приостановлена, зачисление цело и доступ вернётся вместе со статусом;
`lesson_not_found`; `nothing_to_study` — незакрытых уроков не осталось (только
при вызове без `lesson`; с `course` — в этом курсе, с полем `course`); `web_demo_exhausted` (с `lessons_used` и
`lessons_limit`) — пробные уроки веб-чата пройдены, занятие не заводится;
`program_order` — курс заперт программой, как у `enroll`: запись могла
появиться раньше вступления в программу; `unknown_channel`.

**Поверхность MCP-инструмента у `start_lesson` другая, чем у метода.**
Контракт
описывает метод Frappe; инструмент MCP-сервиса — не его зеркало, и разница
здесь не случайна:

- параметра `channel` у инструмента нет — сервис подставляет его сам, из
  контекста вызова. Модель не может забыть канал, а поверхность инструментов
  у своих агентов учеников остаётся прежней;
- `directive` и `course_directive` инструмент отдаёт **одним полем**: два поля
  с инструкциями — приглашение обработать одно и забыть второе;
- структурные маркеры (`[[lms:quiz]]`) инструмент заменяет фразой для агента.

Клиент, разговаривающий с приложением напрямую, получает то, что описано
здесь, — оба поля директив, маркеры как есть и `channel` параметром.

Отзыв разрешения на курс у организации **отдельным кодом не отражается**:
проверка списка разрешённых курсов работает при назначении, а уже выданное
зачисление она не снимает.
Прошедший дедлайн отказом **не является**: урок отдаётся, в ответе
`overdue: true`, зачёт фиксируется как поздний.

## `lms_frappe_app.api.student.study_options`

Что продолжать: урок, который открыл бы `start_lesson` без аргументов, и
следующие уроки других курсов пространства (learning-services#403). Зовёт веб-чат,
открытый без урока: вместо того чтобы молча начать урок и потратить пробный,
он показывает развилку.

**Параметры:** `space` (необязательный) — пространство; без него — выбранное.

```json
{ "ok": true, "data": {
  "recommended": {
    "lesson": { "id": "lesson-2", "title": "Цели и источники", "number": 2, "total": 8 },
    "course": { "id": "course-risks", "title": "Риски проекта" },
    "deadline": null, "overdue": false, "mandatory": false,
    "reason": "last_lesson", "web": true },
  "others": [ {
    "lesson": { "id": "lesson-7", "title": "Сегменты", "number": 1, "total": 6 },
    "course": { "id": "course-canvas", "title": "Lean Canvas" },
    "deadline": "2026-10-02", "overdue": false, "mandatory": true,
    "reason": "deadline", "web": false } ],
  "web_demo": { "used": 2, "limit": 2, "left": 0 } } }
```

Порядок: урок последнего занятия, если не пройден (`reason: last_lesson`),
иначе следующий урок его курса (`last_course`); дальше курсы по дедлайну
(`deadline`) и без него (`next`). По уроку на курс, пройденные курсы не
попадают. `others` — не больше трёх. `web` — пустит ли веб-чат на урок:
урок, уже начатый в браузере, пробного не тратит. Нечего продолжать —
`recommended: null`.

**Отказы:** нет.

## `lms_frappe_app.api.student.lesson_session`

Последнее занятие ученика по уроку — чтобы вернуть его в разговор, а не
начинать с чистого листа.

**Параметры:** `lesson`.

```json
{ "ok": true, "data": {
  "lesson": "lesson-6", "title": "Циклы",
  "session": "sess-01H…", "status": "Completed", "has_chat_state": true,
  "completed": true,
  "next_lesson": { "id": "lesson-7", "title": "Функции" },
  "objectives_progress": { "marked": 2, "total": 2, "open": [] } } }
```

`objectives_progress` — отметки целей этого занятия, как у `mark_objective`;
`null`, если занятий по уроку не было.

Занятий по уроку ещё не было — `session` и `status` приходят `null`,
`has_chat_state` — `false`. `next_lesson` считается по курсу, а не по
занятию: это следующий незакрытый урок, и он приходит всегда, пока такой есть.

`Why:` `start_lesson` переиспользует только незакрытое занятие, а закрытое
квизом заводит заново — ученик, вернувшийся к пройденному уроку, видел его с
первого вопроса. По этому методу потребитель решает: показать историю
разговора или заводить занятие.

Метод только читает: занятий не создаёт и событий в журнал не пишет — иначе
каждый возврат на страницу оставлял бы след, которого не было.

**Отказы:** `lesson_not_found`, `not_enrolled`, `organization_suspended`.

## `lms_frappe_app.api.student.report_outcomes`

Итог по целям урока. **Все цели урока должны иметь статус до квиза и до
закрытия урока:** `request_quiz` и `complete_lesson` иначе отказывают кодом
`outcomes_required` со списком `missing`. Статус ставят отметки
`mark_objective` по ходу и этот итог.

**Параметры:** `session`, `outcomes` — список `{ "objective": …, "status": …,
"resume_from": … }`; `resume_from` необязателен.

`objective` — цель урока дословно, как она пришла в `objectives` от
`start_lesson`, или её номер с единицы. `status` — `covered`, `touched` или `skipped`; набор закрыт.

`resume_from` — одна фраза агента к незакрытой цели: с чего продолжать на
следующем занятии. Сервер вернёт её в `carried_over` у `start_lesson`, и мостик
построится от неё, а не от пересказа: конспект целиком способен вернуть
объяснение, которое ученика запутало. Длиннее 500 знаков — `objectives_mismatch`
с `field: "resume_from"`.

Итог **дополняет отметки**: пункт замещает отметку той же цели, цели без
пункта остаются с отметкой. Вместе с отметками итог обязан покрыть **ровно**
цели урока — без пропущенных и без лишних; иначе `objectives_mismatch` с
`missing` и `unexpected`. Заметка о сделанном у разобранной цели итогом
`covered` не стирается.

```json
{ "ok": true, "data": { "session": "sess-01H…", "reported": 3,
  "progress": { "marked": 3, "total": 3, "open": [] },
  "empty_blocks": [ { "artifact": "risk_register", "key": "goals",
                      "title": "Цели проекта" } ] } }
```

`empty_blocks` — блоки документов курса, которые собирают на этом уроке (`lesson`
блока в схеме), а у ученика они пусты; пустой список, если таких нет. Это
предупреждение, а не отказ: квиз и закрытие урока от него не зависят. Агент
предлагает заполнить блок до конца занятия или оставить в домашнем задании.
`Why:` урок засчитывает квиз, и документ курса можно было оставить пустым
незаметно; запрет давал бы обход — «непустой» ещё не значит «готов», а блок
часто доводят после занятия (решение владельца, learning-services#296).

Повторный итог замещает статусы названных целей. Поэтому
`objectives_skipped` у `request_quiz` не создаёт тупика — разобрали
пропущенное, отметили или сдали итог заново, квиз открыт.

Урок, у которого целей нет — директивы нет вовсе или в ней пустой
`objectives`, — отчёта не требует: `request_quiz` и `complete_lesson`
пропускают проверку. Требовать нечего, и отказ загнал бы агента в тупик без
выхода.

Цели, оставшиеся `touched` или `skipped`, возвращаются на следующих занятиях
курса в `student_context.carried_over`, а руководителю — в `student_detail`.

**Отказы:** `not_your_session`; `objectives_mismatch` — статус не из набора
(с `objective` и `status`) либо состав не совпал с целями урока (с `missing`
и `unexpected`).

## `lms_frappe_app.api.student.mark_objective`

Отметка одной цели урока по ходу занятия (learning-services#409). Только `POST`.

**Параметры:** `session`, `objective` — номер цели в `objectives` от
`start_lesson`, с единицы; `status` — `covered` или `touched`; `note` — одна
фраза: у `covered` обязательна — что ученик сделал на своей задаче, у
`touched` — с чего продолжать.

```json
{ "ok": true, "data": { "session": "sess-01H…", "objective": 2,
  "text": "Уметь читать код", "status": "covered",
  "progress": { "marked": 1, "total": 3,
                "open": [ { "number": 1, "text": "Понимать цикл" },
                          { "number": 3, "text": "Писать цикл с условием" } ] },
  "signals": [], "warnings": [ "teaching_notes_not_taken" ] } }
```

`warnings` — мягкие проверки порядка у занятия лёгкого старта: отметки идут,
а указания (`teaching_notes_not_taken`) или материал
(`lesson_material_not_taken`) не взяты. Это не отказ: отметка записана
(решение владельца, learning-services#407). У полного старта всё выдано сразу,
и список пуст.

Отметка сразу пишется в занятие: страница курса показывает её, а перенос на
следующее занятие берёт её и из брошенного занятия. Повторная отметка той же
цели замещает прежнюю. `skipped` отметкой не ставится — только итогом урока
`report_outcomes`. Номер сопоставляется с целями действующей директивы урока.

`progress` — сколько целей урока отмечено и какие ещё нет, с номерами; тот же
объект приходит как `objectives_progress` в `start_lesson`, `remember` и
`update_artifact` посреди занятия.

### Сигналы

`signals` в ответах `start_lesson` и `mark_objective` — выводы сервера из
истории ученика, которых агент по одному разговору сделать не может: код и
данные, без текста. Фразу для агента складывает потребитель контракта, как и по
структурным маркерам. В ответе не больше трёх сигналов, по приоритету таблицы;
каждый — один раз за занятие: показанный занятие помнит, и повторный вызов его
не принесёт. Пусто — сказать нечего.

| `code` | Данные | Когда |
|---|---|---|
| `lesson_wrapup` | `empty_blocks` — как у `report_outcomes` | отметкой закрыта последняя цель урока |
| `objective_struggling` | `objective` (номер), `text`, `sessions` | цель урока осталась `touched` в двух и более занятиях ученика; на старте — по прошлым, после отметки `touched` — с этой |
| `abandoned_in_row` | `attempts` | два и больше последних занятия по уроку брошены подряд без единой отметки |
| `blocks_empty` | `blocks` — `artifact`, `key`, `title` | после отметки `covered` отмечена половина целей, а ни один блок документа урока не начат |
| `deadline_pace` | `lessons_left`, `lessons_per_week` (`null` при просрочке), `overdue` | срок курса прошёл или к нему нужно от трёх уроков в неделю |

Времени внутри занятия в сигналах нет: сервер считает по нему сам — брошено ли
занятие, успевает ли ученик к сроку — и отдаёт вывод. `Why:` агенты не
отслеживают реальное время и неверно толкуют его внутри урока. Сигналы
строятся только по истории самого ученика — без репортов и без других
учеников (решения владельца, learning-services#416).

**Отказы:** `not_your_session`; `session_closed` — занятие закрыто;
`objectives_mismatch` — нет цели с таким номером (с `total`), статус не
`covered`/`touched`, у `covered` нет `note` или заметка длиннее 500 знаков
(с `field: "note"`).

## `lms_frappe_app.api.student.report_issue`

Репорт агента о том, что мешает курсу работать на этом уроке. Разбирают его
сотрудники платформы и авторы курса, а статус и ответ видит ученик —
`my_reports` и `student_context.closed_reports` у `start_lesson`.

**Параметры:** `session`, `kind`, `text`, `question` (необязателен),
`objective` (необязателен).

`kind` — один из `stuck`, `misconception`, `material_issue`,
`quiz_question_issue`, `directive_mismatch`, `out_of_scope`. `question` —
вопрос квиза этого урока, для репорта о вопросе. `objective` — цель урока
строкой, не ссылкой: переформулированная автором цель не должна задним числом
переписать то, о чём уже сообщили. Описание режется по 2000 символов, цель —
по 140.

**Курс, урок и действующую редакцию указаний проставляет сервер** из занятия,
и параметрами они не передаются: привязка от агента указала бы на чужой урок,
а вторая её копия разъехалась бы с занятием. Редакция указаний отвечает на
вопрос «это ещё актуально или указание с тех пор переписали».

```json
{ "ok": true, "data": { "report": "8f3c1a…", "kind": "material_issue" } }
```

Номер — для ученика: по нему он найдёт свой репорт в `my_reports` и узнает,
чем кончилось дело.

**Отказы:** `not_your_session` — занятие принадлежит другому ученику;
`unknown_report_kind` (с `kind`) — вид не из списка; `report_text_required`
(с `kind`) — описание пустое; `question_mismatch` (с `question`) — вопрос не
из квиза этого урока.

## `lms_frappe_app.api.student.complete_lesson`

Отмечает урок пройденным там, где проверять нечего: у урока нет квиза, квиз
состоит из вопросов, которые сервер проверить не может, или политика
организации квиза не требует.

**Параметры:** `session`.

```json
{ "ok": true, "data": {
  "lesson": "lesson-6", "session_status": "Completed",
  "next_lesson": { "id": "lesson-7", "title": "Функции" },
  "empty_blocks": [] } }
```

`empty_blocks` — как у `report_outcomes`: пустые блоки документа этого урока на
момент закрытия. Урок закрывается и с ними.

**Отказы:** `not_your_session`; `session_closed` (с `status`) — занятие уже
закрыто, `Completed` или `Abandoned`; `outcomes_required` — отчёт по целям
урока ещё не сдан, см. `report_outcomes`; `quiz_required` — у урока есть
обязательный квиз, и закрыть его можно только сдачей; `busy` (с `session`) —
прохождение этого урока в этот момент меняет другой запрос, урок не закрыт:
повторите вызов.

Порядок проверок именно такой: закрытое занятие отвечает `session_closed`
раньше, чем метод спросит про отчёт.

Последнее — несущее ограничение, а не формальность: без него метод стал бы
обходом проверки, и серверный зачёт, на котором держится вся схема, потерял
бы смысл.

Занятие, брошенное по бездействию, урок не закрывает: иначе урок числился бы
пройденным при брошенном занятии, и прогресс разошёлся бы с журналом. Вернуться
к уроку — `start_lesson`: он заведёт по нему новое занятие, и закрывается уже
оно. Поэтому и повторный вызов по тому же `session` отвечает `session_closed`,
а повторное открытие пройденного урока остаётся безвредным.

## `lms_frappe_app.api.student.request_quiz`

Переводит сессию в `Awaiting Quiz`, создаёт попытку, отдаёт первый вопрос.

**Параметры:** `session`.

```json
{ "ok": true, "data": {
  "attempt": "att-01H…",
  "question": { "id": "q-14", "text": "Что выведет цикл…",
                "kind": "choice", "multiple": false,
                "options": [ { "id": "1", "text": "…" } ],
                "index": 1, "total": 5 },
  "touched_objectives": [ "Уметь читать код" ] } }
```

В `options` нет признака правильности; идентификатор варианта — его номер.
`multiple` говорит, сколько вариантов верных. У вопроса со свободным вводом
`kind` равен `input`, и поля `options` нет.

Незавершённая попытка **возвращается как есть**, с первым неотвеченным
вопросом: иначе ученик бросал бы попытку после каждого вердикта и перебирал
варианты, а лимит считает только завершённые.

Каждый выданный вопрос — и первый, и возвращённый с незавершённой попыткой —
пишется в журнал проверки (см. `submit_answer`).

**Отказы:** `not_your_session` — занятие принадлежит другому ученику;
`outcomes_required` — отчёт по целям урока не сдан, см. `report_outcomes`;
`objectives_skipped` (со списком `skipped`) — в отчёте есть цели, до которых
не дошли; `quiz_not_configured` — у урока нет квиза; `quiz_not_checkable` —
сверять нечего; `not_enrolled` и `organization_suspended` —
доступ к курсу отозван после начала занятия;
`quiz_attempts_exhausted` (с `attempts_used`); `retry_too_soon`
(с `retry_after`).

`touched` квиз не блокирует, `skipped` блокирует. Тупика отказ не создаёт:
повторный `report_outcomes` замещает отчёт целиком.

`touched_objectives` — формулировки целей, которые отчёт занятия отметил
`touched`, в порядке директивы; пустой список, если таких нет. Приходит и при
возвращённой незавершённой попытке.

`retry_after` в отказе `retry_too_soon` — ISO 8601 со смещением часового пояса
сайта, тот же момент, что `retry_after` в итоге проваленной попытки
(`submit_answer`).

В попытку берутся только вопросы, которые сервер может сверить сам. Открытые
он не проверяет: их разбирают на занятии, а зачёт от агента — не зачёт. Frappe
Learning не позволяет смешивать открытые с проверяемыми в одном квизе, поэтому
промежуточного случая нет: квиз либо весь открытый, либо проверяемый целиком.

Из проверки выпадает и вопрос с вариантами, у которого ни один не отмечен
верным: сверять его не с чем. Он просто не попадает в попытку — так кривой
вопрос мешает себе, а не всему курсу. Квиз, где таких вопросов не осталось ни
одного, отвечает `quiz_not_checkable`; урок с таким квизом закрывается
`complete_lesson`.

## `lms_frappe_app.api.student.submit_answer`

Принимает ответ, возвращает вердикт и следующий вопрос.

**Параметры:** `attempt`, `question`, `answer`, `student_words`.

`student_words` — обязательный: что ученик написал в ответ, дословно, а не
пересказ и не номер варианта. Сервер его не проверяет, и на вердикт он не
влияет — судит только `answer`. Нет его или он пуст — отказ
`student_words_required`, ответ не принят. Длиннее 2000 знаков — обрезается,
а не отклоняется.

Ответ, как его прислал агент, слова ученика и вердикт хранятся в журнале
проверки вместе с выданными вопросами — для разбора курса. Журнал видят
только администраторы платформы; ни ученику, ни руководителю он не отдаётся.

```json
{ "ok": true, "data": {
  "verdict": { "correct": true, "explanation": "…" },
  "next_question": { "id": "q-15", "index": 2, "total": 5, "…": "…" },
  "attempt_finished": false } }
```

Неверный ответ на вопрос с вариантами:

```json
{ "ok": true, "data": {
  "verdict": { "correct": false, "why_wrong": "…" },
  "next_question": { "id": "q-15", "index": 2, "total": 5, "…": "…" },
  "attempt_finished": false } }
```

Когда вопросы кончились:

```json
{ "ok": true, "data": {
  "verdict": { "correct": true },
  "next_question": null, "attempt_finished": true,
  "result": { "score": 1.0, "passed": true, "pass_threshold": 1.0,
              "session_status": "Completed" } } }
```

Попытка не зачтена:

```json
{ "ok": true, "data": {
  "verdict": { "correct": false },
  "next_question": null, "attempt_finished": true,
  "result": { "score": 0.5, "passed": false, "pass_threshold": 1.0,
              "session_status": "Awaiting Quiz",
              "attempts_left": null,
              "retry_after": "2026-09-25T14:30:00+03:00" } } }
```

Сверка выполняется на сервере. По завершении попытки пишутся стандартные
`LMS Quiz Submission` и `LMS Course Progress` — поэтому результат виден в
браузерном интерфейсе, и оба канала сходятся в одной записи.

`explanation` — пояснения верных вариантов — возвращается только **вместе с
верным** ответом: ошибившийся получил бы готовый ответ перед следующей
попыткой. При неверном ответе на вопрос с вариантами приходит `why_wrong` —
пояснения тех **выбранных** вариантов, которые неверны, через пробел: ответа
они не называют. Пояснение верного варианта при неверном ответе не приходит
ни в каком поле, в том числе когда среди выбранных есть и верные. Нет
пояснений у выбранных неверных — нет и ключа; то же с `explanation`.

`attempts_left` и `retry_after` есть только в итоге **незачтённой** попытки.
`attempts_left` — сколько попыток ещё можно начать, `null` — лимита нет.
`retry_after` — момент, с которого `request_quiz` начнёт следующую попытку,
ISO 8601 со смещением часового пояса сайта; при `attempts_left: 0` —
`null`, пересдавать нечем. Считаются они по тем же правилам, по которым
следующий `request_quiz` отвечает `quiz_attempts_exhausted` и `retry_too_soon`.

**Отказы:** `attempt_finished`, `question_mismatch` (вопрос не из этой попытки
или уже отвечен), `not_your_session` — попытка принадлежит другому ученику,
`not_enrolled` и `organization_suspended` — доступ к курсу отозван, пока шла
попытка; `student_words_required` — не переданы слова ученика; `busy` (с
`attempt`) — попытку или прохождение урока в этот момент меняет другой запрос,
ответ не принят: повторите вызов. Отклонённый ответ в журнал проверки не
попадает.

Вопрос, у которого не отмечен ни один верный вариант, отдельным отказом не
отражается: до квиза он не доходит — `request_quiz` в состав попытки берёт
только вопросы с эталоном, а квиз без единого такого вопроса отвечает
`quiz_not_checkable`.

Доступ к курсу перепроверяется на каждом ответе, а не только при создании
попытки: приостановка организации или снятое зачисление посреди квиза иначе не
мешали бы довести попытку до зачёта по курсу, которого у ученика уже нет.
Проверка идёт раньше остальных, поэтому у отозванного доступа `not_enrolled` /
`organization_suspended` придёт и на вопрос не из попытки.

Ответ на вопрос с вариантами — идентификаторы из `options`, строкой (`"2"`,
`"1,3"`) или списком. Текст варианта тоже принимается и сопоставляется с его
идентификатором: модели передают текст вместо номера, а отказ из-за формата
ученик воспримет как «ответил неверно». Идентификаторы важнее текста — у
варианта может быть текст «3», а `"1,3"` остаётся номерами; ответ целиком
сверяется с текстом варианта раньше, чем режется по запятым. Совпадение
множеств выбранных и верных вариантов строгое при любом формате. Свободный ввод сверяется без учёта регистра и
лишних пробелов.

## `lms_frappe_app.api.student.artifact`

Документы курса, которые ученик собирает по ходу обучения, — перечень или
один документ целиком. Один метод и на обзор, и на чтение: два метода для
одного вопроса агент выбирает наугад.

**Параметры:** `course`, `artifact` (необязательный) — ключ документа, `space`
(необязательный) — чей документ.

Без ключа — перечень с долей заполненности:

```json
{ "ok": true, "data": { "course": "course-p3", "space": "org-1", "artifacts": [
  { "artifact": "project_summary", "title": "Резюме проекта",
    "purpose": "Проект на одной странице — чтобы все договорились об одном и том же.",
    "layout": "sections", "modified": "2026-09-28T22:14:42.064609+05:00",
    "blocks_total": 6, "blocks_filled": 2 } ] } }
```

`purpose` — одна-две фразы автора курса: зачем ученику этот документ; `null`,
если автор не написал. `modified` — когда документ ученика последний раз
менялся, ISO 8601 со смещением пояса сайта; `null`, пока в нём ничего не
записано (learning-services#462).

С ключом — блоки в порядке схемы; заполненные с текстом, пустые с подсказкой
автора:

```json
{ "ok": true, "data": {
  "space": "org-1", "course": "course-p3", "artifact": "project_summary",
  "title": "Резюме проекта", "layout": "sections",
  "blocks": [
    { "key": "goal_and_benefits", "title": "Цель и ожидаемые выгоды",
      "hint": "Конкретно, без клише", "lesson": "lesson-2", "span": 1,
      "kind": "text", "accept": [], "content": "Открыть седьмую кофейню…",
      "file": null, "url": null, "preview": null },
    { "key": "money", "title": "Финансовый план",
      "hint": "…", "lesson": "lesson-5", "span": 1,
      "kind": "file", "accept": ["xlsx", "csv"], "content": "",
      "file": { "name": "plan.xlsx", "type": "xlsx", "size": 18234,
                "uploaded_at": "2026-09-25T14:02:11", "url": "/private/files/plan.xlsx" },
      "url": null,
      "preview": "| Месяц | Выручка | Расходы |\n| --- | --- | --- |\n| Январь | 100 | 80 |" } ],
  "tables": {}, "fields": {}, "canvas": null,
  "modified": "2026-09-28T14:32:05+05:00", "version": 37 } }
```

Документ с таблицей (learning-services#330) — у блока с полями и колонками
есть `fields` (со значениями), `table`, `columns`, `filled` и `empty_cells`;
строки — в `tables` документа:

```json
{ "ok": true, "data": {
  "course": "course-risk", "artifact": "risk_register",
  "title": "Реестр рисков проекта", "layout": "sections",
  "blocks": [
    { "key": "assessment", "title": "Оценка", "hint": "…", "lesson": "lesson-3",
      "span": 1, "kind": "text", "accept": [], "content": "", "file": null,
      "url": null, "preview": null,
      "fields": [ { "key": "threshold", "title": "Порог внимания",
                    "type": "number", "required": true, "value": 12 } ],
      "table": "register",
      "columns": [ { "key": "probability", "title": "Вероятность", "type": "scale",
                     "min": 1, "max": 5, "required": true }, "…" ],
      "filled": true, "empty_cells": [] } ],
  "tables": { "register": {
    "name": "register", "title": "Реестр", "owner": "risks", "prefix": "R",
    "columns": [ { "key": "event", "title": "Событие", "type": "text",
                   "required": true, "block": "risks" }, "…" ],
    "views": [ { "type": "matrix", "x": "impact", "y": "probability",
                 "highlight": "in_work", "title": "" } ],
    "rows": [ { "id": "R1", "event": "Подрядчик уйдёт на другой объект",
                "probability": 4, "impact": 4, "rank": 16, "in_work": true } ],
    "preset": false,
    "markdown": "| ID | Событие | … |\n| --- | --- | … |\n| R1 | Подрядчик уйдёт на другой объект | … |" } },
  "fields": { "threshold": 12 }, "canvas": null,
  "modified": "2026-09-28T14:32:05+05:00", "version": 37 } }
```

`tables` — таблицы документа: колонки всех блоков по порядку схемы (у
колонки — `block`, чей это вклад), `owner` — блок, который заводит строки,
строки с посчитанными формулами и `markdown` — таблица текстом для агента.
Типы колонок: `text`, `longtext`, `number`, `scale` (целое от `min` до `max`,
`labels` — таблица документа с подписями делений), `date` (ISO), `select`
(`options`), `ref` (ID строки таблицы `ref`), `check` (с пределом `max`),
`formula` (считает сервер). `preset` — строки таблицы ещё нетронутая
заготовка автора. `required` у колонки — `true` или ключ колонки,
при истинном значении которой клетка обязательна. Пустая формула — не ноль,
а «ещё не посчитано». `fields` документа — значения полей всех блоков.

Поле тоже бывает формулой (learning-services#351): `{"key": "clients_needed",
"title": "Клиентов нужно", "type": "formula", "formula": "stage_goal / price"}`.
Его значение считает сервер при каждом чтении и не хранит: в `fields`
документа, в `fields[].value` блока, в выгрузке markdown и xlsx (в шапке книги
— значением). Формулы полей считаются в порядке схемы — формула видит ввод
всех полей и формулы выше себя; формулы колонок видят посчитанные поля. Число
приходит целым, если оно целое (`60`, а не `60.0`), сравнение — `true` или
`false`, пустой операнд — `null`. Формула поля — не ввод: заполненность блока
и `empty_cells` на неё не смотрят.

`canvas` — холст документа, у документа без холста `null`
(learning-services#351):

```json
{ "grid": [ "problem solution uvp unfair segments",
            "problem metrics uvp channels segments",
            "costs costs revenue revenue revenue" ],
  "labels": { "problem": "Проблема", "uvp": "Обещание" },
  "sketch": "first_sketch",
  "summary": { "problem": [ "problem", "alternative", "solution" ] } }
```

`grid` — строки сетки, в строке — ключи блоков документа через пробел, `.` —
пустая ячейка; область блока — прямоугольник, так что сетка уходит в CSS
`grid-template-areas` как есть. `labels` — короткие подписи ячеек по ключу
блока (`{}`, если подписей нет). `sketch` — ключ блока, поля которого держат
первый набросок: поле с ключом ячейки — её «как было»; в сетке этого блока нет
(`null`, если наброска нет). `summary` — какие поля документа и колонки
таблицы блока показать в ячейке (`{}`, если сводки нет). Холст — только
раскладка: блоки, их значения и заполненность те же, что в `blocks`.

Блок с полями и колонками заполнен, когда заполнены его обязательные поля,
в таблице есть строки и у каждой строки непусты обязательные колонки блока.
Пока у блока нет ни одного значения, заполненностью считается его текст:
так документ, собранный до таблиц, не теряет прогресса. `empty_cells` —
чего не хватает: `{row, column}` или `{field}`.

`kind` — вид блока: `text` — markdown в `content`; `file` — файл ученика
(таблица, журнал) и текст рядом с ним; `link` — ссылка на внешний документ
(`url`) и текст рядом. `accept` — расширения, которые принимает блок-файл.
У файла — `file` со сведениями о нём и `preview`: шапка и первые строки
таблицы (`csv`, первый лист `xlsx`) markdown-текстом, по которому агент
сверяет готовность, не открывая файл. Строк в срезе — `artifact_preview_rows`
из `Agent Learning Settings`; у ячейки с формулой без сохранённого значения в
срезе стоит сама формула. Файл загружает ученик на странице «Мои документы»
(`upload_artifact_file`); скачивается он по `file.url` и открывается только
ученику — права `File` Frappe берёт у документа. Заполнен блок, где есть
текст, файл или ссылка.

`modified` — когда документ ученика менялся в последний раз (ISO 8601 со
смещением пояса сайта), `version` —
сколько раз он сохранялся (по журналу изменений Frappe); у документа, который
ещё не заводился, — `null` и `0`. Самой истории метод не отдаёт.

Документы идут в порядке, в каком автор их впервые объявил; правка схемы
порядка не меняет. Блок, убранный автором из схемы, в ответ не попадает, но
его содержимое остаётся в базе и вернётся вместе с блоком.

**Отказы:** `not_enrolled`, `organization_suspended`, `artifact_not_found`.

## `lms_frappe_app.api.student.update_artifact`

Записывает блок документа целиком.

**Параметры:** `course`, `artifact`, `key`, `content` (markdown), `clear`
(необязательный, по умолчанию `false`), `url` (необязательный) — адрес у
блока-ссылки, `table` и `file_name` (необязательные) — таблица для блока-файла
и имя файла, `rows`, `delete_rows`, `fields` (необязательные) — строки,
удаления и поля блока с колонками, `space` (необязательный) — в чей документ.

```json
{ "ok": true, "data": { "artifact": "project_summary", "key": "goal_and_benefits",
                        "blocks_total": 6, "blocks_filled": 3,
                        "empty_cells": [], "created": [] } }
```

Посреди занятия — у ученика есть открытое занятие по курсу — в ответе ещё
`objectives_progress`, как у `mark_objective`: документ собирают на занятии, и
это место напомнить об отметках целей (learning-services#409).

```json
{ "ok": true, "data": { "artifact": "project_summary", "key": "goal_and_benefits",
                        "blocks_total": 6, "blocks_filled": 3,
                        "empty_cells": [], "created": [],
                        "objectives_progress": { "marked": 1, "total": 3, "open": [] } } }
```

`empty_cells` — чего не хватает блоку с полями и колонками после записи
(`{row, column}` или `{field}`), у прочих блоков пусто. `created` — ID строк,
которые завела эта запись.

`rows` — у блока с колонками (learning-services#330): список строк
`{"id": "R1", "колонка": значение}` со своими колонками блока. Строка без `id`
заводится — это может только блок, который таблицу заводит (`owner`); ID
выдаёт сервер, номера не переиспользуются. Со `id` — правка своих колонок
строки: названные клетки меняются, прочие остаются; пустое значение клетку
стирает. `delete_rows` — ID строк на удаление, тоже только у хозяина
таблицы. `fields` — `{"поле": значение}` полей блока. Значения приводятся к
типу колонки: «4» у шкалы — 4, «05.03.2027» у даты — `2027-03-05`, вариант
выбора — к написанию из схемы. Всё проверяется до записи: отказ не меняет
документ. `content` рядом — заметка к блоку. `clear` у такого блока стирает и
его поля, и его колонки во всех строках; у хозяина — все строки таблицы.

Замещение, а не дописывание: ученик уточняет уже сказанное, и склейка
превратила бы документ в стенограмму разговора. Экземпляр документа заводится
при первой записи; ключи нормализуются к нижнему регистру.

Сервер проверяет только форму — документ и блок есть в схеме, текст непуст.
Отвечает ли текст подсказке автора, смотрит агент: артефакт **на зачёт не
влияет**, зачёт ставит сервер по квизу, и подыгрывать здесь нечему.

`url` принимает только блок-ссылка (`kind: link`), и только `http://` или
`https://`; текст при ссылке необязателен — прежний остаётся.

`table` принимает только блок-файл (`kind: file`): таблица, которую собрал
агент, — список строк, строка — список ячеек (текст, число, пусто), формула —
строка с `=`: `[["Месяц", "Выручка", "Расходы", "Прибыль"], ["Январь", 100, 80,
"=B2-C2"]]`; допустима и JSON-строкой. Сервер собирает `xlsx` — формулы в нём
остаются формулами — или `csv`, если блок принимает только его, и кладёт
файлом в блок тем же путём, что `upload_artifact_file`, со срезом. Имя файла —
`file_name` или ключ блока, расширение подставляется. `content` рядом
записывается как текст блока. До 500 строк и 50 колонок. `Why:` текст таблицы
в десятки раз дешевле байтов base64 через параметры модели.

`clear: true` очищает блок: его строка удаляется из документа ученика вместе
со ссылкой и файлом, и в `artifact` он снова приходит пустым, с подсказкой
автора. `content` при этом
пуст или не передаётся. Ответ тот же, что у записи; очистка блока, которого
нет, — не отказ. Пустой `content` без `clear` — по-прежнему
`artifact_content_required`: случайная пустая запись блок не стирает.

**Отказы:** `not_enrolled`, `organization_suspended`, `artifact_not_found`,
`artifact_block_not_found`, `artifact_content_required`,
`artifact_clear_with_content` — `clear` вместе с непустым `content` или `url`;
`artifact_kind_mismatch` (с `kind`) — `url` у блока, который не ссылка, или
`table` у блока, который не файл; `artifact_invalid_url` — адрес не `http(s)`;
`artifact_invalid_table` — таблица не список строк, ячейка не текст и не
число или таблица больше предела (с `max_rows`, `max_columns`);
`artifact_file_type` — блок-файл не принимает ни `xlsx`, ни `csv`;
`artifact_unknown_column` (с `columns`) и `artifact_unknown_field` (с
`fields`) — колонки или поля нет у этого блока; `artifact_unknown_row` —
строки с таким `id` нет; `artifact_rows_owner_only` (с `owner`) — строку
заводит или удаляет не хозяин таблицы; `artifact_invalid_value` (с `column` или
`field`) — значение не подходит типу: не число, балл вне шкалы, нет такого
варианта, ссылка на несуществующую строку, неверная дата, запись в формулу —
колонку или поле;
`artifact_too_many_checked` (с `max`) — отмечено больше флажков, чем
допускает колонка; `artifact_too_many_rows` — больше 200 строк.

Документ принадлежит пространству: личному или организации, давшей курс.
Пространство определяется при первой записи — курс назначен организацией
ученика, значит её, иначе личное — и дальше не меняется: начатый документ
остаётся там, где начат. Личный документ читает только сам ученик. Документ
организации читают ещё её руководители (`Manager`, `Org Admin`) и — если
организация открыла документы всем — её участники; только прямым чтением
записи, методов отчётности с содержимым документа нет. Ушедший из организации
свой документ в ней читает, организация — тоже. `Why:` доступ решает
пространство документа, а не общая организация руководителя и ученика:
человек учится лично и в нескольких компаниях (learning-services#341).

## `lms_frappe_app.api.student.upload_artifact_file`

Кладёт файл ученика в блок-файл документа. Зовёт его страница «Мои документы»
или окно загрузки в чате (MCP Apps), но не модель: байты через её параметры
стоили бы десятки тысяч токенов на файл, а окно передаёт их скрытым от модели
инструментом.

**Параметры:** `course`, `artifact`, `key` и сам файл — полем `file` формы
`multipart/form-data` (так шлёт страница) или парой `file_name` + `content` —
содержимое в base64, префикс `data:…;base64,` допустим (так передаёт MCP-сервис
из окна загрузки в чате). Битый base64 — `artifact_file_missing`. `space`
(необязательный) — в чей документ.

```json
{ "ok": true, "data": { "artifact": "plan", "key": "money",
  "file": { "name": "plan.xlsx", "type": "xlsx", "size": 18234,
            "uploaded_at": "2026-09-25T14:02:11", "url": "/private/files/plan.xlsx" },
  "preview": "| Месяц | Выручка | Расходы |\n| --- | --- | --- |\n| Январь | 100 | 80 |",
  "blocks_total": 3, "blocks_filled": 1 } }
```

Файл приватный и привязан к документу ученика: права на него Frappe берёт у
документа — кто читает документ, тот открывает и файл. Новый файл замещает прежний, прежний удаляется. Срез (`preview`)
считается сразу при загрузке; для файла, который не таблица, или нечитаемой
таблицы — `null`, а файл всё равно сохраняется.

**Отказы:** `not_enrolled`, `organization_suspended`, `artifact_not_found`,
`artifact_block_not_found`; `artifact_kind_mismatch` (с `kind`) — блок не
принимает файлы; `artifact_file_missing` — файл не передан или пуст;
`artifact_file_type` (с `accept` и `received`) — расширение не из допустимых;
`artifact_file_too_large` (с `max_bytes` и `size`) — больше
`artifact_file_max_mb` из `Agent Learning Settings`.

## `lms_frappe_app.api.student.homework`

Домашнее задание урока и сдача ученика в пространстве (learning-services#439).
Зовут страница урока и окно загрузки файлов в чате.

**Параметры:** `lesson`, `space` (необязательный) — чья сдача.

```json
{ "ok": true, "data": {
  "space": "org-1", "lesson_url": "/lms/courses/course-p3/learn/2-1",
  "homework": { "lesson": "lesson-6", "title": "Встреча со спонсором",
    "description": "Проведите встречу и опишите итог…", "answer_mode": "text_and_files",
    "due": { "mode": "relative", "days": 5, "date": null } },
  "submission": { "id": "a1b2c3d4e5", "status": "Submitted",
    "due_at": "2026-10-06T14:02:11", "overdue": false, "version": 2,
    "assigned_at": "2026-10-01T14:02:11", "submitted_at": "2026-10-02T09:15:40",
    "answer": "Встретился, договорились о бюджете…",
    "files": [ { "id": "f1a2b3c4d5", "name": "protocol.pdf", "type": "pdf", "size": 48213,
                 "uploaded_at": "2026-10-02T09:15:40", "url": "/private/files/protocol.pdf" } ],
    "history": [
      { "event": "assigned", "by": "pupil@example.com", "by_name": "Анна Петрова",
        "at": "2026-10-01T14:02:11",
        "version": null, "comment": null, "due_at": "2026-10-06T14:02:11" },
      { "event": "returned", "by": null, "by_name": "Ирина Смирнова",
        "at": "2026-10-01T21:10:00",
        "version": 1, "comment": "Не хватает решения по бюджету", "due_at": null },
      { "event": "submitted", "by": "pupil@example.com", "by_name": "Анна Петрова",
        "at": "2026-10-02T09:15:40",
        "version": 2, "comment": null, "due_at": null } ],
    "versions": [ { "version": 1, "saved_at": "2026-10-01T20:00:00",
                    "answer": "Черновик…", "files": [] },
                  { "version": 2, "saved_at": "2026-10-02T09:15:40",
                    "answer": "Встретился, договорились о бюджете…", "files": [ { "id": "f1a2b3c4d5",
                      "name": "protocol.pdf", "type": "pdf", "size": 48213,
                      "uploaded_at": "2026-10-02T09:15:40", "url": "/private/files/protocol.pdf" } ] } ] } } }
```

**Задание** — одно на урок, от автора, одинаковое для всех. `answer_mode` —
какие поля есть у ответа: `text`, `files` или `text_and_files`. `due.mode` —
`none` (без срока), `relative` (`days` дней после закрытия урока) или
`absolute` (до конца дня `date` по времени платформы). У урока без задания
`homework: null` — это не отказ: страница урока зовёт метод всегда.

**Сдача** — одна на задание, ученика и пространство; `null`, пока ученик не
сохранял ответ и урок не закрывался. Задание выдаётся закрытием урока — сданным
квизом или `complete_lesson`: фоном, через несколько секунд после ответа,
появляется сдача `Assigned` с `assigned_at` и сроком. Статусы: `Assigned` — выдана, `Submitted` — сдана, `Returned` — на
доработке, `Accepted` — принята. `due_at` — выставленный срок; относительный
считается при выдаче и потом не пересчитывается. `overdue` — признак, а не
статус: срок прошёл, а статус `Assigned` или `Returned`. `history` — журнал
событий `assigned`, `submitted`, `returned`, `accepted`, `reopened`: `by` —
почта автора, только если событие ваше (по ней страница пишет «Вы»), у
событий куратора — `null`; `by_name` — имя автора (у своих без имени — почта,
у куратора без имени — «Куратор»); `comment` — у действий куратора.
`versions` — снимок ответа на каждое сохранение, файлы старых версий остаются
доступными. `id` файла передаётся в `remove_files` метода `submit_homework`.

Домашка ничего не блокирует: ни следующий урок, ни завершение курса.

**Отказы:** `lesson_not_found`, `not_enrolled`, `organization_suspended`,
`space_not_available`, `course_not_in_space`.

Домашки ученика в пространстве — со статусами, сроками и последним
комментарием куратора.

**Параметры:** `course` (необязательный) — только этого курса; `lesson`
(необязательный) — одна домашка урока целиком; `space` (необязательный).

```json
{ "ok": true, "data": { "space": "org-1", "items": [
  { "id": "a1b2c3d4e5", "course": "course-p3", "course_title": "Управление проектами",

    "status": "Returned", "due_at": "2026-10-06T14:02:11", "overdue": false,
    "version": 2, "last_comment": "Не хватает решения по бюджету" } ] } }
```

Свежие сверху. `last_comment` — комментарий последнего возврата на доработку
или отмены приёма. С `lesson` строка одна и несёт ещё `homework` — задание, как у
`homework`, — и `submission` — сдачу целиком, без `versions`. Домашки курсов,
на которые ученик больше не записан, в перечень не попадают.

**Отказы:** `lesson_not_found`, `not_enrolled`, `organization_suspended`,
`space_not_available`, `course_not_in_space`.

## `lms_frappe_app.api.student.submit_homework`

Сохраняет ответ на домашку — сдаёт или правит. Каждый вызов — новая версия и
статус `Submitted`; сохранение до закрытия урока заводит сдачу сразу в
`Submitted`.

**Параметры:** `lesson`; `answer` (необязательный) — текст ответа целиком, не
передан — остаётся прежним; `space` (необязательный); `remove_files`
(необязательный) — `id` файлов, которые убрать из ответа; новые файлы — полями
`file` формы `multipart/form-data` (так шлёт страница урока) или списком
`files` из `{ "name": "protocol.pdf", "data": "<base64>" }` (так передаёт
MCP-сервис из окна загрузки в чате). Убранный файл не удаляется: на него
ссылаются прежние версии.

```json
{ "ok": true, "data": { "space": "org-1",
  "submission": { "id": "a1b2c3d4e5", "status": "Submitted", "due_at": null,
    "overdue": false, "version": 1, "assigned_at": null,
    "submitted_at": "2026-10-02T09:15:40", "answer": "Встретился…",
    "files": [],
    "history": [ { "event": "submitted", "by": "pupil@example.com", "by_name": "Анна Петрова",
                   "at": "2026-10-02T09:15:40",
                   "version": 1, "comment": null, "due_at": null } ],
    "versions": [ { "version": 1, "saved_at": "2026-10-02T09:15:40",
                    "answer": "Встретился…", "files": [] } ] } } }
```

Ответ не пустой — есть текст или файл — и несёт только поля из `answer_mode`.
Неполный ответ (`text_and_files` без файлов) принимается: оценки нет, его
видит и возвращает куратор. Пределы: не больше 10 файлов в ответе, размер
файла — `artifact_file_max_mb` из `Agent Learning Settings`, за одно
сохранение — не больше 30 МБ новых файлов; тип — любой, кроме запрещённых
Frappe.

**Отказы:** `lesson_not_found`, `not_enrolled`, `organization_suspended`,
`space_not_available`, `course_not_in_space`; `no_homework` — у урока нет
задания; `empty_answer` — нет ни текста, ни файлов; `answer_mode` (с
`answer_mode`) — в ответе поле, которого у задания нет; `too_many_files` (с
`limit`); `file_missing` (с `file`) — файл не передан или пуст (в том числе
битый base64); `invalid_files` — `files` не список объектов `{ name, data }` или
`remove_files` не список `id`; `file_too_large` (с `file` и `limit_mb`) — больше
нашего предела или предела Frappe; `answer_too_large` (с `limit_mb`) — новых
файлов больше предела сохранения; `file_rejected` (с `file`) — Frappe не
принял файл; `accepted_locked` — домашку уже приняли; `busy` (с `lesson`) —
ту же сдачу в этот момент сохраняет другой запрос, ничего не сохранено:
повторите вызов. Отказ по файлу ничего не
сохраняет: ни ответа, ни других файлов этого вызова.

## `lms_frappe_app.api.student.remember`

Записывает об ученике то, что пригодится на следующих занятиях. Записанное
возвращается в `student_context` при каждом `start_lesson`.

**Параметры:** `kind` — `fact`, `observation` или `project`; `key` — короткий
повторяемый ключ (`role`, `pace`, `scenario`); `text`; `session` — обязателен
для наблюдения и проекта.

Факт живёт у ученика целиком — роль и отрасль от предмета не зависят.
Наблюдение (как учится) и проект (на чём учится: свой проект, учебный
сценарий, роль в нём) привязываются к курсу занятия, поэтому без `session` их
записать нельзя. `Why:` учебный сценарий одного курса, записанный фактом,
молча приходил в другой (learning-services#408). Ключи нормализуются к нижнему
регистру.

```json
{ "ok": true, "data": { "key": "role", "kind": "fact" } }
```

С `session` открытого занятия в ответе ещё `objectives_progress`, как у
`mark_objective`: запоминают посреди занятия, там же напоминание об отметках.

```json
{ "ok": true, "data": { "key": "pace", "kind": "observation",
                        "objectives_progress": { "marked": 0, "total": 2, "open": [] } } }
```

Запись по существующему ключу **замещает** текст, а не заводит вторую: ключ и
есть способ уточнить уже сказанное.

В одном наборе — факты ученика, наблюдения одного курса, проект одного курса — помещается
`student_notes_limit` ключей из `Agent Learning Settings`. Упор в предел —
отказ; замещение записи по существующему ключу предела не двигает.

Факты по ключам профиля (набор отдаёт `my_profile`) в предел не входят: по
ним `remember` не отказывает, и в счёте прочих фактов они не участвуют.
`Why:` ученик с полным набором прочих фактов иначе не смог бы заполнить
профиль (learning-services#463). Набор фиксирован, так что предел остаётся
конечным.

**Отказы:** `unknown_note_kind` (с `kind`) — вид не `fact`, `observation` или
`project`; `note_key_required` (с `key`) — ключ пустой; `not_your_session` —
наблюдение или проект без `session` или по чужому занятию; `note_limit_reached` (с `limit`) — набор
заполнен.

## `lms_frappe_app.api.student.my_notes`

Что агент запомнил об ученике. Те же заметки, что приходят в
`student_context` от `start_lesson`, — без переноса целей.

**Параметры:** `course` (необязательный) — добавляет к фактам наблюдения и
проект этого курса; без него приходят факты, а все проекты — в
`projects_elsewhere`.

```json
{ "ok": true, "data": {
  "facts": [ { "key": "role", "text": "Руководитель отдела",
               "since": "2026-09-01T12:20:00",
               "updated": "2026-09-02T09:10:00" } ],
  "observations": [ { "key": "pace", "text": "Считает в уме быстрее, чем пишет",
                      "since": null, "updated": "2026-09-02T09:10:00" } ],
  "project": [],
  "projects_elsewhere": [ { "key": "scenario",
                            "text": "Учебный сценарий «Северный склад»",
                            "since": null, "updated": "2026-09-24T21:26:04",
                            "course": "course-risks",
                            "course_title": "Риски проекта" } ] } }
```

`project` — проект этого курса. `projects_elsewhere` — проекты других курсов,
пока у этого своего нет: агент спрашивает, берём ли тот же или у ученика свой,
а не подставляет его молча.

`since` — когда факт записали впервые; у наблюдения его нет. `updated` —
когда текст замещали последний раз. Даты наружу не для красоты: наблюдение
трёхмесячной давности и вчерашнее — разные утверждения.

**Отказов нет.**

## `lms_frappe_app.api.student.my_profile`

Профиль ученика: факты агента по блокам и заполненность. Своих полей у
профиля нет — это фиксированный набор ключей фактов (`kind = fact`), тех же,
что пишет `remember` и отдаёт `my_notes`. Правится профиль теми же
`remember` и `forget`. `Why:` отдельные поля профиля разошлись бы с фактом
`role`, который агент и так пишет на уроках (learning-services#463).

**Параметры:** `user` (необязательный) — чей профиль, без него свой;
`summary` (необязательный) — `1`, чтобы получить только заполненность.

```json
{ "ok": true, "data": {
  "user": "ivanov@example.com", "full_name": "Иван Иванов", "user_image": null,
  "blocks": [ { "id": "work", "title": "Контекст работы", "facts": [
      { "key": "role", "label": "Роль", "text": "Руководитель отдела продаж",
        "updated": "2026-10-01T12:00:00" },
      { "key": "industry", "label": "Отрасль", "text": null, "updated": null } ] } ],
  "other_facts": [ { "key": "language", "text": "Пишет на Python",
                     "updated": "2026-09-20T18:40:00" } ],
  "filled": 1, "total": 9, "complete": false,
  "interview_url": "https://lms.example.com/chat?mode=profile" } }
```

`blocks` — блоки профиля по порядку, в каждом все ключи блока, заполненные
или нет: у пустого `text` и `updated` — `null`. `title` и `label` — подписи
на языке пользователя. Набор блоков и ключей потребитель берёт из ответа и
своей копии не держит. `other_facts` — факты вне набора, свежие сверху; подписей у них
нет — ключ придумал агент. Наблюдения и проекты курсов в профиль не входят:
они про курс, а не про человека.

`filled` — сколько ключей набора заполнено, `total` — сколько их всего,
`complete` — заполненных не меньше порога, и подсказку «заполните профиль»
пора гасить.

`interview_url` — адрес интервью с агентом о профиле в веб-чате. Только у
своего профиля и только когда у установки есть сервис агента, иначе `null`.

С `summary=1` — одна заполненность, без фактов: её читает сайдбар на каждой
загрузке.

```json
{ "ok": true, "data": { "filled": 5, "total": 9, "complete": false,
                        "interview_url": "https://lms.example.com/chat?mode=profile" } }
```

Чужой профиль видят только роли платформы (`System Manager`, `Administrator`,
`Agent Service`) — те же, что видят заметки агента. Руководителю организации
и автору курсов (`Moderator`) — отказ. `Why:` ученик честнее говорит о цели и
уровне, если это не уходит начальнику, и профиль не сдвигает границу, которую
держат заметки.

**Отказы:** `not_your_profile` (с `user`) — чужой профиль без роли платформы,
в том числе по несуществующему логину: отказ не подтверждает, есть ли такой
человек; `user_not_found` (с `user`) — роли платформы, когда такого
пользователя нет.

## `lms_frappe_app.api.student.my_reports`

Репорты с занятий ученика: что с ними стало и что ответили. Свежие сверху, не
больше 50.

**Параметры:** `course` (необязательный) — только репорты этого курса.

```json
{ "ok": true, "data": { "reports": [
  { "id": "8f3c1a…", "kind": "material_issue", "lesson": "lesson-5",
    "lesson_title": "Критический путь", "objective": null,
    "text": "В примере перепутаны сроки задач",
    "reported_at": "2026-09-01T13:02:00", "status": "fixed",
    "resolution": "Пример переписали: сроки задач сверены с диаграммой",
    "resolved_at": "2026-09-02T10:15:00" } ] } }
```

`status` — `new`, `in_progress`, `fixed`, `rejected` или `duplicate`.
`resolution` — ответ ученику от того, кто разбирал репорт; у дубля без своего
ответа — ответ репорта, дублем которого он признан. `resolution` и
`resolved_at` — `null`, пока их нет. `objective` — цель урока, о которой был
репорт, если агент её назвал.

**Отбираются репорты занятий ученика, а не записи от его имени**: репорт,
перенесённый сотрудником платформы, остаётся репортом ученика. Прав на сам
`Agent Course Report` у ученика нет — читать его можно только этим методом.
Занятие и вопрос квиза наружу не идут.

**Отказов нет.**

## `lms_frappe_app.api.student.get_my_progress`

Сводка по себе в пространстве: сколько курсов, сколько просрочено, доля
пройденного, документы и последние занятия.

**Параметры:** `space` (необязательный).

```json
{ "ok": true, "data": { "space": "personal",
  "courses_total": 3, "courses_overdue": 1,
  "courses": [ { "id": "course-basics", "title": "Основы", "deadline": "2026-09-15",
                 "overdue": false, "completion": 0.42,
                 "documents": [ { "artifact": "summary", "title": "Резюме проекта",
                                  "purpose": "Проект на одной странице.",
                                  "layout": "sections",
                                  "modified": "2026-09-28T22:14:42.064609+05:00",
                                  "blocks_total": 6, "blocks_filled": 4 } ] } ],
  "recent_sessions": [ { "lesson": "lesson-6", "status": "Completed",
                         "started_at": "2026-09-01T12:20:00" } ] } }
```

`completion` — доля пройденных уроков курса, округлённая до сотых.
`documents` — документы курса и сколько блоков в них заполнено, как в перечне
`artifact`; отдельно от `completion`, потому что урок засчитывает квиз, а не
документ. У курса без документов — пустой список.
`documents` — документы этого пространства. `recent_sessions` — последние
занятия ученика в этом пространстве, свежие вперёд.

**Отказов нет.**

## `lms_frappe_app.api.student.chat_state`

Сохранённое состояние разговора веб-чата по своему занятию. Формат знает только
тот, кто его записал: backend хранит строку и не разбирает её.

**Параметры:** `session`.

```json
{ "ok": true, "data": { "session": "sess-01H…", "state": "{…}", "version": "1" } }
```

До первого сохранения `state` и `version` — `null`.

**Отказы:** `not_your_session`.

## `lms_frappe_app.api.student.save_chat_state`

Замещает состояние разговора по своему занятию. Одна запись на занятие.

**Параметры:** `session`, `state` — строка JSON, `version` — версия формата
состояния (сменилась — потребитель отбрасывает запись).

```json
{ "ok": true, "data": { "session": "sess-01H…", "version": "1" } }
```

Статус занятия не проверяется: квиз закрывает занятие посреди хода, а
состояние пишется после, и отказ терял бы последний ответ агента.

**Отказы:** `not_your_session`, `invalid_chat_state` — `state` не строка JSON.

Записи состояния не читаются напрямую ни учеником, ни руководителем, и ни один
метод отчётности их не отдаёт. `Why:` переписка — не отчётность, а внутри
состояния лежат результаты инструментов, включая директиву; ничего сверх того,
что ученик и так получает `start_lesson`, там нет, эталонов — тоже.

## `lms_frappe_app.api.student.scenario_state`

Сохранённый разговор сценария вне урока — своего. Сценарий — разговор с
агентом в боковой панели, не привязанный к занятию: интервью о профиле
(`profile`), позже знакомство с платформой. Урочный разговор живёт в
`chat_state`: его ключ — занятие. Формат знает только тот, кто его записал.

**Параметры:** `key` — ключ сценария: латиница в нижнем регистре, цифры, `_`
и `-`, начинается с буквы, до 32 знаков.

```json
{ "ok": true, "data": { "key": "profile", "state": "{…}", "version": "1" } }
```

До первого сохранения и после сброса `state` и `version` — `null`.

**Отказы:** `invalid_scenario_key` (с `key`).

## `lms_frappe_app.api.student.save_scenario_state`

Замещает разговор сценария. Одна запись на ученика и сценарий; счётчик ходов
не трогает.

**Параметры:** `key`, `state` — строка JSON, `version` — версия формата
состояния (сменилась — потребитель отбрасывает запись).

```json
{ "ok": true, "data": { "key": "profile", "version": "1" } }
```

**Отказы:** `invalid_scenario_key` (с `key`), `invalid_chat_state` (с `key`) —
`state` не строка JSON; `busy` (с `key`) — запись разговора в этот момент
меняет другой запрос, и повтор на новом снимке тоже не прошёл: повторите
вызов.

## `lms_frappe_app.api.student.reset_scenario_state`

Начинает разговор сценария заново: стирает `state` и `version`. Нечего
стирать — тоже успех.

**Параметры:** `key`.

```json
{ "ok": true, "data": { "key": "profile" } }
```

Счётчик ходов сброс не трогает. `Why:` иначе лимит ходов обходился бы кнопкой
«начать заново».

**Отказы:** `invalid_scenario_key` (с `key`); `busy` (с `key`) — запись
разговора в этот момент меняет другой запрос, и повтор на новом снимке тоже не
прошёл: повторите вызов.

## `lms_frappe_app.api.student.count_scenario_turn`

Засчитывает ход сценария и отвечает, сколько ходов сделано в текущем окне.
Сколько ходов позволено, решает вызывающий: метод только считает.

**Параметры:** `key`.

```json
{ "ok": true, "data": { "key": "profile", "turns": 3 } }
```

Окно — 24 часа от первого хода окна: истекло — следующий ход открывает новое
окно и считается первым (`1`). `Why:` лимит навсегда закрыл бы сценарий
ученику, который вернётся к нему через полгода. Счётчик хранится в базе, а не
в памяти сервиса, и рестарт его не обнуляет. Ход засчитывается отдельным
вызовом, а не перезаписью вместе с разговором: перезапись затёрла бы ход,
засчитанный параллельно.

Два хода разом база стенда (снимочная изоляция MariaDB) разводит
взаимоблокировкой или уникальным индексом; метод откатывает свою транзакцию и
один раз повторяет счёт на новом снимке. То же у `save_scenario_state` и
`reset_scenario_state`.

**Отказы:** `invalid_scenario_key` (с `key`); `busy` (с `key`) — запись
разговора в этот момент меняет другой запрос, и повтор на новом снимке тоже не
прошёл: повторите вызов.

Записи разговоров сценариев не читаются напрямую ни учеником, ни
руководителем, и ни один метод отчётности их не отдаёт — по той же причине,
что и у `save_chat_state`.

# Методы менеджера

Требуют роль `Organization Manager`. Данные ограничивает
`permission_query_conditions` — отдельной проверки прав в методе нет.

## `lms_frappe_app.api.manager.org_report`

**Параметры:** `course` (необязательный), `status` (необязательный), `organization`
(необязательный) — отчёт одной из своих организаций; чужая — пустой `rows`.

```json
{ "ok": true, "data": { "rows": [
  { "user": "ivanov@example.com", "full_name": "Иван Иванов",
    "course": "course-basics", "organization": "Компания",
    "status": "in_progress", "progress": 0.42,
    "deadline": "2026-09-15", "mandatory": true, "overdue": false,
    "last_activity": "2026-09-01T12:20:00",
    "document": { "blocks_total": 11, "blocks_filled": 7 },
    "quiz": { "passed": 4, "first_try": 3 } } ] } }
```

`document` — сколько блоков во всех документах курса и сколько из них заполнил
ученик в пространстве этой организации: личный документ по тому же курсу не
считается. Считаются блоки действующих схем; у курса без документов — нули.
Отдельно от `progress`: урок засчитывает квиз, и без этой пары пройденный курс
с пустым документом не отличить от собранного.

`quiz` — сколько уроков курса сдано и сколько из них с первой попытки. Зачёт —
без ошибок и без лимита попыток, поэтому «сдан» не отличает понявшего от
перебравшего ответы, а номер зачтённой попытки отличает. Попытки считаются во
всех пространствах: прогресс у человека общий; наружу — только числа.

`status` — `not_started`, `in_progress` или `completed`; параметром `status`
выдача сужается до одного из них. Руководителю без организаций приходит
пустой `rows`.

**Отказов нет.**

## `lms_frappe_app.api.manager.student_detail`

Курсы, занятия и попытки квизов по одному ученику своей организации.

**Параметры:** `user`.

```json
{ "ok": true, "data": {
  "user": "ivanov@example.com", "full_name": "Иван Иванов",
  "courses": [ { "id": "course-basics", "title": "Основы",
                 "deadline": "2026-09-15", "overdue": false, "mandatory": true } ],
  "sessions": [ { "lesson": "lesson-6", "course": "course-basics",
                  "status": "Completed",
                  "started_at": "2026-09-01T12:20:00",
                  "finished_at": "2026-09-01T13:05:00",
                  "objectives": [ { "objective": "Понимать разницу между while и for",
                                    "status": "covered" } ] } ],
  "quiz_attempts": [ { "lesson": "lesson-6", "attempt": 1, "status": "Passed",
                       "score": 0.8, "passed": true,
                       "finished_at": "2026-09-01T13:05:00" } ] } }
```

В `courses` только курсы, пришедшие от организаций вызывающего: человек может
состоять в нескольких компаниях, и чужие назначения — как и его самозапись —
руководителя не касаются. `sessions` и `quiz_attempts` — так же: только занятия
в пространствах организаций вызывающего, без личной работы ученика и работы
для другой компании (learning-services#344).

`objectives` — покрытие целей из `report_outcomes`: видно, какие темы
разобраны, а на какие обратить внимание дальше.

Тексты ответов ученика на открытые вопросы **не отдаются**, заметки агента об
ученике и состояние разговора — тем более: отчёт про результат, а не про
содержание диалога. Документы ученика (`artifact`) сюда тоже не идут.

**Отказы:** `not_your_student` — запрошенный ученик не состоит ни в одной
организации вызывающего.

# Методы команды

Страница «Команда» в пространстве организации: участники и документы, которые
они собирают в её пространстве (learning-services#355). Доступ — тот же, что у
самих документов: руководители (`Manager`, `Org Admin`) видят всегда,
участники — если организация открыла документы всем
(`documents_visible_to: members`). Прочим, в том числе ушедшим, — отказ
`team_not_available`. Разговоры с наставником, заметки агента и личные
документы сюда не выходят ни при какой настройке.

## `lms_frappe_app.api.team.team`

Участники организации и курсы, которые она назначала, с документами курсов.

**Параметры:** `organization`.

```json
{ "ok": true, "data": {
  "organization": "org-1", "title": "Кофейни", "can_see_report": true,
  "can_manage": true, "can_change_roles": false, "member_limit": 25,
  "members": [ { "user": "ivanov@example.com", "full_name": "Иван Иванов",
                 "role": "Member", "left": false, "left_on": null } ],
  "courses": [ { "id": "course-p3", "title": "Проекты по P3.express",
                 "documents": [ { "artifact": "project_summary",
                                  "title": "Резюме проекта" } ] } ] } }
```

`members` — действующие, затем ушедшие (`left`, `left_on`): документы ушедших
остаются у организации. `can_see_report` — зрителю открыт отчёт
(`org_report` с `organization`): только руководителю. `can_manage` — зритель
приглашает и отмечает уход (руководитель), `can_change_roles` — меняет роли
(администратор организации, `Org Admin`). `member_limit` — сколько
действующих участников может быть в неподтверждённой организации
(`own_org_member_limit`); `null` — без лимита.

**Отказы:** `team_not_available`.

## `lms_frappe_app.api.team.team_documents`

Документ курса у каждого участника в пространстве организации — по блокам,
для сравнения: что написал каждый в одном и том же блоке.

**Параметры:** `organization`, `course`, `artifact`.

```json
{ "ok": true, "data": {
  "organization": "org-1", "course": "course-p3", "artifact": "project_summary",
  "title": "Резюме проекта",
  "authors": [ { "user": "ivanov@example.com", "full_name": "Иван Иванов",
                 "left": false, "blocks_filled": 4, "blocks_total": 6,
                 "modified": "2026-09-28T14:02:11" } ],
  "blocks": [ { "key": "sponsor", "title": "Спонсор проекта", "entries": [
    { "user": "ivanov@example.com", "full_name": "Иван Иванов", "left": false,
      "filled": true, "content": "Директор по развитию", "file": null,
      "url": null, "table_markdown": null } ] } ] } }
```

Только документы пространства организации: личный документ по тому же курсу и
документ для другой компании не входят. `table_markdown` — у блока с
колонками: таблица документа целиком, markdown. У файла — имя и адрес; права
на файл Frappe берёт у документа.

**Отказы:** `team_not_available`, `course_not_in_organization` — организация
этот курс не назначала, `artifact_not_found`.

## `lms_frappe_app.api.team.create_invite`

Ссылка, по которой вступают в организацию участником (learning-services#363).
Руководитель отправляет её сам — писем платформа не шлёт. Одна ссылка — на
любое число людей. Только `POST`.

**Параметры:** `organization`.

```json
{ "ok": true, "data": { "token": "k3…", "url": "https://lms.example.com/lms/join/k3…" } }
```

**Отказы:** `team_not_available`, `not_allowed` — зритель не руководитель.

## `lms_frappe_app.api.team.invites`

Действующие ссылки организации — чтобы отозвать ненужную.

**Параметры:** `organization`.

```json
{ "ok": true, "data": { "invites": [
  { "token": "k3…", "url": "https://lms.example.com/lms/join/k3…",
    "created_by": "boss@example.com", "created": "2026-09-29T12:00:00" } ] } }
```

**Отказы:** `team_not_available`, `not_allowed`.

## `lms_frappe_app.api.team.revoke_invite`

Отзывает ссылку: по ней больше не вступить, вступившие остаются. Только `POST`.

**Параметры:** `token`.

```json
{ "ok": true, "data": { "token": "k3…", "revoked": true } }
```

**Отказы:** `invite_not_found`, `team_not_available`, `not_allowed`.

## `lms_frappe_app.api.team.invite_info`

Куда ведёт ссылка — страница вступления показывает это до входа, гостю тоже:

## `lms_frappe_app.api.team.allocations`

Назначения организации и курсы, которые она может назначить
(learning-services#365). Только руководителю.

**Параметры:** `organization`.

```json
{ "ok": true, "data": {
  "allocations": [ { "id": "ca-01", "course": "course-p3", "title": "Проекты по P3.express",
                     "whole_team": false, "members": [ "ivanov@example.com" ],
                     "deadline": "2026-10-31", "mandatory": true,
                     "chosen_by_member": false,
                     "homework": [ { "homework": "hw-01", "lesson": "lesson-6",
                                     "lesson_title": "Спонсор проекта",
                                     "title": "Встреча со спонсором",
                                     "author_due": { "mode": "relative", "days": 5, "date": null },
                                     "due": { "mode": "absolute", "days": null, "date": "2026-10-20" } } ] } ],
  "courses": [ { "id": "course-p3", "title": "Проекты по P3.express" } ] } }
```

`chosen_by_member` — курс взял сам сотрудник из каталога организации;
`courses` — опубликованные курсы, открытые организации. Анонсов в `courses`
нет: назначить их нельзя.

`homework` — домашние задания уроков курса в порядке уроков
(learning-services#452): `author_due` — срок автора (как `due` у
`student.homework`), `due` — срок этого назначения, `null` — действует срок
автора. Срок назначения действует для всей его группы и только в пространстве
организации: личная сдача живёт по сроку автора. Если ученика покрывают
несколько назначений организации, берётся ближайший срок. Срок выставляется
сдаче при выдаче (при первом сохранении до выдачи — если все действующие
правила абсолютные) и потом не пересчитывается.

**Отказы:** `team_not_available`, `not_allowed`.

## `lms_frappe_app.api.team.assign_course`

Назначает курс всей команде (`members` пуст — новичок получит курс сам) или
выбранным людям, со сроком и отметкой обязательности. Адресатам уходит письмо
о назначении, один раз. Только `POST`.

**Параметры:** `organization`, `course`, `members` (необязательный — список
учётных записей), `deadline` (необязательный, `ГГГГ-ММ-ДД`), `mandatory`
(необязательный).

```json
{ "ok": true, "data": { "id": "ca-01" } }
```

За несколько дней до срока (`deadline_reminder_days` в `Agent Learning
Settings`, по умолчанию 3; `0` — не напоминать) тем, кто не прошёл курс,
уходит напоминание — тоже один раз. Тот же порог — у напоминания о сроке
домашки; если от выдачи до срока домашки меньше, напоминание уходит в
середине промежутка. На курс, взятый сотрудником самим, писем нет.

**Отказы:** `team_not_available`, `not_allowed`, `course_not_allowed` —
курс организации не открыт, `course_upcoming` — курс анонсирован и ещё
готовится.

## `lms_frappe_app.api.team.update_allocation`

Правит срок, обязательность, сроки домашек и — у поимённого назначения —
список людей. Дописанным уходит письмо; вычеркнутые остаются зачисленными.
Только `POST`.

**Параметры:** `allocation`, `deadline` (пустая строка снимает срок, не
передан — остаётся), `mandatory`, `members`, `homework_due`.

`homework_due` — сроки домашек назначения списком (или строкой JSON):
`[ { "homework": "hw-01", "due_mode": "relative", "due_days": 3 },
{ "homework": "hw-02", "due_mode": "absolute", "due_date": "2026-10-20" } ]`.
Список **заменяет** сроки целиком; `[]` снимает все; `null` или не передан —
сроки остаются. `due_mode` — `relative` (дней после закрытия урока) или
`absolute` (до конца дня по времени платформы); «как у автора» — строки нет.
Сроки, уже выставленные сдачам, не пересчитываются.

```json
{ "ok": true, "data": { "id": "ca-01" } }
```

**Отказы:** `allocation_not_found`, `team_not_available`, `not_allowed`;
`invalid_due` — `homework_due` не список объектов, режим не `relative` и не
`absolute`, у относительного нет дней, у абсолютного — даты, или задание
повторяется; `homework_not_in_course` (с `homework`) — задание не из курса
назначения. Строка задания, которое ушло из курса вместе с уроком,
отклоняется, только если её меняют; неизменённую назначение молча
выбрасывает.

## `lms_frappe_app.api.team.remove_allocation`

**Отказы:** `allocation_not_found`, `team_not_available`, `not_allowed`.

# Методы куратора

Проверка домашек в вебе — очередь «Ждут проверки» и карточка сдачи
(learning-services#452). Все методы — только `POST`.

**Кто проверяет.** Руководитель (роль `Organization Manager`) — сдачи
пространств своих организаций; методист (`Course Creator`) и модератор
(`Moderator`) — все сдачи всех курсов, включая личные пространства. Свою сдачу
не проверяет никто, даже с ролью куратора; архивную (прогресс сброшен) — тоже.
Остальным очередь пуста, а действия отвечают `not_allowed`.

**Ученик** назван полным именем, без имени — почтой: почту ученика куратору
иначе не отдаём. В журнале сдачи (`history`) события самого читателя несут
`by` — его почту, остальные — `by: null` и `by_name`: имя ученика или
«Ученик», имя куратора или «Куратор».

**Проверенная версия** (`reviewed_version`) — `version` последней строки
журнала `returned`, `accepted` или `reopened`; `null` — сдачу ещё не
проверяли. С ней страница сравнивает текущую версию ответа.

**Дайджест.** Раз в день куратору уходит письмо «N домашек ждут проверки» со
ссылкой на очередь — первым ежечасным запуском после 9:00 по времени
платформы, в котором у него есть ожидающие. Руководителю — по его
организациям, модератору — по всем курсам, методисту — только по курсам, где
он в `instructors`. Свои сдачи не считаются; пустая очередь — письма нет.

## `lms_frappe_app.api.review.queue`

Сдачи, которые куратор вправе проверять, — старые сверху.

**Параметры:** `status` — `Submitted` (по умолчанию), `Returned`,
`Accepted` или `Assigned`; `course` (необязательный), `organization`
(необязательный; `personal` — личные пространства), `limit` (по умолчанию и
не больше 50).

Пример — для методиста: ему видны и личные сдачи.

```json
{ "ok": true, "data": {
  "items": [ { "id": "a1b2c3d4e5", "status": "Submitted", "student": { "name": "Анна Петрова" },
               "course": "course-p3", "course_title": "Управление проектами",
               "lesson": "lesson-6", "lesson_title": "Спонсор проекта",
               "title": "Встреча со спонсором",
               "organization": "org-1", "organization_title": "Кофейни Юга",
               "submitted_at": "2026-10-02T09:15:40", "version": 2, "reviewed_version": 1,
               "due_at": "2026-10-06T14:02:11", "overdue": false } ],
  "total": 1,
  "courses": [ { "id": "course-p3", "title": "Управление проектами" } ],
  "organizations": [ { "id": "org-1", "title": "Кофейни Юга" },
                     { "id": "personal", "title": "Личное" } ] } }
```

`total` — сколько сдач под фильтром, `items` — не больше `limit`.
`organization` — имя организации или `personal`, `organization_title` у
личного — «Личное». `courses` и `organizations` — значения для фильтров из всех
видимых куратору сдач, без учёта выбранных фильтров; `personal` в них есть,
только если куратору видны личные. Руководителю фильтр `personal` отдаёт
пустую очередь. `overdue` — как у `my_homework`.

**Отказов нет.**

## `lms_frappe_app.api.review.submission`

Карточка сдачи: задание, ответ с версиями, журнал и действия, доступные сейчас.

**Параметры:** `submission`.

```json
{ "ok": true, "data": {
  "submission": { "id": "a1b2c3d4e5", "status": "Submitted", "due_at": null, "overdue": false,
    "version": 2, "assigned_at": "2026-10-01T14:02:11", "submitted_at": "2026-10-02T09:15:40",
    "answer": "Встретился, договорились о бюджете…", "files": [],
    "history": [ { "event": "returned", "by": null, "by_name": "Ирина Смирнова",
                   "at": "2026-10-01T21:10:00", "version": 1,
                   "comment": "Не хватает решения по бюджету", "due_at": null } ],
    "versions": [ { "version": 1, "saved_at": "2026-10-01T20:00:00",
                    "answer": "Черновик…", "files": [] } ] },
  "homework": { "lesson": "lesson-6", "title": "Встреча со спонсором",
    "description": "Проведите встречу и опишите итог…", "answer_mode": "text_and_files",
    "due": { "mode": "relative", "days": 5, "date": null } },
  "student": { "name": "Анна Петрова" },
  "course": "course-p3", "course_title": "Управление проектами",
  "lesson": "lesson-6", "lesson_title": "Спонсор проекта",
  "lesson_url": "/lms/courses/course-p3/learn/2-1",
  "organization": "org-1", "organization_title": "Кофейни Юга",
  "reviewed_version": 1,
  "actions": [ "accept", "send_back" ] } }
```

`submission` и `homework` — те же формы, что у `student.homework`. `actions`
— что куратор может сделать сейчас: `accept` и `send_back` у сдачи в статусе
`Submitted`, `reopen` — у `Accepted`; пустой список — карточка только для
чтения. Открыть карточку может всякий, кому видна сдача, — и сам ученик;
своя и архивная сдача приходят без действий.

**Отказы:** `submission_not_found`; `not_allowed` — сдача вам не видна.

## `lms_frappe_app.api.review.accept`

Принимает сдачу. Принятую ученик больше не правит.

**Параметры:** `submission`, `version` — версия, которую куратор видел.

```json
{ "ok": true, "data": { "submission": { "id": "a1b2c3d4e5", "status": "Accepted" },
  "homework": { }, "student": { "name": "Анна Петрова" },
  "course": "course-p3", "course_title": "Управление проектами",
  "lesson": "lesson-6", "lesson_title": "Спонсор проекта",
  "lesson_url": "/lms/courses/course-p3/learn/2-1",
  "organization": "org-1", "organization_title": "Кофейни Юга",
  "reviewed_version": 2, "actions": [ "reopen" ] } }
```

Ответ — карточка, как у `submission`, после действия. В журнал пишется строка
`accepted` с версией.

**Отказы:** `submission_not_found`; `not_allowed` — эту сдачу вы не
проверяете или она ваша; `stale_version` (с `version` — текущей) — ученик
сохранил новую версию, посмотрите её; `wrong_status` (со `status`) — сдача не
в `Submitted` или уже неактивна; `busy` — сдачу в этот момент меняет другой
запрос, ничего не сохранено: повторите.

## `lms_frappe_app.api.review.send_back`

Возвращает сдачу на доработку с комментарием: что доделать. Письмо с
комментарием ученику уходит ближайшей ежечасной рассылкой.

**Параметры:** `submission`, `version`, `comment`.

```json
{ "ok": true, "data": { "submission": { "id": "a1b2c3d4e5", "status": "Returned" },
  "homework": { }, "student": { "name": "Анна Петрова" },
  "course": "course-p3", "course_title": "Управление проектами",
  "lesson": "lesson-6", "lesson_title": "Спонсор проекта",
  "lesson_url": "/lms/courses/course-p3/learn/2-1",
  "organization": "org-1", "organization_title": "Кофейни Юга",
  "reviewed_version": 2, "actions": [ ] } }
```

Возвращённую ученик правит, сохранение снова ставит `Submitted` новой
версией. Комментарий — последний комментарий куратора в `my_homework` и
`start_lesson`.

**Отказы:** как у `accept`, и `comment_required` — комментарий пустой.

## `lms_frappe_app.api.review.reopen`

Отменяет ошибочный приём: принятая сдача снова на доработке, с комментарием.

**Отказы:** как у `send_back`; `wrong_status` — сдача не в `Accepted`.

# Методы админки

Кнопки на карточках Desk, а не инструменты агента: в MCP их нет.

## `lms_frappe_app.api.admin.reset_student_progress`

Сбрасывает прогресс ученика по курсу записи — как будто он на курс не
записывался. Кнопка «Сбросить прогресс» на карточке `LMS Enrollment`.

**Параметры:** `enrollment` — запись на курс.

```json
{ "ok": true, "data": {
  "student": "ivanov@example.com", "course": "course-basics",
  "sessions_archived": 2, "attempts_archived": 1, "artifacts_archived": 1,
  "notes_archived": 1, "homework_archived": 1, "runs_archived": 1,
  "progress_deleted": 1, "enrolled_again": false } }
```

Занятия, попытки квиза, документы курса, заметки агента, сдачи домашки и
прохождения уроков по курсу уходят в архив: ученик переносится в
`archived_student` с датой `archived_at`, поле «Ученик» очищается. Методы
учебного потока ищут по ученику и архив не видят — следующее занятие по курсу
открывается как первое (`first_in_course`), лимит попыток квиза полный,
документ пустой, домашка сдаётся заново новой сдачей, урок курса из релиза
проходится заново новым прохождением. Открытые занятия и попытки закрываются
как брошенные. Заметки без курса — общие факты об ученике — не трогаются.

Удаляются отметки пройденного (`LMS Course Progress`), итоги квиза для браузера
(`LMS Quiz Submission`) архивных попыток и сама запись на курс. Если курс
ученику назначила организация, запись выдаётся заново, пустая
(`enrolled_again: true`): иначе обязательный курс пропал бы до пересохранения
назначения.

Репорты не трогаются: `my_reports` находит их и по архивным занятиям, и ответ
автора ученик видит. В карточке пользователя остаётся комментарий: кто, когда
и что сбросил.

Одна транзакция: упало на любом шаге — не изменилось ничего. `Why:` архив, а не
удаление, — решение владельца (learning-services#313): история занятий и
репортов остаётся.

**Права:** администратор платформы (`System Manager`) или автор курса —
преподаватель курса либо модератор, как решает Learning (`can_modify_course`).
Остальным — ошибка прав Frappe.

**Отказы:** `enrollment_not_found`.

# Релиз курса

Курс публикуется целиком — релизом: один JSON-документ формата
`lms-release/1` (learning-services#500). Собирает его компилятор курса вне
платформы; приложение проверяет релиз, хранит снимок новой версией и строит
по нему курс Frappe Learning. Публикует релиз `publish_release`.

Схема публичной и серверной части —
`lms_frappe_app/agent_learning/releases/release.public.schema.json`
(JSON Schema 2020-12). Дом схемы — здесь; копия — у компилятора курса, и
сверяется она с этой.

| Часть | Что | Как с ней обходится приложение |
|---|---|---|
| `format` | `"lms-release/1"` | другой — отказ `release_format_unsupported` |
| `course` | ключ, название, карточка, обещание, корневая цель, атрибуция, глоссарий | карточка — в курсе Learning |
| `chapters` | главы по порядку: ключ, название, описание, уроки | глава Learning по ключу |
| `lessons` | уроки по порядку: ключ, глава, название, зачин, разделы документа, цели с пунктами целей агента, квиз, домашка | урок Learning по ключу; цели, пункты и квиз — в индексе релиза |
| `document` | документ курса: разделы и колонки; `null` — документа нет | схема документа курса |
| `agent`, `map` | пакет агента и карта курса | **непрозрачны**: хранятся в снимке как есть, не разбираются |

Правила:

- **Ключи стабильны.** На ключе держится состояние ученика между релизами;
  переименовать ключ — то же, что удалить узел и завести новый.
- **`lessons[].quiz.answers` — только сервер.** Верный вариант и пояснение не
  уходят ни в один ответ ученику и агенту; пояснение ученик видит после ответа
  — по правилу квиза урока («Квиз урока из релиза»).
  Релиз и его индекс читают только авторские роли.
- **Сверх схемы сервер проверяет** уникальность ключей в своих пространствах,
  ссылки (урок ↔ глава, урок → разделы, вопрос → цель своего урока, ответ →
  вопрос, условие колонки → колонка раздела), порядок уроков по главам, что
  верный вариант — вариант своего вопроса, что документ ложится на движок
  документов (ключи раздела и колонки — латиница в нижнем регистре, поле
  раздела «один раз» не совпадает с другим полем или колонкой) и что названия
  влезают в поля Learning.
- **Раздел документа — блок с тем же ключом.** Раздел `rows: many` — таблица
  блока, `rows: one` — поля блока; ячейки — многострочный текст. Блок
  показывается на уроке, который первым пишет в раздел.
- **Снятое из релиза не удаляется**: урок и глава уходят из программы, запись
  остаётся; вернувшийся ключ получает ту же запись. Программа курса с релизом —
  только главы и уроки релиза.
- **Релиз неизменяем.** Исправление — новый релиз; откат — публикация
  прежнего файла новой версией.

## Состояние ученика по релизу

Прогресс ученика по курсу из релиза держится на ключах релиза, а не на записях
Learning: ученик всегда на действующем релизе, и новый релиз переносит его
состояние по ключам. Здесь — модель; методы ученика и агента над ней придут с
цепочкой инструментов агента.

### Прохождение урока

Прохождение — одно на ученика, курс и ключ урока, общее для всех пространств;
занятия по уроку ссылаются на него. В нём — пункты целей агента
(`lessons[].objectives[].goals`) и цели урока со статусами, которые вычисляет
сервер.

| Что | Статусы | Как получается |
|---|---|---|
| Пункт | `open`, `done`, `planned`, `not_needed` | ставит агент; любой статус, кроме `open`, — со свидетельством; `not_needed` — только у необязательного пункта; вернуть в `open` можно |
| Цель урока | `not_started`, `touched`, `covered` | `covered` — все обязательные пункты цели в `done` или `planned`, `touched` — хоть один; цель без обязательных пунктов — `covered` сразу |
| Урок | `not_started`, `in_progress`, `covered`, `passed` | начат с первой отметки пункта не в `open` и обратно не «расначинается»; `covered` — начат и все цели разобраны; `passed` — урок закрыт (квиз сдан или квиза нет) и пересчётом не снимается |
| Глава | `not_started`, `in_progress`, `passed` | не хранится: `passed` — пройдены все уроки главы, `in_progress` — хоть один начат; считаются только уроки действующего релиза |

Отметка пункта — запись с предупреждением, а не отказ: пункт, отмеченный не по
порядку, пишется, а агент получает, что по цели ещё открыто, и следующий шаг —
первый открытый обязательный пункт урока по порядку релиза. Отказ — на ошибку
формы и на прохождение, которое отмечать нельзя (архивное, чужое занятие, урок
не в релизе).

**Сверка с действующим релизом — по ключам**, при обращении к прохождению и
фоном после публикации нового релиза. Новые пункты — `open`, новые цели —
`not_started`; исчезнувшие снимаются и в статусы не идут, но отметка остаётся:
вернувшийся ключ получает её обратно. Цель пункта, вид, обязательность,
название и порядок — из релиза. Урок исчез из релиза — прохождение читается,
но новое не заводится, пункт не отмечается и квиз не начинается
(`lesson_not_in_release`).

**Прохождение не видят ни ученик, ни руководитель** — ни методом, ни чтением
записи: пункты и свидетельства — инструмент агента. Наружу из прохождения
уходят статусы целей, урока и главы, а не пункты. Сброс прогресса архивирует
прохождения курса, и урок проходится заново (`reset_student_progress`).

### Квиз урока из релиза

Вопросы, верные варианты, пояснения и порог — из `lessons[].quiz` релиза.

- **Снимок вопросов — в попытке.** Попытка снимает все вопросы урока
  действующего релиза по порядку — без верного варианта и пояснения; ответы
  сервер проверяет по релизу попытки, а не по действующему: новый релиз
  посреди попытки её не ломает. Ответ — ключ варианта или его текст.
- **Зачёт:** `верных × 100 ≥ pass_percentage × всего`, порог — урока в релизе
  попытки. Лимит попыток, пауза и обязательность квиза — политика платформы;
  попытки считаются по ученику, курсу и ключу урока.
- **Итог** — доля верных и `objective_results`: верных из всех по каждой цели
  урока. Сданная попытка закрывает урок (`passed`) и подтверждает квизом цели,
  все вопросы которых отвечены верно. «Подтверждено квизом» и статус цели по
  отметкам агента — два разных признака, ни один не выводится из другого.
- **Пояснение** к верному ответу приходит сразу; к неверному — только в итоге
  сданной попытки. Неверный ответ получает лишь `correct: false`, несданная
  попытка — остаток попыток и время пересдачи, без пояснений и верных
  вариантов. `Why:` пояснение к вопросу называет верный вариант, а попытка
  может быть не последней.
- **Ответы попытки** не читает никто, кроме служебных ролей, — ни руководитель,
  ни сам ученик: в записи ответа лежит признак верности. Руководитель видит
  итог попытки.

### Домашка урока из релиза

`lessons[].homework` — часть релиза; публикация переносит её в шаблон домашки
урока, и выдача, сроки и проверка куратором работают как у любой домашки.
Домашка ушла из релиза — шаблон без сдач удаляется, со сдачами снимается:
ученикам без сдачи он не выдаётся и не сдаётся, а выданную домашку ученик
сдаёт и куратор проверяет. Вернулась — снова действует тот же шаблон.

# Методы авторинга

Всё, что ниже, требует роли `Course Creator` или `Moderator`. Вызов без неё
отклоняется **403**, а не кодом отказа: у агента ученика нет сценария, в
котором он что-то с этим сделает, и нарушение доступа должно попадать в
журнал Frappe как нарушение.

Эталоны ответов доступны только здесь и только этим ролям. Правило «эталон не
выходит наружу» остаётся дословным для всех методов ученика.

**Объект, которого нет, — доменный отказ, а не 404.** Каждый метод сначала
проверяет, что переданное существует, и отвечает кодом по виду объекта:
`course_not_found`, `chapter_not_found`, `lesson_not_found`,
`question_not_found` — с полем `id`. `Why:` агент куратора работает с
идентификаторами, полученными из прошлых ответов, и опечатка в ссылке — его
обычная ошибка, а не нарушение доступа: она должна приходить кодом, по
которому он переспросит, а не HTTP-ошибкой.

**Курс из релиза правится только релизом** (learning-services#500). Методы
сборки по кусочку — правка курса, глав, уроков, их порядка, директив, схемы
документа, квиза, домашки и карты — на курсе с действующим релизом отказывают
`course_from_release` (с `course`): правка разошлась бы с релизом и пропала
бы на следующей публикации. Курс правят в карте и публикуют новый релиз
(`publish_release`).

## `lms_frappe_app.api.authoring.course_reports`

Репорты агентов по курсу: что мешает курсу работать.

**Параметры:** `course`; необязательные `kind` (вид репорта), `lesson`,
`limit` (не больше 50, оно же по умолчанию), `status` — `new`, `in_progress`,
`fixed`, `rejected`, `duplicate` или `open` (`new` и `in_progress` вместе).

```json
{ "ok": true, "data": { "course": "p3-express", "reports": [
  { "id": "ACR-00004", "kind": "directive_mismatch", "lesson": "lesson-4",
    "objective": null, "question": null,
    "text": "Много вопросов подряд без вводного объяснения",
    "reported_at": "2026-09-20T19:50:39", "directive_version": 3,
    "status": "fixed", "resolution": "Добавили вводное объяснение перед вопросами",
    "resolved_at": "2026-09-21T11:05:00" } ] } }
```

**Кто пожаловался, не отдаётся.** Куратору нужно, что не так с курсом, а не
кто сказал: имя в выдаче превращает обратную связь в донос и отучает
жаловаться. Занятие и ученик остаются в самой записи — сотрудник платформы
разберётся, если дойдёт до разбирательства.

`directive_version` — редакция директивы урока **на момент жалобы**. Без неё
претензия «указание не подходит» нечитаема: курс с тех пор переписывали, и
непонятно, на что жаловались.

Свежие сверху. `objective` и `question` заполнены, когда репорт был про
конкретную цель или вопрос квиза. `resolution` — ответ ученику, `resolved_at`
— когда репорт получил итог; оба `null`, пока их нет.

**Отказы:** `course_not_found`, `unknown_report_kind` — с перечнем видов в
сообщении; `unknown_report_status` (с `status`).

## `lms_frappe_app.api.authoring.resolve_report`

Сменить статус репорта и ответить ученику.

**Параметры:** `report`, `status`; необязательные `resolution` — ответ,
который увидит ученик, и `duplicate_of` — репорт, дублем которого признан
этот. Только `POST`.

| Было | Можно перевести в |
|---|---|
| `new`, `in_progress` | любой другой статус |
| `fixed`, `rejected`, `duplicate` | только `in_progress` — переоткрыть |

`fixed` и `rejected` требуют непустой `resolution`; `duplicate` — `duplicate_of`
того же курса, не сам репорт. `resolution` пишется заново при каждой смене
статуса: не передан — ответа нет, и переоткрытый репорт не выдаёт ученику
прежний итог за действующий. `duplicate_of` хранится только у дубля.

```json
{ "ok": true, "data": { "id": "ACR-00004", "status": "fixed",
  "resolution": "Добавили вводное объяснение перед вопросами",
  "resolved_at": "2026-09-21T11:05:00", "duplicate_of": null } }
```

`resolved_at` ставится при переходе в `fixed`, `rejected` или `duplicate` и
снимается при переоткрытии. Итог ученик получит в `my_reports` и один раз — в
`student_context.closed_reports` на ближайшем занятии курса; после
переоткрытия новый итог придёт снова.

`Why:` закрытый репорт меняет итог только через переоткрытие: итог уже ушёл
ученику, и молча заменить его другим значило бы переписать то, что он прочёл.

**Отказы:** `report_not_found` (с `id`); `unknown_report_status` (с `status`);
`invalid_report_transition` (с `status` — текущим — и `allowed`);
`report_resolution_required` (с `status`) — `fixed` или `rejected` без ответа;
`duplicate_of_required`; `invalid_duplicate_of` (с `duplicate_of`) — такого
репорта нет, он из другого курса или это сам репорт.

## `lms_frappe_app.api.authoring.list_courses`

Курсы платформы: черновики и опубликованные.

**Параметры:** `published` (необязательный) — `true` оставляет
опубликованные, `false` черновики; без него приходят все.

```json
{ "ok": true, "data": { "courses": [
  { "id": "course-basics", "title": "Основы",
    "summary": "Для тех, кто не программировал", "published": false,
    "upcoming": false, "lessons_total": 12,
    "updated_at": "2026-09-01T12:20:00" } ] } }
```

`upcoming` — курс в каталоге как анонс (`announce_course`); у анонса
`published` тоже `true`.

Список полный, а не «мои»: курсы на платформе общие. Порядок — по времени
последней правки, свежие вперёд.

`Why:` без этого метода сборка разваливается на второй сессии — все остальные
методы требуют идентификатор, а взять его куратору, вернувшемуся назавтра,
негде.

**Отказов нет.**

**Параметры:** `title`, `summary`, `description` (необязательно).

{ "ok": true, "data": { "id": "course-basics", "title": "Основы", "published": false } }

Правит название, материал или зачин урока.

```json
{ "ok": true, "data": { "id": "lesson-1", "title": "Переменные",

```

## `lms_frappe_app.api.authoring.move_lesson`

Переносит урок в другую главу или на другое место в своей.

**Параметры:** `lesson`, `chapter` (необязательно), `position` (необязательно,
считается с единицы; без него — в конец).

```json
{ "ok": true, "data": { "id": "lesson-3", "chapter": "ch-2",
                        "lessons": [ "lesson-7", "lesson-3", "lesson-9" ] } }
```

`lessons` — порядок главы, в которую урок встал, после переноса.

При переносе меняются и `chapter`, и `course` урока: иначе он числился бы в
прежнем курсе, а показывался в новом.

**Отказы:** `lesson_not_found`, `chapter_not_found`.

## `lms_frappe_app.api.authoring.remove_lesson`

Удаляет ошибочно созданный урок вместе с его квизом, директивами и домашним
заданием.

**Параметры:** `lesson`.

```json
{ "ok": true, "data": { "removed": "lesson-3", "chapter": "ch-2",
                        "lessons": [ "lesson-7", "lesson-9" ] } }
```

`lessons` — порядок главы после удаления.

Урок, по которому уже занимались, не удаляется: отказ `lesson_in_use` с
числом записей прогресса (`progress`), занятий (`sessions`), попыток
(`attempts`) и сдач домашки (`homework_submissions`) — приходят только
ненулевые. `Why:` стирание испортило бы
историю зачётов, а курс от лишнего урока не рушится.

Требует роли `Moderator`: Frappe Learning не даёт `Course Creator` право
удалять уроки, хотя главу, квиз и директиву — даёт. Асимметрия чужая, но
обходить её своей проверкой нельзя: агент получил бы то, чего не может тот же
человек в браузере. Отказ приходит **403**, как и любая нехватка роли.

**Отказы:** `lesson_not_found`, `lesson_in_use`.

## `lms_frappe_app.api.authoring.remove_chapter`

Удаляет пустую главу.

**Параметры:** `chapter`.

```json
{ "ok": true, "data": { "removed": "ch-2", "course": "course-basics" } }
```

Непустая глава отклоняется: уроки удаляются поштучно и с проверкой прогресса,
и обходить её каскадом нельзя.

**Отказы:** `chapter_not_found`; `chapter_not_empty` (со списком `lessons`) —
в главе остались уроки.

## `lms_frappe_app.api.authoring.reorder_lessons`

Порядок уроков главы **полным списком**: операция идемпотентна, а состав
сверяется с текущим.

**Параметры:** `chapter`, `lessons`.

```json
{ "ok": true, "data": { "chapter": "ch-2",
                        "lessons": [ "lesson-3", "lesson-7", "lesson-9" ] } }
```

Расхождение состава — отказ `order_mismatch` с полями `expected` и
`received`; порядок остаётся прежним.

**Отказы:** `chapter_not_found`, `order_mismatch`.

## `lms_frappe_app.api.authoring.reorder_chapters`

Порядок глав курса — тем же способом и с той же сверкой состава.

**Параметры:** `course`, `chapters`.

```json
{ "ok": true, "data": { "course": "course-basics",
                        "chapters": [ "ch-2", "ch-1" ] } }
```

**Отказы:** `course_not_found`, `order_mismatch`.

## `lms_frappe_app.api.authoring.set_directive`

Директива преподавателя новой версией. Прошлые снимаются с действия, но не
удаляются: занятие, идущее сейчас, уже получило свою.

**Параметры:** `lesson`, `teaching_directive`, а также `objectives`,
`probing_questions`, `common_misconceptions`, `success_criteria` —
многострочным текстом, строка на пункт.

```json
{ "ok": true, "data": { "id": "AD-00007", "lesson": "lesson-1", "version": 2 } }
```

`objectives` — те самые цели, которые ученик получает в `start_lesson`, по
которым сдаётся `report_outcomes` и без которых отчёт не требуется вовсе.

`objectives` — единственное поле директивы, видимое снаружи: его отдаёт
`course_map`, в том числе гостю. Остальное остаётся на сервере.

**Отказы:** `lesson_not_found`.

## `lms_frappe_app.api.authoring.set_course_directive`

Сквозная директива курса новой версией — то, что одинаково на каждом уроке:
роль и тон преподавателя, формат занятия, кого учим, как называть вещи. Агент
получает её вместе с директивой урока, поэтому повторять её в уроках не нужно.
Прошлые версии снимаются с действия тем же порядком, что у урочной.

**Параметры:** `course`, `teaching_directive`, а также `objectives`,
`student_profile`, `glossary`, `remember_about_student`; списочные — строка на
пункт.

`remember_about_student` — что в этом курсе стоит помнить об ученике между
занятиями. Заметки агент ведёт сам (`remember`), здесь задаётся, чему в них
место. Ученику поле не показывается: оно приходит внутрь `course_directive`,
под пометкой `teacher_only`.

```json
{ "ok": true, "data": { "id": "ACD-00001", "course": "course-basics", "version": 1 } }
```

Курс без директивы даёт предупреждение `course_without_directive` в
`readiness` — публикацию оно не блокирует.

**Отказы:** `course_not_found`.

## `lms_frappe_app.api.authoring.set_course_artifact`

Схема документа, который ученик собирает по ходу курса, — новой версией.
Действующая схема одна на пару «курс + ключ»; прошлые версии снимаются с
действия, как у директив. Содержимое ученика хранится по ключам блоков и
правку схемы переживает: добавленный блок появится пустым, убранный
исчезнет со страницы, не стирая написанного.

**Параметры:** `course`, `artifact` — ключ документа (`project_summary`),
`title`, `blocks`, `layout` — `sections` (столбцом, по умолчанию) или
`canvas` (сеткой по `span`), `canvas` (необязательный) — холст документа,
`purpose` (необязательный) — одна-две фразы ученику: зачем этот документ.
Ученик видит их в «Моих документах» под названием. Не назван — остаётся у
прежней версии; пустая строка убирает (learning-services#462).

```json
{ "blocks": [
  { "key": "goal_and_benefits", "title": "Цель и ожидаемые выгоды",
    "hint": "Конкретно, без клише; готов, когда назван результат",
    "lesson": "lesson-2", "span": 1 },
  { "key": "money", "title": "Финансовый план", "hint": "…",
    "lesson": "lesson-5", "kind": "file", "accept": "xlsx,csv" } ] }
```

`kind` — вид блока: `text` (по умолчанию), `file` — файл ученика, `link` —
ссылка на внешний документ. `accept` — допустимые расширения блока-файла,
строкой через запятую или списком; точки и регистр не важны.

`spec` (необязательно, learning-services#330) — поля блока и его колонки в
таблице документа:

```json
{ "key": "assessment", "title": "Оценка", "lesson": "lesson-3",
  "spec": {
    "fields": [ { "key": "threshold", "title": "Порог внимания",
                  "type": "number", "required": true } ],
    "table": "register",
    "columns": [
      { "key": "probability", "title": "Вероятность", "type": "scale",
        "min": 1, "max": 5, "labels": "probability_scale", "required": true },
      { "key": "rank", "title": "Ранг", "type": "formula",
        "formula": "probability * impact" },
      { "key": "in_work", "title": "В работе", "type": "formula",
        "formula": "rank >= threshold" } ] } }
```

Блоки с одним `table` вносят колонки в одну таблицу; первый такой блок —
хозяин: он заводит строки, у него `prefix` ID строк, `title` таблицы,
`rows` — заготовка строк (шкалы с описанными делениями) и `views` —
`{"type": "matrix", "x", "y", "highlight"}`, `{"type": "report",
"filter", "columns", "field"}` или `{"type": "columns", "title", "columns"}` —
готовый набор колонок широкой таблицы («Кратко», «Признаки»). Типы полей: `text`, `longtext`, `number`,
`date`, `select`, `formula`; колонок — те же и `scale`, `ref`, `check`.
Формула — числа, имена колонок и полей, `+ - * /`, сравнения, `and`, `or`,
`not`, скобки. Формула поля (learning-services#351) ссылается только на поля
документа, а на поле-формулу — только объявленное выше неё: считаются они
одним проходом в порядке схемы. `required` у формулы — отказ: её не
заполняют. Схема проверяется до записи целиком: ключи колонок и полей не
повторяются, `ref` и `labels` ведут на таблицы документа, формулы — на
известные имена, условие `required` — на колонку таблицы.

`canvas` (необязательно, learning-services#351) — холст документа: где на
сетке стоит каждый блок.

```json
{ "grid": [ "problem solution uvp unfair segments",
            "problem metrics uvp channels segments",
            "costs costs revenue revenue revenue" ],
  "labels": { "problem": "Проблема", "uvp": "Обещание" },
  "sketch": "first_sketch",
  "summary": { "problem": [ "problem", "alternative", "solution" ] } }
```

`grid` — непустой список строк; в строке — ключи блоков этого документа через
пробел (`.` — пустая ячейка), во всех строках ячеек поровну, область каждого
блока — прямоугольник. `labels` — подписи ячеек, ключи — из сетки. `sketch` —
блок с полями первого наброска: поле с ключом ячейки — её «как было»; хотя бы
одно такое поле обязательно, в сетке этого блока нет. `summary` — по ключу
ячейки список полей документа и колонок таблицы её блока. Холст хранится
версией схемы вместе с блоками; без `canvas` у новой версии холста нет.

Порядок блоков задаётся здесь и нигде больше: ученик видит их в нём же.
`hint` адресована агенту ученика; `lesson` — на каком уроке блок обычно
собирают, подсказка, а не ограничение. Ключи нормализуются к нижнему
регистру; повторяющийся ключ отклоняется ошибкой валидации. Ключи `table`,
`report`, `canvas`, `compare` заняты видами страницы документа (они и блок
делят один сегмент адреса `/documents/<курс>/<документ>/<вид или блок>`) —
отказ `artifact_invalid_spec` с `key`; так же у шаблона и у схемы, собранной
из шаблона с правками курса (learning-services#367).

```json
{ "ok": true, "data": { "id": "ACA-00001", "course": "course-p3",
                        "artifact": "project_summary", "version": 1 } }
```

**Отказы:** `course_not_found`, `lesson_not_found` — блок ссылается на
несуществующий урок; `invalid_block_kind` (с `key` и `kind`) — вид не из
`text`, `file`, `link`; `artifact_invalid_spec` (с `key`, `table`, `column`,
`field`) — схема полей и колонок не читается или холст не раскладывается (с
`key` — ячейка или блок, где ошибка).

Схема целиком отвязывает документ от шаблона: у новой версии нет ни
шаблона, ни правок (`template` в `course_draft` — `null`). Документ из
шаблона — `set_course_artifact_template`.

Схема без блоков даёт предупреждение `artifact_without_blocks` в
`readiness` — публикацию оно не блокирует: курс без документа — нормальный
курс. Блок-файл без `accept` — предупреждение `artifact_file_without_accept`
(с `key`): такой блок примет любой файл, и срез для агента может не
построиться.

## `lms_frappe_app.api.authoring.set_artifact_template`

Новая версия шаблона документа (learning-services#370). Шаблон — схема
документа без уроков, общая для курсов: реестр одного вида в курсах для
разных отраслей — один шаблон и правки каждого курса к нему. Каждый вызов —
новая версия; прежние не меняются, и курсы, закрепившие их, на них и
остаются.

**Параметры:** `template` — ключ шаблона: латиница в нижнем регистре, цифры,
`_` и `-`, до 60 знаков (`risk-register`); `title` — название документа по
умолчанию; `blocks`, `layout`, `canvas` — как у `set_course_artifact`, но
без `lesson` у блоков: урок принадлежит курсу и задаётся в правках привязки;
`note` (необязательно) — что поменялось в версии; `extends`,
`extends_version`, `overlay` (необязательно) — наследник, ниже; `renamed`
(необязательно) — переименования ключей, ниже; `description`
(необязательно, learning-services#387) — одна-две фразы: для какого документа
шаблон, у наследника — чем он отличается от базы.

Описание — у версии, как схема, и после записи не меняется; пробелы по краям
срезаются, пустое хранится как `null`. От родителя наследник его не получает:
описание базы сказало бы про другой документ. По нему агент выбирает шаблон
в `list_artifact_templates`, когда названия похожи.

Схема проверяется той же проверкой, что у `set_course_artifact`: вид блока,
поля и колонки, формулы, холст. Сверх того у шаблона есть блоки, у каждого —
ключ, и ключи не повторяются.

**Наследник** (learning-services#375) — шаблон, который отличается от другого
одинаково в нескольких курсах: `extends` — ключ родителя, `extends_version` —
его версия (без неё — последняя на момент записи), `overlay` — правки к
родителю в формате правок курса (`set_course_artifact_template`), но без
`lesson` нигде и без `title`: название наследника — `title`. `blocks` и
`canvas` у наследника пусты, правка холста — `overlay.canvas`; раскладка —
родителя или `overlay.layout`, параметр `layout` у наследника не читается:
MCP шлёт его всегда, и наследник шаблона-холста молча стал бы столбцом.

```json
{ "template": "risk-register-construction", "title": "Реестр рисков стройки",
  "description": "Реестр рисков строительного объекта: источники — люди и погода",
  "extends": "risk-register", "extends_version": 3,
  "overlay": { "blocks": { "risks": { "hint": "…",
    "spec": { "columns": { "source": { "options": [ "люди", "погода" ] } } } } } } }
```

Схема наследника собирается при записи — родитель ⊕ правки, — проверяется,
как схема любого шаблона, и хранится в версии целиком: `artifact_template`
отдаёт её собранной, курс привязывается к наследнику, как к любому шаблону.
Наследник закреплён за версией родителя: новая версия родителя его не
меняет, на неё наследник переходит своей новой версией. Наследника у
наследника нет.

**Переименования** (learning-services#376) — какие ключи прошлой версии этого
же шаблона в этой версии зовутся иначе:

```json
{ "blocks": { "risks": "threats" }, "fields": { "limit": "threshold" },
  "tables": { "register": "threats" },
  "columns": { "threats": { "event": "what" } } }
```

Колонки — по таблице под её новым именем. Старое имя было в прошлой версии,
новое есть в этой и не занято в прошлой, если только само не переименовано
(обмен двух ключей законен); два старых имени не получают одно новое. У
первой версии переименований нет. По ним `upgrade_course_artifact` переносит
правки курса и данные учеников на новые ключи; без них новое имя для курса —
удалённая колонка и новая пустая.

```json
{ "ok": true, "data": { "id": "ATPL-00001", "template": "risk-register", "version": 3 } }
```

**Отказы:** `artifact_invalid_template` (с `template`) — ключ не по форме или
нет названия; у наследника есть `blocks` или `canvas`; шаблон наследует сам
себя; родитель сам наследник (с `extends`); `extends_version` или `overlay`
без `extends`; переименования не по форме или не сходятся с версиями (с
`path`, например `renamed.columns.threats.event`); `artifact_template_not_found`
(с `template` и `version`) — нет родителя или его версии; `artifact_invalid_overlay` — правки наследника не
собираются (как у `set_course_artifact_template`), в них есть `lesson` (с
`key`) или `title` (с `name`); `artifact_invalid_spec` (с `key`, `table`,
`column`, `field`) — схема не читается, в ней нет блоков, ключ блока пуст или
повторяется, у блока есть `lesson`; `invalid_block_kind` (с `key` и `kind`).

## `lms_frappe_app.api.authoring.list_artifact_templates`

Шаблоны документов: последняя версия каждого и курсы, чьи действующие
документы на нём собраны. У курса — версия шаблона, которую он закрепил:
новая версия шаблона живые курсы не меняет.

**Параметры:** нет.

```json
{ "ok": true, "data": { "templates": [
  { "template": "risk-register", "title": "Реестр рисков",
    "description": "Реестр рисков проекта: событие, источник, вероятность, влияние",
    "version": 3, "note": "Колонка «Источник» стала выбором",
    "extends": null,
    "courses": [ { "course": "course-basics", "course_title": "Основы",
                   "artifact": "risk_register", "version": 2 } ] } ] } }
```

`version` у шаблона — последняя, у курса — закреплённая. `description` —
описание последней версии, `note` — что в ней поменялось; оба `null`, если их
не задали. `extends` — у наследника родитель последней версии,
`{"template": "risk-register", "version": 3}`, у прочих `null`.

## `lms_frappe_app.api.authoring.artifact_template`

Версия шаблона целиком.

**Параметры:** `template`, `version` (необязательно) — без него последняя.

```json
{ "ok": true, "data": {
  "template": "risk-register", "version": 3, "title": "Реестр рисков",
  "description": "Реестр рисков проекта: событие, источник, вероятность, влияние",
  "layout": "sections",
  "blocks": [ { "key": "risks", "title": "Риски", "hint": "…", "span": 1,
                "kind": "text", "accept": [], "spec": { "table": "register",
                "columns": [ { "key": "event", "title": "Событие", "type": "text" } ] } } ],
  "canvas": null, "note": "Колонка «Источник» стала выбором",
  "renamed": null, "extends": null, "overlay": null,
  "created": "2026-09-29T12:00:00.000000" } }
```

Блоки — в той форме, в какой их принимает `set_course_artifact`, без `lesson`;
`spec` — `null` у блока без полей и колонок. У наследника схема — уже
собранная, `extends` — `{"template", "version"}` родителя, `overlay` — правки
к нему; у прочих оба `null`. `renamed` — переименования этой версии
относительно прошлой, `null` — их нет. `description` — описание этой версии,
`null` — его нет.

**Отказы:** `artifact_template_not_found` (с `template` и `version`).

## `lms_frappe_app.api.authoring.set_course_artifact_template`

Документ курса из шаблона с правками курса — новой версией схемы документа
курса. Итоговая схема = шаблон ⊕ правки; собирается при записи, проверяется
целиком, как у `set_course_artifact`, и хранится так же: ученик, страница и
выгрузка видят обычную схему документа и о шаблоне не знают. Новая версия
шаблона курс не меняет — он остаётся на закреплённой.

**Параметры:** `course`, `artifact` — ключ документа в курсе, `template`,
`version` (необязательно) — версия шаблона, без него последняя, `overlay`
(необязательно) — правки курса, `purpose` (необязательно) — зачем документ
ученику, как у `set_course_artifact`. Он у документа курса, а не у шаблона:
не назван — остаётся прежний, в том числе при `upgrade_course_artifact`.

```json
{ "title": "Реестр рисков стройки",
  "blocks": {
    "risks": { "lesson": "lesson-2", "hint": "…",
      "spec": {
        "fields": { "threshold": { "title": "Порог" } },
        "columns": { "source": { "options": [ "люди", "погода" ] }, "kind": null },
        "add_columns": [ { "key": "permit", "title": "Разрешение",
                           "type": "text", "after": "source" } ] } },
    "issues": null },
  "add_blocks": [ { "key": "site_log", "title": "Журнал площадки",
                    "lesson": "lesson-4", "after": "status" } ],
  "canvas": { "labels": { "uvp": "Обещание" } } }
```

Правило одно на все уровни: блок правится по ключу блока, поле и колонка — по
своему ключу (в схеме они списком, в правках — объектом по ключам). Объект
сливается с объектом, `null` удаляет (блок, поле, колонку, подпись, холст
целиком), список заменяет список целиком (`options`, `views`, `rows`,
`grid`, `summary` ячейки, `accept`). Новое — в `add_blocks`, `add_fields`,
`add_columns`: встаёт после ключа из `after`, без него — в конец. Уроки
блоков задаются только здесь: у шаблона их нет. В правке блока — `title`,
`hint`, `lesson`, `span`, `kind`, `accept`, `spec`; в правке схемы блока —
`fields`, `columns`, `add_fields`, `add_columns`, `table`, `prefix`, `title`,
`rows`, `views`; в правке холста — `grid`, `labels`, `sketch`, `summary`.

```json
{ "ok": true, "data": { "id": "ACA-00007", "course": "course-basics",
                        "artifact": "risk_register", "version": 2,
                        "template": "risk-register", "template_version": 3 } }
```

`version` — версия схемы документа курса, как у `set_course_artifact`;
`template_version` — закреплённая версия шаблона.

**Отказы:** `course_not_found`; `artifact_template_not_found` (с `template` и
`version`); `artifact_invalid_overlay` — правка называет блок, поле или
колонку, которых в шаблоне нет (с `key` и `field` или `column`), добавляет
ключ, который уже есть, ставит добавку после несуществующего ключа (с
`after`), называет неизвестное свойство (с `name`) или не объект там, где
нужен объект; `lesson_not_found` (с `id`) — урока нет в этом курсе;
`artifact_invalid_spec`, `invalid_block_kind` — собранная схема не проходит
проверку `set_course_artifact`: например, убран блок, который называет сетка
холста.

## `lms_frappe_app.api.authoring.upgrade_course_artifact`

Документ курса — на новую версию своего шаблона (learning-services#376). Новая
версия шаблона живой курс не меняет; переход — этот явный вызов. Переименования
всех версий между закреплённой и новой (`renamed` у `set_artifact_template`)
складываются в одно. Им переименовываются правки курса — ключи блоков в
`blocks` и `after` у `add_blocks`, поля и колонки в правках схемы блока и их
`after`, таблица, ключи ячеек холста в `grid`, `labels`, `summary` и
`sketch`, поля и колонки в `summary`, — и схема собирается заново с новой
версией тем же путём, что у `set_course_artifact_template`: новой версией
документа курса. В той же транзакции документы учеников по этому курсу и
ключу переходят на новые ключи: ключи блоков, поля, названия таблиц, колонки
строк, счётчики строк. Добавленное курсом (`add_*`) остаётся со своими
ключами.

**Параметры:** `course`, `artifact` — ключ документа в курсе, `version`
(необязательно) — версия шаблона, без него последняя, `dry_run`
(необязательно, по умолчанию `false`) — предпросмотр без записи.

```json
{ "ok": true, "data": { "id": "ACA-00009", "course": "course-basics",
  "artifact": "risk_register", "version": 3,
  "template": "risk-register", "template_version": 4, "from_version": 2,
  "diff": {
    "blocks": { "added": [ "site_log" ], "removed": [], "changed": [ "threats" ] },
    "fields": { "added": [], "removed": [ "limit_note" ] },
    "columns": { "added": [ "threats.permit" ], "removed": [] } },
  "students": 12 } }
```

`version` — новая версия схемы документа курса, `template_version` — версия
шаблона, на которую курс перешёл, `from_version` — с какой. `diff` — между
прежней схемой курса (с переименованными ключами: переименование не выглядит
удалённым и добавленным) и новой; колонки — `"таблица.колонка"`, изменённый
блок — тот, что есть в обеих и отличается чем угодно, от подсказки до урока.
`students` — сколько документов учеников поменялось.

С `dry_run: true` — предпросмотр (learning-services#383): переход проходит
всё до записи — переносит правки, собирает и проверяет схему, считает
разницу и документы учеников, которые поменялись бы, — и не пишет ничего: ни
новой версии документа курса, ни данных учеников. Переход необратим, и
разницу куратору показывают до него. Ответ — тот же, плюс `"dry_run": true`;
`id` — `null`, `version` — нынешняя версия схемы документа курса. Отказы —
те же, что у перехода.

```json
{ "ok": true, "data": { "id": null, "course": "course-basics",
  "artifact": "risk_register", "version": 2,
  "template": "risk-register", "template_version": 4, "from_version": 2,
  "diff": {
    "blocks": { "added": [ "site_log" ], "removed": [], "changed": [ "threats" ] },
    "fields": { "added": [], "removed": [ "limit_note" ] },
    "columns": { "added": [ "threats.permit" ], "removed": [] } },
  "students": 12, "dry_run": true } }
```

Правки курса, которые не собираются с новой версией (называют то, чего в ней
нет), — отказ, и не меняется ничего: ни схема курса, ни данные учеников.
Назад версия не переходит: откат — `set_course_artifact_template` с номером
версии, без переноса данных.

**Отказы:** `course_not_found`; `artifact_not_found` (с `artifact`) — в курсе
нет такого документа; `artifact_not_bound` (с `artifact`) — документ задан
схемой целиком, а не шаблоном; `artifact_template_not_found` (с `template` и
`version`) — нет такой версии шаблона; `artifact_template_same_version` (с
`template` и `version`) — курс уже на ней; `artifact_invalid_template` (с
`template` и `version`) — версия ниже закреплённой; `artifact_invalid_overlay`
(с `key` и `field` или `column`, `after`, `name`) — правки курса не собираются
с новой версией; `lesson_not_found`, `artifact_invalid_spec`,
`invalid_block_kind` — собранная схема не проходит проверку, как у
`set_course_artifact_template`.

## `lms_frappe_app.api.authoring.add_quiz`

Квиз урока целиком. Заводится одним вызовом: квиз без вопросов — состояние, в
котором ученик упирается в зачёт из ничего.

**Параметры:** `lesson`, `questions`, `title` (необязательно),
`passing_percentage` (по умолчанию 70).

```json
{ "questions": [
  { "text": "Что делает цикл?", "type": "Choices", "marks": 1,
    "options": [ { "text": "Повторяет", "correct": true, "explanation": "верно" },
                 { "text": "Ветвит" } ] },
  { "text": "Назовите оператор", "type": "User Input",
    "answers": ["for", "while"] } ] }
```

```json
{ "ok": true, "data": { "id": "quiz-1", "lesson": "lesson-1",
                        "questions": [ "q-14", "q-15" ] } }
```

Тип по умолчанию `Choices`. `Open Ended` не принимается: такой вопрос сервер
не проверяет, а зачёт, выставленный агентом, не зачёт.

Состав вариантов проверяет сам Frappe Learning — дубли, минимум два варианта,
хотя бы один верный. Нарушение возвращается отказом `invalid_question` с
номером вопроса в `question_index`; вопросы этого квиза откатываются целиком.

Второй квиз на уроке не заводится: урок отдаёт агенту ровно один, а остальные
становятся невидимым мусором. Правится вопросами существующего —
`add_question`, `update_question`, `remove_question`.

**Отказы:** `lesson_not_found`; `empty_quiz` — список вопросов пуст;
`quiz_exists` (с `quiz`) — у урока уже есть квиз; `unknown_question_type`
(с `received`) — тип не `Choices` и не `User Input`; `too_many_options`
(с `received`) — вариантов или образцов ответа больше, чем Frappe Learning
хранит в вопросе; `invalid_question` (с `question_index`).

## `lms_frappe_app.api.authoring.add_question`

Добавляет вопрос в существующий квиз урока.

**Параметры:** `lesson`, `question` — один элемент того же вида, что в
`questions` у `add_quiz`.

```json
{ "ok": true, "data": { "quiz": "quiz-1", "question": "q-16",
                        "questions_total": 6 } }
```

**Отказы:** `lesson_not_found`; `quiz_missing` — у урока нет квиза, его
заводит `add_quiz` целиком; `unknown_question_type` (с `received`);
`too_many_options` (с `received`); `invalid_question`.

## `lms_frappe_app.api.authoring.update_question`

Правит текст вопроса, варианты или образцы ответа.

**Параметры:** `question`, а также `text`, `options`, `answers` — любое из
трёх; непереданное остаётся как было.

`options` и `answers` **замещают** прежние целиком: правка «трёх вариантов на
два» иначе оставила бы третий на месте, и вопрос отвечал бы не тем, что видит
куратор.

```json
{ "ok": true, "data": { "id": "q-16", "text": "Что выведет цикл…",
                        "affects_attempts": 3 } }
```

`affects_attempts` — сколько ответов учеников уже дано на этот вопрос. Правка
после ответов разрешена: блокировать исправление опечатки в опубликованном
курсе хуже, чем оставить её, — но куратор должен знать, что меняет вопрос,
который кто-то уже видел.

Правка, ломающая состав вариантов, отменяется целиком: вопрос не остаётся
наполовину переписанным.

**Отказы:** `question_not_found`; `too_many_options` (с `received`);
`invalid_question` (с `question`).

## `lms_frappe_app.api.authoring.remove_question`

Убирает вопрос из квиза урока.

**Параметры:** `lesson`, `question`.

```json
{ "ok": true, "data": { "quiz": "quiz-1", "questions_total": 5 } }
```

Сама запись вопроса не удаляется: на неё ссылаются ответы прошлых попыток, и
стирание испортило бы историю зачётов.

**Отказы:** `lesson_not_found`; `quiz_missing`; `question_not_found`
(с `quiz` и `question`) — в этом квизе такого вопроса нет.

## `lms_frappe_app.api.authoring.add_homework`

Домашнее задание урока (learning-services#439): одно на урок, как квиз,
одинаковое для всех учеников. Выдаётся закрытием урока — сданным квизом или
`complete_lesson`; в `start_lesson` следующего урока оно приходит как
`previous_homework` вместе со сдачей ученика. Необязательное: `publish_course` его не проверяет, и
домашка ничего не блокирует.

**Параметры:** `lesson`, `title`, `description` — что сделать и что сдать,
markdown; `answer_mode` — `text`, `files` или `text_and_files` (по умолчанию);
`due_mode` — `none` (по умолчанию), `relative` — `due_days` дней после
закрытия урока, `absolute` — до конца дня `due_date` (`YYYY-MM-DD`) по
времени платформы. Поле другого режима срока очищается.

```json
{ "ok": true, "data": { "id": "a1b2c3d4e5", "lesson": "lesson-1",
  "title": "Встреча со спонсором", "description": "Проведите встречу…",
  "answer_mode": "text_and_files", "due_mode": "relative", "due_days": 5,
  "due_date": null } }
```

**Отказы:** `lesson_not_found`; `homework_exists` (с `homework`) — у урока
уже есть задание, правьте его; `invalid_answer_mode`; `invalid_due` — у
`relative` нет числа дней больше нуля, у `absolute` — даты, или режим
неизвестен.

## `lms_frappe_app.api.authoring.update_homework`

Правит домашнее задание урока. Незаданное и пустое не затирается.

**Параметры:** `lesson`; необязательные `title`, `description`, `answer_mode`,
`due_mode`, `due_days`, `due_date` — как у `add_homework`.

```json
{ "ok": true, "data": { "id": "a1b2c3d4e5", "lesson": "lesson-1",
  "title": "Встреча с заказчиком", "description": "Проведите встречу…",
  "answer_mode": "text", "due_mode": "absolute", "due_days": null,
  "due_date": "2026-10-15" } }
```

Сдачи ссылаются на задание, а не копируют его: исправленная формулировка видна
всем сразу. Сроки, уже выставленные сдачам, не пересчитываются — ученик не
получает просрочку задним числом.

**Отказы:** `homework_missing` — у урока нет задания; `invalid_answer_mode`;
`invalid_due`.

## `lms_frappe_app.api.authoring.remove_homework`

Удаляет домашнее задание урока, пока по нему никто не сдавал.

**Параметры:** `lesson`.

```json
{ "ok": true, "data": { "lesson": "lesson-1", "removed": true } }
```

**Отказы:** `homework_missing`; `homework_in_use` (с `submissions`) — по
заданию есть сдачи, в том числе архивные после сброса прогресса: его можно
только переписать.

## `lms_frappe_app.api.authoring.get_lesson`

Урок целиком: материал, действующая директива и квиз с эталонами.

**Параметры:** `lesson`.

```json
{ "ok": true, "data": {
  "id": "lesson-1", "title": "Списки", "chapter": "ch-1", "course": "c-1",
  "body": "## Списки\n\nСписок хранит значения по порядку.",
  "directive": { "id": "AD-00007", "version": 2,
                 "created_at": "2026-09-23T14:05:11.482913",
                 "teaching_directive": "…", "objectives": "…" },
  "course_directive": { "id": "ACD-00001", "version": 1,
                        "created_at": "2026-09-20T09:12:40.118204",
                        "teaching_directive": "…", "objectives": "…" },
  "quiz": { "id": "quiz-1", "passing_percentage": 70, "questions": [
    { "id": "q-14", "text": "Что выведет цикл…", "type": "Choices",
      "options": [ { "text": "Десять", "correct": true,
                     "explanation": "Цикл идёт от нуля до девяти" } ],
      "answers": [] } ] },
  "homework": { "id": "a1b2c3d4e5", "lesson": "lesson-1", "title": "Список дел",
    "description": "Составьте список задач на неделю…", "answer_mode": "text_and_files",
    "due_mode": "relative", "due_days": 5, "due_date": null } } }
```

У варианта `explanation` — пояснение из `add_quiz`, пустая строка, если его
нет. Автору оно видно по роли, как и эталоны; ученику — только вместе с
вердиктом (см. «Запрещённые поля»).

Директивы приходят как есть, не разобранными на пункты: куратор сверяет тот
самый текст, который уедет агенту ученика. `created_at` — когда поставлена
действующая версия. Директивы нет — `null`; квиза нет —
`quiz` тоже `null`; домашнего задания нет — `homework: null`. Задание — в том
же виде, что отдаёт `add_homework`.

Отдельный метод, а не поле `course_draft`: полные тексты всех уроков в одном
ответе — десятки килобайт на каждый вызов, а сверяют поурочно.

**Отказы:** `lesson_not_found`.

## `lms_frappe_app.api.authoring.course_draft`

Курс целиком, как его собрали, — с эталонами и списком проблем.

**Параметры:** `course`.

```json
{ "ok": true, "data": {
  "id": "course-basics", "title": "Основы", "summary": "Для начинающих",
  "published": false, "upcoming": false,
  "chapters": [ { "id": "ch-1", "title": "Глава", "lessons": [
    { "id": "lesson-1", "title": "Циклы", "has_body": true,
      "body_chars": 4210, "body_segments": 1,
      "has_directive": false, "directive_version": null, "objectives": 0,
      "quiz": null,
      "homework": { "title": "Список дел", "answer_mode": "text_and_files",
                    "due_mode": "relative" } } ] } ],
  "directive": null,
  "artifacts": [ { "id": "ACA-00001", "version": 1,
    "artifact": "project_summary", "title": "Резюме проекта",
    "purpose": "Проект на одной странице — чтобы все договорились об одном и том же.",
    "layout": "sections", "template": "project-summary",
    "template_version": 2, "template_latest": 3,
    "overlay": { "blocks": { "goal_and_benefits": { "lesson": "lesson-1" } } },
    "blocks": [ { "key": "goal_and_benefits",
      "title": "…", "hint": "…", "lesson": "lesson-1", "span": 1,
      "kind": "text", "accept": [] } ] } ],
  "readiness": { "blocking": [], "warnings": [
    { "code": "lesson_without_directive", "lesson": "lesson-1",
      "message": "Урок без директивы" } ] },
  "revision": "2026-09-23T14:05:11.482913",
  "author_url": "https://lms.example.com/author?course=course-basics",
  "map_discrepancies": null, "open_notes": 2 } }
```

`quiz` у урока — тот же состав с эталонами, что отдаёт `get_lesson`; полного
текста уроков здесь нет. Наполненность — фактами: `body_chars` — длина
материала, `body_segments` — на сколько частей урок режет `start_lesson` при
текущем `lesson_segment_limit`, `directive_version` и `objectives` — версия
действующей директивы и число её целей (`null` и `0` без директивы).
`homework` — название, вид ответа и правило срока домашнего задания урока,
`null` без задания; целиком оно — у `get_lesson`.
`revision` — самая свежая отметка изменения курса, та же, что у
`course_revision`; `author_url` — страница курса в кабинете автора.
`map_discrepancies` — сколько расхождений с картой декомпозиции нашёл
`course_map_check`; `null`, если карты нет. Публикацию не блокирует.
`open_notes` — сколько замечаний автора ждёт агента (см. `list_notes`).

У документа курса `template` и `template_version` — шаблон и закреплённая
версия, `template_latest` — последняя версия шаблона: больше закреплённой —
шаблон ушёл вперёд. `overlay` — правки курса к шаблону в том виде, в каком
их принял `set_course_artifact_template` (`{}` — правок нет). Перепривязка
заменяет правки целиком: чтобы поменять одну, берут эти и правят их, иначе
уроки блоков и прочие правки курса пропадут. У документа со схемой целиком
все четыре — `null`.

Шаблон, ушедший вперёд, даёт предупреждение `artifact_template_outdated` в
`readiness` — с `artifact`, `template` и сообщением «Документ «Реестр
рисков»: шаблон risk-register вышел в v4, курс на v3.», дополненным `note`
последней версии. Публикацию оно не блокирует: курс на закреплённой версии
работает, как работал; переход — `upgrade_course_artifact`.

## `lms_frappe_app.api.authoring.course_revision`

Отметка последнего изменения курса — для опроса кабинетом автора без чтения
курса целиком. Растёт от правки курса, глав, уроков, квизов и вопросов,
директив урока и курса, схем документа, домашних заданий, в том числе от удаления урока или
вопроса; от чтения не меняется. В MCP не выставляется.

**Параметры:** `course`. Только `GET`.

```json
{ "ok": true, "data": { "course": "course-basics",
  "revision": "2026-09-23T14:05:11.482913",
  "notes_revision": "2026-09-23T15:40:02.118305" } }
```

`notes_revision` — самая свежая отметка замечаний автора: растёт от нового
замечания, ответа и смены статуса; `null`, если замечаний нет. `revision` от
замечаний не меняется — замечание не правка курса.

**Отказы:** `course_not_found`.

## `lms_frappe_app.api.authoring.add_note`

Замечание автора на месте курса. Петля «увидел → агент поправил → принял»:
человек ставит замечание в кабинете, агент правит курс и отмечает «сделано»,
человек принимает.

**Параметры:** `course`, `target`, `text`, `quote`, `lesson`, `via`. Только
`POST`.

- `target` — место: `course`, `course_directive.<поле>`, `lesson`, `material`,
  `directive.<поле>`, `question.<id>`, `block.<документ>/<ключ>`, `map.<узел>`.
  Месту внутри урока нужен `lesson`; `course` и `course_directive` урока не
  принимают. Вопрос проверяется по квизу урока; блок и узел карты — только по
  форме: они могут быть задуманы, но ещё не собраны.
- `quote` — выделенный текст, необязательный.
- `via` — кто пишет: `author` (по умолчанию) или `agent`. Признак для
  очереди, а не защита: писать могут только авторские роли.

```json
{ "ok": true, "data": { "id": "AAN-00012", "course": "course-basics",
  "lesson": "lesson-4", "target": "directive.teaching_directive",
  "status": "open", "waiting_on": "agent" } }
```

**Отказы:** `course_not_found`; `invalid_target` с полем `where` (`target`
или `lesson`); `invalid_note` с `where` — пустой `text` или неизвестный `via`.

## `lms_frappe_app.api.authoring.list_notes`

Замечания курса с нитью ответов, старые сверху.

**Параметры:** `course`, `status` (`open`, `done`, `accepted`), `lesson`.

```json
{ "ok": true, "data": { "course": "course-basics", "notes": [
  { "id": "AAN-00012", "lesson": "lesson-4", "target": "directive.teaching_directive",
    "label": "Урок 4 «Ответ и мера» · директива · teaching_directive",
    "missing": false, "quote": "По каждой мере три вопроса…",
    "text": "Слишком допрос: дай пример меры", "via": "author",
    "author": "curator@example.com", "author_name": "Куратор",
    "status": "done", "waiting_on": "author",
    "created_at": "2026-09-23T15:40:02.118305", "updated_at": "2026-09-23T15:52:40.004411",
    "replies": [ { "via": "agent", "author": "curator@example.com",
      "author_name": "Куратор", "text": "Добавил пример меры для склада",
      "created_at": "2026-09-23T15:52:40.001037" } ] } ] } }
```

`label` — место словами по курсу, каким он есть сейчас; `missing` — места
больше нет. `waiting_on` — чей ход: `done` ждёт автора; открытое — того, кто
не сказал последнего слова: вопрос агента ждёт автора, замечание автора —
агента; у принятого — `null`.

**Отказы:** `course_not_found`; `invalid_note` с `where: status`.

## `lms_frappe_app.api.authoring.set_note_status`

Сменить статус замечания. `text` уходит ответом в нить.

**Параметры:** `note`, `status`, `text`, `via`. Только `POST`.

## `lms_frappe_app.api.authoring.set_course_map`

Новая версия карты декомпозиции курса — замысла, с которым сверяется
собранное. Каждый вызов создаёт версию; действующая одна. С курсом карта при
записи не сверяется: её согласуют до сборки.

**Параметры:** `course`, `levels`, `nodes`, `lessons`, `blocks` — списки;
приходят массивами или строками JSON. Только `POST`.

- `levels` — `[{key, title, needs_children?, needs_lesson?}]`, слева
  направо, первый — корень. `needs_children` — у узла уровня должен быть
  узел справа; `needs_lesson` — узлу уровня нужен урок. Флаг у последнего
  уровня `needs_children` — отказ.
- `nodes` — `[{id, level, text, parents?, note?, tags?, lesson?, objective?}]`.
  `parents` — узлы соседнего левого уровня; `lesson` — ключ пункта плана;
  `objective` — узел является целью урока.
- `lessons` — план: `[{key, title, chapter?, lesson?}]`; `lesson` — урок
  этого курса, к которому привязан пункт.
- `blocks` — план блоков документа: `[{artifact, key, title?, lesson?,
  criteria?}]`; `lesson` — ключ пункта плана, `criteria` — критерии, которые
  должны дойти до подсказки блока.

Ключи и идентификаторы — строки; целые числа принимаются и приводятся к
строке. Неизвестное поле — отказ, а не пропуск.

```json
{ "ok": true, "data": { "id": "ACM-00003", "course": "course-basics",
  "version": 3, "counts": { "lessons": 0, "objectives": 1, "blocks": 0,
  "integrity": 0, "total": 1 } } }
```

`counts` — счётчики `course_map_check` сразу после записи.

**Отказы:** `course_not_found`; `invalid_map` с полем `where` — где ошибка:
`nodes[T1].parents`, `lessons[u2].lesson`, `blocks[register/risks].criteria`.

## `lms_frappe_app.api.authoring.course_map_check`

Действующая карта против курса на платформе.

**Параметры:** `course`.

```json
{ "ok": true, "data": {
  "course": "course-basics",
  "map": { "id": "ACM-00003", "version": 3,
    "created_at": "2026-09-23T14:05:11.482913",
    "levels": [ { "key": "result", "title": "Результат",
      "needs_children": false, "needs_lesson": false } ],
    "nodes": [ { "id": "R", "level": "result", "text": "Живой реестр",
      "parents": [], "note": "", "tags": [], "lesson": null,
      "objective": false } ],
    "lessons": [ { "key": "u1", "title": "Риск как событие",
      "chapter": "Рамка", "lesson": "lesson-1" } ],
    "blocks": [ { "artifact": "register", "key": "risks", "title": "",
      "lesson": "u1", "criteria": [ "пять записей" ] } ] },
  "platform": {
    "lessons": [ { "id": "lesson-1", "number": 1, "title": "Риск как событие",
      "chapter": "Рамка", "objectives": [ "Риск это событие" ] } ],
    "blocks": [ { "artifact": "register", "key": "risks", "title": "Риски",
      "lesson": "lesson-1", "hint": "Пять записей…" } ] },
  "matches": { "u1": "lesson-1" },
  "discrepancies": [ { "group": "objectives", "code": "mismatch",
    "plan_lesson": "u1", "lesson": "lesson-1", "missing": [],
    "extra": [ "Лишняя цель" ], "nodes": [],
    "message": "Цели урока «Риск как событие» расходятся с картой: нет 0, лишних 1" } ],
  "counts": { "lessons": 0, "objectives": 1, "blocks": 0, "integrity": 0,
    "total": 1 },
  "tags": {} } }
```

`matches` — пункт плана → урок платформы: по привязке, у непривязанного —
по названию; пары нет — `null`. Группы и коды расхождений:

- `lessons`: `missing` (пункта нет на платформе), `extra` (урока нет в карте),
  `title`, `chapter` (`expected` — в карте, `actual` — на платформе),
  `order` — урок сдвинут относительно карты;
- `objectives`: `mismatch` (`missing`, `extra`, `nodes` — узлы недостающих
  целей), `order`;
- `blocks`: `missing` (блока нет в схеме), `extra` (блока нет в карте),
  `lesson` (`expected`, `actual` — уроки), `criteria` (`missing` — критерии,
  которых нет в подсказке; сравнение без регистра и лишних пробелов);
- `integrity`: `orphan` (нет пути к первому уровню), `unexpanded`
  (флаг `needs_children`), `no_lesson` (флаг `needs_lesson`); ссылка —
  `node`.

`tags` — узлы по меткам. Карты нет — `map: null`, `counts: null`, пустые
`matches` и `discrepancies`; `platform` приходит всегда.

**Отказы:** `course_not_found`.

## `lms_frappe_app.api.authoring.publish_release`

Публикует релиз курса целиком — новой версией. Только `POST`.

**Параметры:** `release` — релиз (объект или строка JSON), формат — раздел
«Релиз курса»; `course` (необязательно) — курс без уроков (анонс), к которому
привязать первый релиз. Без `course` курс ищется по `release.course.key`; нет
такого — заводится черновиком, вызвавший становится преподавателем курса.

```json
{ "ok": true, "data": { "course": "primer-kursa", "course_key": "sample-course",
  "release": "REL-00007", "version": 3, "unchanged": false, "course_created": false,
  "published": true,
  "chapters": { "created": [], "updated": ["ch-1"], "removed": [], "restored": [] },
  "lessons": { "created": ["l-4"], "updated": ["l-1"], "removed": ["l-3"], "restored": ["l-2"] },
  "document": { "artifact": "notebook", "version": 4 },
  "warnings": [ { "code": "public_text_empty", "where": "chapters[ch-2].description" } ] } }
```

`chapters` и `lessons` — ключи созданных, изменённых и снятых из программы
узлов; `restored` — вернувшихся в программу: их не было в прежнем релизе, и
они получили свою прежнюю запись (могут быть и в `updated`). `document` — ключ и версия действующей схемы документа курса; у
релиза без документа — `null`. `warnings` — то, что публикации не мешает:
`public_text_empty` (пустой текст ученику; на месте пустой карточки курса —
его название), `explanation_missing`, `required_condition_ignored` (условие
обязательности у поля раздела «один раз» теряется).

Тот же релиз ещё раз — `unchanged: true`, версия прежняя, ничего не пишется:
повтор вызова после обрыва связи не плодит версий. Признак «опубликован» не
меняется: новый курс — черновик, новый релиз опубликованного курса действует
сразу. Открывает курс из релиза `publish_course`: его готовность проверена
при публикации релиза. Всё или ничего: отказ на любом шаге оставляет курс
как был.

**Отказы:** `release_invalid` — релиз не JSON, не объект, несёт `NaN` или
бесконечность в любой части (и в `agent`, `map`) или не проходит схему
(`errors` — до 20 расхождений `{path, message}`, `total`);
`release_format_unsupported` (`format`, `supported`); `release_inconsistent`
(`problems` — до 20 `{code, where, …}`: `duplicate_key`, `broken_ref`,
`chapter_order`, `quiz_correct`, `document_key`, `text_too_long`; `total`);
`course_not_found` (`id`); `course_key_mismatch` — у переданного курса другой
ключ (`course`, `course_key`, `release_key`); `course_key_taken` — ключ
релиза уже у другого курса или его курс сейчас заводит другая публикация,
повтор вызова найдёт курс (`release_key`; `course` — курс с этим ключом,
`null`, если он ещё не виден); `course_has_content` — у переданного курса
без ключа есть уроки (`course`, `lessons`).

## `lms_frappe_app.api.authoring.publish_course`

Открывает курс ученикам, если он к этому готов.

**Параметры:** `course`.

```json
{ "ok": true, "data": { "id": "course-basics", "published": true,
                        "warnings": [ { "code": "course_without_quiz",
                                        "message": "…" } ],
                        "notified": 0 } }
```

Публикация анонса открывает его для записи. Тем, кто просил сообщить о
выходе, уходит письмо, один раз; `notified` — сколько писем ушло.

Публикация проверяет готовность и возвращает **все** проблемы разом — иначе
агент будет долбиться в неё по одной ошибке за вызов:

| Код | Что не так |
|---|---|
| `empty_course` | нет глав или ни одного урока |
| `empty_lesson` | урок без материала |
| `blank_question` | вопрос без текста |
| `empty_quiz` | квиз без вопросов |
| `no_summary` | нет краткого описания |

Отказ приходит кодом `course_not_ready`, список — в поле `problems`.
Предупреждения (`lesson_without_directive`, `course_without_directive`,
`course_without_quiz`, `artifact_without_blocks`, `artifact_file_without_accept`,
`artifact_template_outdated`) публикацию не блокируют и
возвращаются в успешном ответе.

Курс из релиза (`publish_release`) старой проверки готовности не проходит:
релиз проверен целиком при публикации.

**Отказы:** `course_not_found`, `course_not_ready` (с `problems`).

## `lms_frappe_app.api.authoring.announce_course`

Показывает курс в каталоге как анонс (learning-services#389): записаться
нельзя, можно попросить сообщить о выходе. Только `POST`.

**Параметры:** `course`.

```json
{ "ok": true, "data": { "id": "ops-junctions", "published": true, "upcoming": true,
  "objectives": [ "Описать процесс в пять колонок",
                  "Найти стыки между отделами" ] } }
```

Готовности анонс не требует: уроков может ещё не быть. Требует целей курса —
поля `objectives` действующей директивы курса: у анонса наружу выходят только
они. У курса из релиза цели курса — цели глав: названия глав действующего
релиза по порядку; директивы у такого курса нет (learning-services#500).
Открывает анонс `publish_course`, снимает — `unpublish_course`.

**Отказы:** `course_not_found`, `course_objectives_missing` — у курса нет
целей, `course_already_published` — курс уже открыт ученикам.

## `lms_frappe_app.api.authoring.unpublish_course`

Снимает курс с публикации — и анонс тоже.

**Параметры:** `course`.

```json
{ "ok": true, "data": { "id": "course-basics", "published": false } }
```

Прогресс учеников снятие не трогает: зачисления и записи прогресса остаются,
и курс вернётся на место вместе с публикацией. Удаления курсов в контракте
нет — снятая с публикации ошибка обратима, удалённый курс с прогрессом нет.

**Отказы:** `course_not_found`.

## `lms_frappe_app.api.authoring.course_testers`

Тестеры курса: кому автор открыл курс до публикации (learning-services#393).
Зовёт кабинет автора, в MCP не выставляется.

**Параметры:** `course`.

```json
{ "ok": true, "data": { "course": "ops-junctions", "testers": [
  { "user": "anna@example.com", "name": "Анна Петрова",
    "progress": 40, "since": "2026-09-29" } ] } }
```

Тестер — обычная запись на курс с отметкой `agent_tester`: доступ к занятиям
даёт сама запись, опубликован ли курс, не важно. `progress` — процент
пройденного, как у записи на курс.

**Отказы:** `course_not_found`.

## `lms_frappe_app.api.authoring.add_testers`

Записывает тестерами курса людей с учётной записью на платформе. Зовёт
кабинет автора, в MCP не выставляется. Только `POST`.

**Параметры:** `course`, `users` — список адресов или текст, где они
разделены запятыми, пробелами или переводами строк.

```json
{ "ok": true, "data": { "course": "ops-junctions",
  "added": [ { "user": "anna@example.com", "notified": true } ],
  "skipped": [ { "user": "ivan@example.com", "reason": "user_not_found" } ],
  "testers": [ { "user": "anna@example.com", "name": "Анна Петрова",
                 "progress": 0, "since": "2026-09-29" } ] } }
```

Каждому записанному уходит приглашение со ссылкой на курс; `notified: false` —
почта не настроена, и сообщить надо самому. `reason` у пропущенного:
`user_not_found` — учётной записи нет или она отключена, `already_tester`,
`already_enrolled` — человек уже учится на курсе, и тестером его не делаем.

**Отказы:** `course_not_found`, `users_required` — ни одного адреса.

## `lms_frappe_app.api.authoring.remove_tester`

Закрывает тестеру доступ тем же сбросом, что `reset_student_progress`:
занятия, попытки квиза и документ уходят в архив, запись удаляется. Зовёт
кабинет автора, в MCP не выставляется. Только `POST`.

**Параметры:** `course`, `user`.

```json
{ "ok": true, "data": { "course": "ops-junctions", "user": "anna@example.com",
  "testers": [] } }
```

**Отказы:** `course_not_found`, `tester_not_found` — человек не тестер курса.

## Метки времени

Приходят **без указания зоны**, в часовом поясе сайта Frappe. Трактовать их
как UTC нельзя: разойдётся на смещение сервера.

Исключение — `retry_after` (итог проваленной попытки в `submit_answer`, отказ
`retry_too_soon`): он приходит со смещением пояса сайта. Этот момент агент
называет ученику, и строка без пояса читалась как UTC.

## Версионирование

Пока нет внешних потребителей, контракт меняется вместе с реализацией и
описывает текущее состояние. Появится первый сторонний клиент — версия
переедет в путь метода.

## Чего в контракте нет

- **Административных операций** — заведение организаций, назначение курсов и
  выдача ролей делаются в браузерном интерфейсе Frappe.
- **Прямого доступа к `LMS Question`** — недоступен ни одной роли ученика ни
  при каких условиях.
